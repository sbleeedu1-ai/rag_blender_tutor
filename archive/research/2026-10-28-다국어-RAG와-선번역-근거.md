# 번역이 필요한지 판단하기 위해, 다국어 검색과 한국어 답변의 연구 근거를 확인한다

조사일: 2026-10-28. 공식 모델 문서, ACL 논문 원문, 저자 공개 코드를 대조했다. 검색 결과 요약문만으로 결론을 내리지 않았다. 블로그·커뮤니티 의견은 근거에서 제외했다.

## 질문과 결론

확인할 주장: 한국어 질문으로 영어 설명서 검색이 가능한 다국어 임베딩을 쓰고, 답변 모델이 영어 근거를 읽어 한국어로 답한다면, 설명서 본문의 한국어 선번역은 필수인가?

**이 구조는 실제 연구와 구현 근거가 있다. 본문 전체를 한국어로 미리 번역해야만 가능한 구조는 아니다. 다만 다국어 모델을 쓴다는 이유만으로 번역의 이득이 없다고 결론 낼 수는 없다. 번역 효과는 모델·자료·질문에 따라 달랐다.**

임베딩은 글의 뜻을 숫자로 바꿔 비슷한 글을 찾는 방법이다. 교차 언어 검색은 질문과 문서의 언어가 다른 검색을 말한다. 검색과 답변 생성은 따로 확인해야 한다.

| 주장 | 확인한 근거의 강도 | 이 프로젝트에서 남은 확인 |
|---|---|---|
| 한국어 질문으로 영어 문서를 찾을 수 있다 | 다국어 검색 연구와 한국어 실험이 있음 | Blender 설명서·초보자 표현에서의 검색 성능 |
| 영어 근거를 읽고 한국어로 답할 수 있다 | 한국어를 포함한 실제 RAG 실험이 있음 | 선택한 답변 모델의 정확도와 화면 용어 준수 |
| 그러므로 한국어 본문 선번역은 필수다 | 이 필수조건은 성립하지 않음 | 선번역 없이 시작한 결과를 기준으로 삼을 수 있음 |
| 그러므로 번역을 넣어도 이득이 없다 | 이를 뒷받침하지 않음. 개선·하락 사례가 모두 있음 | 원문만 / 번역 포함을 같은 질문으로 직접 비교 |

## 1. 공식 모델 문서가 보장하는 범위

OpenAI는 `text-embedding-3-large`를 영어와 비영어 작업용 임베딩 모델로 설명하고, 임베딩 안내에서도 다국어 성능 향상을 명시한다. 이는 다국어 지원의 근거다. 그러나 이 문구만으로 한국어 질문→영어 Blender 설명서의 검색 정확도를 알 수는 없다. [모델 공식 문서](https://developers.openai.com/api/docs/models/text-embedding-3-large), [임베딩 공식 안내](https://developers.openai.com/api/docs/guides/embeddings).

평가 이름에도 주의해야 한다. MIRACL은 여러 언어를 포함하지만 각 평가에서는 질문과 검색 문서가 같은 언어다. MIRACL 평균 점수를 그대로 한국어→영어 검색 점수라고 설명하면 틀린다. [MIRACL 논문](https://aclanthology.org/2023.tacl-1.63/), 초록.

반면 BGE-M3 논문에는 **한국어 질문으로 영어 Wikipedia를 찾는 MKQA 실험**이 있다. 비교 모델 `OpenAI-3`를 `text-embedding-3-large`라고 명시하므로, 이 프로젝트에서 계획한 모델의 직접 근거가 된다. [BGE-M3 원논문](https://arxiv.org/html/2402.03216v3), §4.1-4.2, Table 3·13.

| 한국어→영어 검색 모델 | 상위 20개 안 근거 포함(Recall@20) | 상위 100개 안 근거 포함(Recall@100) |
|---|---:|---:|
| text-embedding-3-large | 53.9 | 63.9 |
| BGE-M3 Dense | 61.9 | 71.6 |

설명서 본문을 한국어로 선번역하지 않아도 검색할 수 있다는 실험 근거다. 다만 Wikipedia의 상위 20·100개 결과에 대한 수치다. Blender에서 상위 6개를 고를 때의 성능, 답변 정확도, 본문 번역의 추가 효과를 나타내지 않는다. BGE 저자의 비교 실험이며 우리 자료에서 재현한 결과는 아니다.

## 2. 한국어 질문과 영어 근거로 한국어 답변을 만든 실험

NAVER Labs Europe의 Chirkova 외(2024)는 한국어를 포함한 13개 언어로 다국어 RAG를 시험했다. BGE-m3 검색기·재순위 모델과 Command-R-35B 답변 모델을 사용하고, 사용자 언어로 답하라는 지시를 주었다. 영어 Wikipedia만 쓰는 조건이 포함되어 있다. [논문 원문](https://aclanthology.org/2024.knowllm-1.15.pdf), Table 1, §3-4.

| 한국어 질문 평가 | 검색 없음 | 영어 Wikipedia만 검색 | 영어+한국어 Wikipedia 검색 |
|---|---:|---:|---:|
| MKQA | 21.5 | 32.2 | 38.4 |
| XOR-TyDi QA | 31.0 | 33.4 | 40.0 |

지표는 **정답과 생성 답변의 문자 세 글자 묶음이 겹치는 정도(character 3-gram recall)**다. 검색 적중률이나 답변 정답률이 아니다. 영어 근거로 한국어 답변을 만드는 구조가 작동했다는 근거로 읽어야 한다.

영어+한국어 조건의 한국어 Wikipedia는 영어 자료를 통째로 번역해 만든 자료가 아니다. 따라서 이 표의 차이를 “선번역의 효과”라고 해석할 수는 없다. 저자도 자료마다 정답 근거가 존재하는 언어의 차이를 설명한다. [같은 논문](https://aclanthology.org/2024.knowllm-1.15.pdf), §5.4.

저자 공개 구현에도 한국어(`ko`) 질문과 영어 자료(`retrieve_en`)를 선택할 수 있게 되어 있다. 다른 모델·자료·재순위 단계가 포함된 실험이므로 이 프로젝트의 속도나 품질을 보장하는 수치는 아니다. [BERGEN 저자 구현 안내](https://github.com/naver/bergen/blob/main/documentation/multilingual.md), Datasets.

## 3. 번역을 붙이면 무조건 좋아지는가: 직접 비교 연구

CLIRudit(Valentini 외, 2025)는 영어 키워드로 프랑스어 학술 자료의 제목·초록을 찾으며, 번역 없음·질문 번역·문서 번역을 직접 비교했다. 다음은 같은 검색 모델에서 GPT-4o-mini로 문서를 영어로 번역했을 때의 결과다. [논문 원문](https://aclanthology.org/2025.mrl-main.16.pdf), Table 1, §4.2·5.

| 검색 모델 | 번역 없음 MAP | 문서 번역 MAP |
|---|---:|---:|
| BGE-m-gemma2 | 0.571 | 0.560 |
| multilingual-e5-large | 0.434 | 0.490 |
| BM25 | 0.181 | 0.549 |

MAP는 정답 문서를 앞쪽에 배치하는 정도를 합쳐 본 검색 지표다. 관측 점수를 보면 어떤 뜻 검색 모델은 개선됐으며 하락한 경우도 있다. 낱말 검색인 BM25에는 문서 번역의 영향이 컸다. 이 결과는 번역이 필수라는 주장과 번역이 무용하다는 주장을 모두 경계하게 한다. 프랑스어 학술 검색 결과이므로 한국어·Blender·OpenAI 모델로 수치를 옮길 수는 없다.

또 이 실험은 **문서를 번역한 뒤 검색하는 방법**이다. 원문과 번역을 한 청크에 이어 붙인 방식이나 두 벡터 방식의 우열을 검증한 표가 아니다.

## 4. 한국어에 맞춘 문서가 더 잘 검색될 가능성은 있는가

Park·Lee(2025)는 한국어를 포함한 언어들에서 같은 내용을 다른 언어로 바꾸고 검색 순위 변화를 조사했다. 부록 G의 한국어 질문 사례에서는 영어 문단을 한국어로 번역한 뒤 순위가 34위에서 2위로 올라갔다. 다만 후보 문서를 다시 순위 매긴 **개별 사례**이므로, 전체 검색 성능이 그만큼 개선된다는 뜻은 아니다. [논문 원문](https://aclanthology.org/2025.findings-acl.295.pdf), §2·4, Appendix G/Table 12.

2026년 후속 연구는 영어가 유리해 보이는 현상에서 자료량·정답 근거 분포의 영향을 분리했다. 그 결과 질문과 문서가 같은 언어일 때 유리한 경향을 보고했다. 따라서 “다국어 임베딩은 언어에 영향을 전혀 받지 않는다”는 설명은 피해야 한다. 이 연구의 방법은 질문을 보강하며 전체 문서를 선번역하는 방식은 아니다. [Park 외, 2026 논문](https://aclanthology.org/2026.findings-acl.1353.pdf), 초록·§3-4.

이 두 결과는 한국어 번역을 검색 보강 가설로 시험할 근거가 된다. 이 프로젝트에서 번역을 채택해야 한다는 확정 근거는 아니다.

한영 검색을 직접 다룬 Jang 외(2025)의 arXiv 연구에서도 BGE-M3 기본 모델이 같은 한국어끼리 찾을 때보다 한국어→영어에서 낮은 점수를 보였다. Belebele의 nDCG@10은 한국어→한국어 93.16, 한국어→영어 88.36이었다. nDCG@10은 상위 10개에 정답 문서를 얼마나 앞쪽에 놓는지 평가하는 지표다. 이는 언어 간 손실이 남을 수 있다는 근거이며, 문서 선번역을 비교한 실험은 아니다. [한영 검색 논문](https://arxiv.org/html/2507.08480v1), §3, Table 1. arXiv 공개본의 실험이며 Blender에 일반화하지 않는다.

## 5. 영어 근거만 주면 답변은 저절로 한국어가 되는가

한국어를 포함한 NAVER 연구는 사용자 언어로 답하라는 명시적 지시가 중요하다고 보고했다. 한국어 질문이라는 사실에만 기대기보다 출력 언어를 지시하고 확인해야 한다. [Chirkova 외(2024)](https://aclanthology.org/2024.knowllm-1.15.pdf), §5.3, Table 5.

가능하지만 출력 언어와 근거 이해를 확인해야 한다. XRAG(Liu 외, 2025)는 영어 문서를 읽고 독일어·스페인어·중국어·아랍어 질문에 답하는 조건 등을 시험했다. 영어 문서만 주는 조건에서는 평가한 모델 모두 사용자 언어를 지키는 데 어려움을 보였다. 다국어 문서를 함께 주는 조건에서는 언어 간 근거를 연결하는 추론도 문제였다. [논문 원문](https://aclanthology.org/2025.findings-emnlp.849.pdf), Figure 1, §5.3-5.4.

이는 주어진 문서로 답을 만드는 평가이며 검색기 성능 자체를 측정하는 실험이 아니다. 한국어는 포함하지 않는다. 이 논문만으로 현재 프로젝트의 답변 모델이 실패한다고 말할 수 없지만, “찾기만 하면 답은 자동으로 정확하다”는 보장도 할 수 없다.

실무상 영어 근거를 읽고 한국어로 답하라는 지시를 한 답변 호출에 넣을 수 있다. 별도의 번역 호출을 반드시 추가할 필요는 없다. 다만 한국어 출력·근거 충실성·실제 화면 용어를 시험해야 한다는 것은 위 연구들로부터의 적용 판단이다.

## 6. 세 가지 번역을 혼동하지 않는다

| 방법 | 번역하는 시점과 대상 | 주로 달라지는 것 |
|---|---|---|
| 본문 선번역 | 자료 준비 때 설명서를 한국어로 번역해 검색에 포함 | 저장·검색 대상, 초기 번역과 검수 작업 |
| 질문 번역 | 질문이 들어올 때 영어 질문을 만들어 검색 | 검색 입력과 질문마다 걸리는 시간 |
| 검색 뒤 번역 | 이미 찾은 영어 근거를 한국어로 바꿔 답변 모델에 전달 | 답변 모델의 근거 이해; 앞선 검색 실패를 되돌리지는 못함 |

영어 근거를 그대로 읽고 한국어 답을 쓰는 방법은 세 번째 번역을 별도 단계로 만들지 않는 설계다. 검색 뒤 번역 연구의 개선 결과를 본문 선번역이 검색을 개선했다는 근거로 쓰면 안 된다.

## 이 프로젝트에 대한 판단

1. **자료 전체를 선번역하지 않고 한국어→영어 검색부터 시험할 근거는 충분하다.**
2. **일부 초보자 범위의 번역을 실험할 근거도 있다.** 다국어 지원과 언어 간 동일 성능은 다른 주장이다.
3. 원문만 검색하는 조건을 기준으로 두고, 같은 개발 질문에서 번역 포함 조건을 비교해야 한다. 한 벡터·두 벡터 비교만 하면 번역 자체가 필요한지는 알 수 없다.
4. 찾은 근거가 맞는지와 한국어 답변이 맞는지는 나눠 확인해야 한다. 특히 Blender 화면 용어 대응은 본문 번역 여부와 별도의 요구다.

앞의 1·2는 외부 자료를 종합한 판단이며, 3·4는 이 프로젝트에 적용할 때의 제안이다. 이번 조사에서 실제 모델 호출이나 Blender 검색 실험을 하지는 않았다. 명세·티켓의 요구사항을 바꾼 결정도 아니다.

## 확인하지 못한 것

- 한국어 초보자 질문으로 Blender 5.2 공식 설명서를 찾는 공개 비교 실험.
- 현재 프로젝트의 번역 포함·미포함 검색 성능 차이.
- `text-embedding-3-large`에서 원문+번역을 한 벡터로 합치는 것과 별도 두 벡터로 만드는 것의 이 프로젝트 내 우열.
- 논문의 Wikipedia·학술 검색 수치를 그대로 사용할 수 있는 Blender 성능 보장.
