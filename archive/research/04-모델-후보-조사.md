# 조사: 답변·임베딩 모델 후보 (티켓 04)

조사일 2026-10-19 · Claude · 유료 API 호출 없음(공식 문서·이전 프로젝트 기록만 읽음)

## 요약

1. **gpt-6-luna**는 입력 $0.10 / 출력 $0.50(100만 토큰당)이고, 기본 생각 수준은 medium이다. OpenAI는 low와 medium 사이 **속도 차이를 숫자로 공개하지 않는다**. "낮을수록 빠르고 토큰을 덜 쓴다"는 방향만 말한다.
2. 이전 프로젝트에서 직접 잰 값으로는 답변 호출(medium) 하나가 **2.6-2.8초**이고, 질문 하나 전체는 18-20초였다. 시간을 가장 많이 잡아먹은 건 답변이 아니라 **리랭커(low 6-13.5초)와 근거 대조(8-9초)** 같은 추가 호출이었다.
3. 임베딩은 지금도 OpenAI 최신이 **text-embedding-3-large($0.13) / -small($0.02)**이다(새 모델 없음). 한국어 질문으로 영어 문서를 찾는 시험에서는 오픈 모델 **bge-m3**가 3-large보다 높다고 bge-m3 저자 논문이 보고한다(한국어 Recall@100 71.6 대 63.9).
4. 설명서 전체를 3-large로 임베딩하는 비용은 **약 $0.2-0.7**(한국어 번역분 포함)로 추정한다. 비용보다는 DB를 다시 만들 때마다 드는 시간과 횟수가 더 신경 쓸 부분이다.
5. ChatGPT 웹 채팅은 2026-10-07부터 **유료 = GPT-6 Sol, 무료·Go = GPT-6 Luna**로 바뀌는 중이다(출시 공지 기준). 다만 도움말 문서 하나에는 무료가 아직 GPT-5.6 Luna로 적혀 있어 서로 어긋난다. 비교할 때는 화면에 보이는 모델 이름과 생각 수준을 매번 기록해야 한다.

용어 풀이(처음 한 번만):
- **토큰**: 모델이 글을 세는 단위. 영어는 약 4글자가 1토큰이다.
- **생각 수준(reasoning effort)**: 모델이 답하기 전에 속으로 얼마나 오래 따져 볼지 정하는 설정. 생각에 쓴 토큰도 출력 요금으로 낸다.
- **임베딩**: 글을 숫자 묶음(벡터)으로 바꿔, 뜻이 비슷한 글을 찾을 수 있게 하는 것.
- **리랭커**: 검색으로 모은 후보 중에서 쓸 자료를 다시 골라 주는 단계(이전 프로젝트는 LLM이 이 일을 함).

## 1. 답변 모델 비교표

가격은 모두 100만 토큰당 미국 달러, 입력 272K 토큰 이하 기준(출처: [가격표](https://developers.openai.com/api/docs/pricing)).

| 모델 | 입력 / 캐시 입력 / 출력 | 공식 설명 | 생각 수준 | 비고 |
|---|---|---|---|---|
| **gpt-6-luna** (이전 프로젝트 사용) | $0.10 / $0.01 / $0.50 | "Our most efficient model for focused, high-volume tasks." | none, low, **medium(기본)**, high, xhigh, max | 문맥 1,050,000토큰, 최대 출력 128,000토큰, 지식 기준일 2026-05-18 ([모델 페이지](https://developers.openai.com/api/docs/models/gpt-6-luna)) |
| gpt-6-luna Fast 모드 | $0.20 / $0.02 / $1.00 | 같은 모델을 우선 처리 | 같음 | 가격표에 Luna Fast 가격이 있다. Fast 모드 문서는 "up to 2.5× faster speeds and more consistent latency"라고 쓴다. 다만 이 숫자를 Luna에서 쟀다는 말은 없다 ([Fast 모드](https://developers.openai.com/api/docs/guides/fast-mode)) |
| 대안 1: **gpt-6.1-sol** | $2.00 / $0.10 / $10.00 | "Near-Astra performance for complex work at a lower cost." | low, medium(기본), high, xhigh, max (none 없음) | Luna보다 입력 20배, 출력 20배 비싸다 ([모델 목록](https://developers.openai.com/api/docs/models), [GPT-6 사용 안내](https://developers.openai.com/api/docs/guides/latest-model)) |
| 대안 2: **gpt-6-luna 생각 none** | Luna와 같음 | — | none | 공식 안내: none은 "Latency-critical tasks that do not benefit from any reasoning" 용도 ([추론 안내](https://developers.openai.com/api/docs/guides/reasoning)) |

참고로만(같은 [가격표](https://developers.openai.com/api/docs/pricing)):
- gpt-6-sol $2.00/$10.00: 6.1-sol이 나와서 굳이 고를 이유가 없다.
- gpt-6-astra $10.00/$50.00: 가장 강한 모델이지만 none 생각 수준이 없고 비싸다.
- gpt-5.6-luna $0.20/$1.20: 옛 Luna인데 gpt-6-luna보다 2배 이상 비싸다.
- gpt-5.4-nano $0.20/$1.25, gpt-5-nano $0.05/$0.40: 작은 모델.

gpt-6 mini·nano는 가격표에 없다.

**low와 medium에 대한 공식 안내** ([추론 안내](https://developers.openai.com/api/docs/guides/reasoning)):
- "Lower effort favors speed and lower token usage." 높이면 더 충분히 생각해 품질이 올라간다.
- medium은 "a well-balanced point on the pareto curve of latency, performance and cost"(속도·성능·비용의 균형점).
- 모델이 쉬운 문제에는 알아서 토큰을 덜 쓴다("reason adaptively").
- 생각 토큰은 출력 토큰으로 요금을 낸다.
- **low와 medium의 속도·비용 차이를 숫자로 적은 공식 문서는 없다.** 처리 속도(초당 토큰)도 Luna 모델 페이지에 없다.
- 첫 글자를 빨리 보여 주려면 "짧은 머리말을 먼저 쓰게 하라"는 팁이 있다(스트리밍으로 답이 나오는 동안 보여 줄 때 쓸 수 있다).

**질문 하나당 비용(추정)**: 입력 6,000토큰(영어 청크 6개 + 지시문), 출력 600토큰(생각 포함)이라고 가정했다.
- gpt-6-luna: 약 $0.0009
- gpt-6.1-sol: 약 $0.018

어느 쪽이든 한 번 묻는 비용은 작다. 그래서 모델은 **속도와 정확도**로 고르면 된다.

## 2. 임베딩 후보와 전체 임베딩 비용 추정

| 후보 | 가격(100만 토큰) | 공식 근거 | 한국어 질문 → 영어 문서 |
|---|---|---|---|
| **text-embedding-3-large** (이전 프로젝트 사용) | $0.13 | "most capable embedding model for both english and non-english tasks", 기본 3072차원, 입력 최대 8192토큰, `dimensions`로 줄일 수 있음 ([모델 페이지](https://developers.openai.com/api/docs/models/text-embedding-3-large), [임베딩 안내](https://developers.openai.com/api/docs/guides/embeddings)) | OpenAI 발표 기준 MIRACL(다국어 검색 시험) 평균 54.9%(ada-002 31.4%) ([발표 글](https://openai.com/index/new-embedding-models-and-api-updates/), 검색 결과 요약으로 확인했고 본문은 접속이 막힘) |
| text-embedding-3-small | $0.02 | 기본 1536차원, MTEB 62.3%(large 64.6%) ([임베딩 안내](https://developers.openai.com/api/docs/guides/embeddings)) | small의 MIRACL 점수는 원문을 열지 못해 확인 못 함. 이전 프로젝트(한국어 → 한국어)에서 small → large로 바꾸자 검색 적중이 30 → 42/56으로 올랐다 |
| 더 새 OpenAI 임베딩 | — | 임베딩 안내와 가격표에 3-large/3-small/ada-002 말고는 없다 ([가격표](https://developers.openai.com/api/docs/pricing)) | 없음 |
| **bge-m3** (오픈 모델, 내 PC에서 실행) | API 요금 없음(내 PC 자원 사용) | 100개 넘는 언어, 입력 최대 8192토큰, 1024차원, 한 모델로 dense(뜻)·sparse(낱말)·multi-vector 검색, MIT 라이선스 ([모델 카드](https://huggingface.co/BAAI/bge-m3)) | 저자 논문의 MKQA(25개 언어 질문 → 영어 위키 문서 찾기) 결과: Recall@100 한국어 **71.6**(3-large 63.9), 평균 75.1(3-large 69.5). Recall@20 한국어 61.9(3-large 53.9) ([논문](https://arxiv.org/html/2402.03216v3)). 우리 상황과 가장 비슷한 시험이다. 다만 **만든 쪽이 직접 잰 숫자**다 |
| multilingual-e5-large (오픈) | API 요금 없음 | 입력 최대 **512토큰**(넘으면 잘림), 1024차원, 질문 앞에 "query: ", 문서 앞에 "passage: "를 붙여야 함, MIT ([모델 카드](https://huggingface.co/intfloat/multilingual-e5-large)) | 모델 카드에는 한국어 → 한국어(Mr.TyDi ko MRR@10 61.6) 결과만 있고, 한국어 → 영어 결과는 없다 |

(Recall@100: 정답 문서가 상위 100개 안에 들어온 비율. 실제로는 상위 20 정도만 쓰니 Recall@20 쪽이 더 가깝다.)

**설명서 전체 임베딩 비용 추정**

근거로 쓴 숫자:
- 4.5 설명서는 2,072쪽, 목차만 있는 쪽을 빼면 1,734쪽이었다(티켓 02 메모).
- 4.5 초보자 범위 100문서는 약 490,000글자로, 문서 하나에 평균 약 4,900글자다(지시받은 값).
- 영어는 1토큰이 약 4글자다([OpenAI 도움말](https://help.openai.com/en/articles/4936856-what-are-tokens-and-how-to-count-them), 검색 결과로 확인). 설명서에는 메뉴 경로·단축키·표가 많아 3.5-4.5글자로 넓게 잡았다.
- 청크 겹침과 머리말(제목·경로)로 토큰이 20% 늘어난다고 가정했다.
- 한국어는 이전 프로젝트에서 잰 값을 썼다. 질문 98개, UTF-8 8,354바이트가 3,796토큰이었다(작업기록 [151]). 한 글자가 3바이트라 치면 **1토큰이 약 0.75-1.2글자**다.

| 경우 | 문서 수 × 글자 | 글자/토큰 | 영어 토큰(×1.2) | 3-large 비용 | 3-small 비용 |
|---|---|---|---|---|---|
| 적게 | 1,700 × 3,000 | 4.5 | 약 136만 | 약 $0.18 | 약 $0.03 |
| 중간 | 2,000 × 4,900 | 4.0 | 약 294만 | 약 $0.38 | 약 $0.06 |
| 많게 | 2,200 × 6,000 | 3.5 | 약 453만 | 약 $0.59 | 약 $0.09 |
| + 한국어 번역(초보자 범위 약 49만 글자) | — | 0.75-1.2 | 약 41-65만 | +$0.05-0.09 | +$0.01 |

→ **3-large로 전체를 한 번 임베딩하면 약 $0.2-0.7, small이면 약 $0.03-0.1.**
- 질문 하나를 임베딩하는 비용은 0에 가깝다.
- 시간은 요청 한도에 달려 있다. Build 등급은 분당 100만 토큰이라 몇 분이면 끝난다. Free 등급은 분당 4만 토큰이라 1-2시간쯤 걸린다([3-large 모델 페이지](https://developers.openai.com/api/docs/models/text-embedding-3-large)).
- 이전 프로젝트에서는 청킹을 바꿀 때마다 DB를 다시 만들었다. 그러니 "몇 번 다시 만들지"까지 곱해서 봐야 한다.

## 3. 비교 대상 GPT(ChatGPT 웹 채팅)

- 공식 안전 문서(2026-10-07 게시): "We're launching GPT-6 to everyone in ChatGPT, across free and paid plans globally." 그리고 "These models will replace GPT-5.6 Sol and GPT-5.6 Luna in ChatGPT."([Deployment Safety Hub](https://deploymentsafety.openai.com/gpt-6-october))
  - 이때 ChatGPT에 들어간 것은 **10월판** 모델이다. Codex와 ChatGPT Work는 아직 9월판을 쓴다고 같은 문서에 적혀 있다.
- ChatGPT 출시 노트: 10-07부터 Plus·Pro·Business·Enterprise는 **GPT-6 Sol**, 10-08부터 Free·Go는 **GPT-6 Luna**. 생각 수준은 Instant부터 Extra High까지 고를 수 있다([출시 노트](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)). 이 페이지는 접속이 막혀 검색 결과 요약으로만 확인했다.
- **어긋나는 문서**: 도움말 [GPT-6 and other models in ChatGPT](https://help.openai.com/en/articles/20001354-gpt-6-and-other-models-in-chatgpt)는 검색 결과 요약상 "무료·Go 기본 = GPT-5.6 Luna, 유료 = GPT-6 Sol"로 적혀 있다(접속 막힘).
  - 이전 프로젝트도 10-08에 무료 화면에서 GPT-5.6 Luna를 보았다(작업기록 [337], 화면 캡처). 무료 배포가 계정마다 순서대로 퍼지는 중이었을 수 있다.
- 결론: **유료 = GPT-6 Sol은 확실하다. 무료 기본이 지금 GPT-6 Luna인지는 공식 문서끼리 어긋나 확정하지 못했다.**
  - 비교할 때는 화면의 모델 이름과 생각 수준(Instant/Think/High 등)을 질문마다 기록한다.
  - 이전 프로젝트처럼 결과를 보기 전에 조건을 정해 둔다(그때는 유료 Sol High, 무료 Luna Think).
  - ChatGPT의 GPT-6 Luna가 API의 `gpt-6-luna`와 같은 판인지는 문서에 나오지 않는다.

## 5. 확인 못 한 것

- gpt-6-luna의 low와 medium 응답 시간·초당 토큰: 공식 숫자가 없다. 직접 재야 한다(유료, 몇 센트).
- Fast 모드의 "최대 2.5배"가 Luna에도 해당하는지: 문서 본문에 Luna 지원이 분명히 적혀 있지 않다. 가격표와 EU 데이터 FAQ에만 나온다. 속도 보장(SLA)이 있는지도 확인 못 했다.
- text-embedding-3-small의 MIRACL 점수, 3-large의 MIRACL 한국어 점수: OpenAI 발표 글이 접속 거부(403)였다.
- ChatGPT 무료 기본 모델(GPT-6 Luna인지 GPT-5.6 Luna인지): 공식 문서끼리 어긋난다. help.openai.com 페이지는 403이라 검색 결과 요약으로만 봤다.
- bge-m3를 이 PC에서 돌렸을 때 질문 하나 임베딩 속도와 필요한 메모리·GPU: 모델 카드에 크기가 적혀 있지 않다. 직접 재 봐야 한다.
- bge-m3와 3-large 비교는 bge-m3 저자 논문 숫자뿐이다. Blender 설명서처럼 메뉴·단축키 용어가 많은 문서에서도 그런지는 모른다.
- Blender 5.2 설명서의 실제 문서 수·글자 수: 티켓 02 결과를 기다린다. 위 비용 추정은 4.5 값으로 했다.

## 6. 다음 결정에 주는 시사점

**청크·검색 방식(티켓 06)**
- 임베딩 비용은 전체 설명서를 넣어도 1달러가 안 된다. 그러니 **비용 때문에 범위를 줄일 이유는 없다.**
- 언어가 다른 검색(한국어 질문 → 영어 문서)이 핵심 위험이다. 고를 수 있는 길:
  - ① 3-large만 쓴다.
  - ② bge-m3(로컬)와 견준다.
  - ③ 질문을 영어로 바꾼 뒤 검색한다(LLM 호출이 하나 늘어 시간이 든다).
  - ④ 초보자 범위는 한국어 번역 청크로도 찾게 한다.
  - 이 넷 가운데서 고르게 된다. 무엇이 나은지는 작은 개발용 질문 세트로 검색 적중을 재서 정하는 것을 권한다.
- 이전 프로젝트의 BM25(낱말 일치 검색)는 한국어 질문과 영어 문서 사이에서는 낱말이 거의 안 겹친다. 그래서 그대로 가져오면 효과가 작을 수 있다. 대신 영어 메뉴 이름·단축키가 질문에 그대로 들어오면 쓸모가 있다.
- 리랭커를 LLM으로 두면 low에서 6-13초가 든다. 속도가 핵심이면 none으로 하거나, 리랭커를 빼고 상위 몇 개만 바로 쓰는 쪽을 먼저 견줘 볼 만하다.

**속도 목표(티켓 11)**
- 이전 프로젝트 구성을 그대로 쓰면 질문 하나에 18-20초가 걸린다. 답변 한 번만 놓고 보면 3초 안팎이다.
- 그러니 "임베딩(0.5초) + 검색 + 답변 한 번(약 3초) + 애드온 왕복" 구성이면 **약 5초 안쪽**을 노릴 수 있다고 본다(추정, 직접 재야 함).
- 리랭커·근거 대조를 넣을 때마다 몇 초씩 늘어난다.
- 스트리밍(답을 나오는 대로 보여 주기)을 쓰면 "첫 글자까지 시간"이 더 짧아진다. 그래서 목표를 "첫 글자"와 "답 끝"으로 나눠 정할지도 함께 정해야 한다. 지도의 시간 재기 규칙은 "답이 다 나온 순간"이다.
- gpt-6-luna low와 medium의 실제 시간 차이는 문서로 알 수 없다. **같은 질문 10개 정도로 low/medium/none을 재는 작은 유료 실험**(예상 몇 센트)을 승인받아 하는 것을 권한다.
