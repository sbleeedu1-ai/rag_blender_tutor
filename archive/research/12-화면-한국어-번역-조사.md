# 조사: Blender 5.2 화면 한국어 번역 범위와 메뉴 이름 대응 방법

티켓: `.scratch/mvp-roundtrip/issues/12-화면-한국어-번역-조사.md` · 조사일 2026-10-19 · 조사자 Claude

## 요약

1. 화면 번역 사전은 설치본의 `5.2/datafiles/locale/ko/LC_MESSAGES/blender.mo` 파일 하나이고, 원본은 Blender 공개 저장소 `blender-v5.2-release` 브랜치의 `locale/po/ko.po`다.
2. 한국어 화면 번역률은 **약 93%**다(공식 표시 93%, 직접 세어 보니 39,341개 중 36,776개 = 93.5%). 설명서 번역(1.1%)과는 완전히 별개다.
3. 검·방패 연습 과정에 나오는 메뉴는 거의 다 번역돼 있다. 다만 **병합(Merge) 메뉴의 "At Center"는 한국어 화면에서도 영어로 나온다**(같은 영어 문구가 문맥(msgctxt)마다 따로 번역되는데, 이 메뉴가 쓰는 "Mesh" 문맥에는 번역이 없다). 로컬 Blender 5.2.2에서 실행해 확인했다.
4. 애드온은 `bpy.context.preferences.view.language`로 화면 언어를 읽을 수 있고, `bpy.app.translations.pgettext_iface(영어, 문맥)`으로 영어 이름을 지금 화면 언어로 바꿀 수 있다. 단 **문맥을 맞게 넘겨야** 화면과 같은 글자가 나온다.
5. "메뉴는 한국어, 도움말(툴팁)은 영어" 같은 부분 번역 설정이 있다(환경 설정 > 인터페이스 > 언어 > 번역의 체크 4개). 첫 실행 빠른 설정 창에는 언어 고르기만 있고 이 체크들은 없다.

## 질문별 답

### 1. 번역 사전은 어디 있고, 한국어는 얼마나 번역됐나

용어 하나: **po/mo 파일**은 "영어 문구 → 번역 문구" 짝을 모은 사전 파일이다. `.po`는 사람이 읽는 글자 파일, `.mo`는 Blender가 빨리 읽도록 바꾼 파일이다. **msgid**는 사전의 영어 원문, **msgctxt**(문맥)는 같은 영어를 뜻에 따라 나누는 꼬리표다.

- **설치본 안**: `<설치 폴더>/5.2/datafiles/locale/ko/LC_MESSAGES/blender.mo`. 이 PC의 `C:\Program Files\Blender Foundation\Blender 5.2\5.2\datafiles\locale\ko\LC_MESSAGES\blender.mo`(3,309,277바이트, Blender 5.2.2)에서 직접 확인했다. 빌드 규칙도 `locale/po/*.po`를 `.mo`로 바꿔 `datafiles/locale/<언어>/LC_MESSAGES/blender.mo`로 설치한다고 적혀 있다.
  - 출처: https://projects.blender.org/blender/blender/src/branch/blender-v5.2-release/source/creator/CMakeLists.txt (localization 부분)
- **공개 저장소**: 5.2용 원본은 Blender 본 저장소의 `locale/po/ko.po`다(별도 blender-translations 저장소가 아니다). 언어 목록과 번역률은 같은 폴더의 `locale/languages` 파일에 있다.
  - https://projects.blender.org/blender/blender/src/branch/blender-v5.2-release/locale/po/ko.po
  - https://projects.blender.org/blender/blender/src/branch/blender-v5.2-release/locale/languages
  - ko.po 머리말: `Project-Id-Version: Blender 5.2.0 LTS Release Candidate`, `Language-Team: Korean <https://translate.blender.org/projects/blender-ui/ui/ko/>`. 즉 번역 작업 자체는 Blender 번역 사이트(Weblate, 여럿이 웹에서 번역하는 도구)에서 하고, 결과가 저장소로 들어온다.
- **번역률**
  - 공식 표시: `locale/languages`에 `24:Korean - 한국어:ko_KR:93%`. 5.2 Python API 문서의 언어 목록에도 "Korean - 한국어 – Locale code: ko_KR. Translation progress: 93%" (https://docs.blender.org/api/5.2/bpy.types.PreferencesView.html#bpy.types.PreferencesView.language).
  - 직접 센 값: 저장소의 `.po`는 **번역된 문구만** 담고 번역 안 된 문구는 아예 빠져 있다(ko.po를 세면 번역 안 된 항목이 0개로 나온다). 그래서 전체 개수는 100% 언어로 표시된 프랑스어·스페인어·러시아어 `.po`를 셌다(셋 다 39,341개). 한국어는 36,776개 → **93.5%**. 설치된 5.2.2의 `.mo`도 같은 개수였다(ko 36,777, fr 39,342, 각각 머리말 1개 포함).
  - 비교로 일본어 100%, 중국어(간체) 100%, 독일어 35% (`locale/languages`).
- **설명서 번역과 구분**: 위 숫자는 Blender 프로그램 화면(메뉴·버튼·툴팁)의 번역이다. 설명서(docs.blender.org/manual) 한국어 번역(1.1%)과는 사전도 작업 사이트도 다르다.

### 2. 연습 과정에 나오는 메뉴·기능 이름의 한국어

확인 방법: 5.2 브랜치 `ko.po`에서 영어 원문을 찾고, 실제 메뉴 코드(`scripts/startup/bl_ui/*.py`, C 소스)에서 그 메뉴가 어느 문맥을 쓰는지 본 뒤, **이 PC의 Blender 5.2.2를 화면 없이 실행해** `pgettext_iface`로 한국어 화면에서 나올 글자를 뽑았다(시험 스크립트는 저장소 밖 임시 폴더에 두었다).

### 3. 애드온이 화면 언어를 읽고, 영어 이름을 지금 언어로 바꿀 수 있나

**읽기** (출처: https://docs.blender.org/api/5.2/bpy.types.PreferencesView.html)
- `bpy.context.preferences.view.language`: 고른 언어. 기본값 `'DEFAULT'`("Automatic", 운영체제 언어를 따르고 없으면 영어). 그래서 **'DEFAULT'일 때 실제 언어는 따로 봐야 한다** → `bpy.app.translations.locale`이 지금 실제로 쓰는 언어 코드를 돌려준다(https://docs.blender.org/api/5.2/bpy.app.translations.html#bpy.app.translations.locale). 실행 확인: 언어를 바꾸면 둘 다 `ko_KR`.
- `use_translate_interface`(메뉴·버튼·패널 글자 번역), `use_translate_tooltips`(툴팁), `use_translate_reports`(오류 등 알림), `use_translate_new_dataname`(새로 만든 물체·재질 이름). 문서상 넷 다 기본값 True. 실행 확인(공장 초기 설정): 넷 다 True.

**바꾸기** (출처: https://docs.blender.org/api/5.2/bpy.app.translations.html)
- `pgettext_iface(msgid, msgctxt=None)`: "화면 글자 번역이 켜져 있으면" 번역해서 돌려주고, 사전에 없으면 영어를 그대로 돌려준다. 문맥을 안 주면 기본 문맥.
- `pgettext_tip`(툴팁 설정 따름), `pgettext_rpt`(알림), `pgettext_data`(새 이름), `pgettext`(설정 무시하고 항상 번역).
- 문맥 이름 목록은 `bpy.app.translations.contexts`(예: `operator_default='Operator'`, `id_mesh='Mesh'`, `id_windowmanager='WindowManager'`, `editor_preferences='Preferences'`, 기본 `'*'`).
- 실행 확인: 화면 번역을 끄면 `pgettext_iface("Add","Operator")`는 "Add", `pgettext`는 여전히 "추가". 툴팁 번역만 끄면 `pgettext_iface`는 "추가", `pgettext_tip`은 "Add". 즉 `pgettext_iface`를 쓰면 **사용자의 "인터페이스 번역" 체크까지 자동으로 따라간다**.

**함정**
- **문맥을 틀리면 다른 글자가 나온다.** 예: `pgettext_iface("At Center")`(기본 문맥)와 `("At Center","Mesh")`는 둘 다 영어, `("At Center","Operator")`는 "센터에서". 화면은 Mesh 문맥이라 영어가 맞다. 문맥이 없으면 다른 문맥으로 대신 찾아 주지 않는다(실행 확인).
- **어떤 문맥인지는 메뉴 코드마다 다르다.** 메뉴 제목은 `bl_translation_context`, 버튼은 `text_ctxt`, 목록 항목은 그 속성의 `translation_context`, 연산자(operator, 버튼 뒤에서 실제로 일을 하는 명령) 이름은 보통 Operator 문맥. 실행 중에는 RNA(Blender 내부 구조를 Python으로 보는 창구)로 읽을 수 있다: `bpy.types.VIEW3D_MT_add.bl_translation_context` → "Operator", `bpy.ops.mesh.merge.get_rna_type().properties["type"].translation_context` → "Mesh", 모디파이어 종류 → "*".
- **연산자 이름 ≠ 메뉴 글자.** 예: Add > Mesh > Cube 버튼의 글자는 메뉴 코드의 `text="Cube"`인데 연산자 자체 이름은 "Add Cube". 검색(F3)에는 연산자 이름이 나온다. 그러니 "메뉴 경로"는 연산자 이름이 아니라 메뉴 코드의 글자로 만들어야 한다.
- **새 데이터 이름도 번역된다.** `use_translate_new_dataname`이 기본 True라서 한국어 화면에서 새로 추가한 물체 이름이 한국어가 될 수 있다. 작업 상태의 "선택 물체" 이름이 한국어로 올 수 있다는 뜻이다(실제 이름 글자는 화면에서 확인 못 함).
- 사전 문구에는 어색한 번역도 있다(예: "Count Method" → "카운트 방법함", "Curve Object" → "곡선 객체를 선택함"). 화면과 같게 보여 주는 것이 목적이면 그대로 써야 하지만, 설명 문장에 섞으면 이상하게 읽힌다.

### 4. 부분 번역 설정, 빠른 설정 창

- **있다.** 환경 설정 > 인터페이스 > 언어(Language) 패널에 "번역(Translate)" 아래 체크 4개: 도움말(Tooltips), 인터페이스(Interface), 보고서(Reports), 새로운 데이터(New Data). 인터페이스만 켜고 도움말을 끄면 "메뉴는 한국어, 툴팁은 영어"가 된다. 체크는 언어가 영어(US)가 아닐 때만 활성.
  - 코드: https://projects.blender.org/blender/blender/src/branch/blender-v5.2-release/scripts/startup/bl_ui/space_userpref.py (`USERPREF_PT_interface_translation`)
  - 설명서: https://docs.blender.org/manual/en/5.2/editors/preferences/interface.html#language (설명서에는 Tooltips·Interface·New Data 3개만 적혀 있고 Reports는 빠져 있다. 코드와 API 문서에는 4개)
  - API 문서의 `use_translate_interface` 설명에도 "튜토리얼이나 설명서를 따라가기 어려워질 수 있다"는 경고가 붙어 있다.
- **첫 실행 빠른 설정(Quick Setup)**: 언어(Language) 고르기 하나, 테마, 키맵, 마우스 선택 버튼, 스페이스바 동작, 그리고 계속(Continue) 버튼. **번역 체크 4개는 없다** → 빠른 설정에서 한국어를 고르면 넷 다 기본값(켜짐)으로 시작한다. 이전 버전 설정이 있으면 "가져오기" 버튼도 나온다.
  - 코드: https://projects.blender.org/blender/blender/src/branch/blender-v5.2-release/scripts/startup/bl_operators/wm.py (`WM_MT_splash_quick_setup`)

### 5. 사전을 어디서 쓸까: (a) 서버가 변환 vs (b) 애드온이 변환

결정은 뒤의 질문 라운드 티켓 몫이다. 장단점만 적는다.

**(a) 서버가 ko.po를 갖고 있다가 "영어 이름 → 한국어(영어)"로 바꿔 보낸다**
- 장점: 애드온이 단순해진다. 서버 시험을 Blender 없이 돌릴 수 있다(테스트는 API 키·Blender 없이 돌아야 한다는 규칙에 맞음). 검색할 때도 한국어 메뉴 이름으로 찾는 등 서버 안에서 다른 용도로 쓸 수 있다.
- 단점: 사전을 서버가 따로 들고 있어야 하고 Blender 버전(5.2.x)마다 맞춰야 한다. 무엇보다 **문맥을 서버가 알아야 한다** — 서버는 메뉴 코드를 모르므로 "At Center"가 Mesh 문맥인지 알려면 메뉴 경로별 문맥 표를 따로 만들어야 한다. 사용자가 "인터페이스 번역"을 끈 경우 등은 애드온이 보내 준 설정을 보고 서버가 따라 해야 한다.

**(b) 서버는 영어 메뉴 이름(과 문맥)을 표시해 보내고, 애드온이 `bpy.app.translations.pgettext_iface`로 바꾼다**
- 장점: 사용자 PC에 깔린 바로 그 사전을 쓰므로 화면 글자와 정확히 같다(버전 차이 없음). 사용자의 번역 체크 설정도 자동으로 따른다. 문맥을 실행 중에 RNA에서 읽을 수도 있다. 서버에 사전을 둘 필요가 없다.
- 단점: 서버 답 안에서 "여기가 메뉴 이름"이라는 표시(형식)를 정해야 하고, 문맥도 함께 실어 보내야 정확하다(문맥 없이 보내면 At Center·Edit Mode 같은 곳이 틀릴 수 있다). 변환 결과는 Blender 안에서만 확인되므로 서버 쪽 시험만으로는 검증이 안 된다. 서버가 쓴 한국어 문장 속 다른 낱말과 메뉴 이름 표기(예: "에디트 모드" vs 설명 문장의 "편집 모드")가 엇갈릴 수 있다.

참고: 두 방식 모두 "번역 없음이면 영어 그대로"는 저절로 된다(`pgettext_iface`도 사전에 없으면 영어를 돌려준다).

## 확인 못 한 것

- **화면 눈 확인 없음.** 모든 한국어는 사전과 `pgettext_iface` 실행 결과로 얻은 값이다. 실제 한국어 화면을 켜서 본 것은 아니다. 특히 다음은 화면에서 봐야 한다.
  - 병합(M) 메뉴의 "At Center"가 정말 영어로 보이는지(코드·실행 결과로는 영어가 맞다).
  - 새 Array 모디파이어 패널에서 입력 이름(Shape·Count 등)과 선택지(Circle 등)가 번역되어 보이는지. 사전에는 있지만 노드 그룹 에셋 입력 이름이 패널에서 번역되는지는 공식 문서에서 찾지 못했다.
  - Operator 문맥 "편집 모드"가 어느 화면에 쓰이는지, Mesh 문맥 "Bevel"이 어디에 쓰이는지.
  - 한국어 화면에서 새로 추가한 물체 이름이 정확히 무엇이 되는지(새 데이터 이름 번역).
- **번역 사이트(translate.blender.org)의 공식 통계 페이지**는 자동 접속 차단(Cloudflare)으로 읽지 못했다. 대신 저장소 `locale/languages`(93%)와 직접 센 값(93.5%)을 썼다.
- 저장소 `.po`가 "번역된 것만 담는다"는 점은 파일을 세어서 알아낸 사실이고, 이를 설명한 공식 문서는 찾지 못했다.
- 5.2 브랜치 ko.po 머리말은 "5.2.0 Release Candidate"로 남아 있다. 이 PC의 5.2.2 설치본 `.mo`와 개수(36,776)가 같아서 같은 내용으로 봤지만, 낱말 하나하나까지 비교하지는 않았다.
- 시점(Viewport) 조작 관련 메뉴 이름(View > Frame Selected "선택한 프레임" 등)은 사전 값만 보고, 연습 과정 1단계에서 실제로 어느 메뉴를 쓸지 정해지지 않아 표에 넣지 않았다.

## 다음 결정에 주는 시사점

**애드온 ↔ 서버 주고받는 형식**
- 작업 상태에 언어를 보낼 때 `preferences.view.language`만으로는 부족하다('DEFAULT'일 수 있음). 실제 언어 `bpy.app.translations.locale`과 `use_translate_interface`(필요하면 `use_translate_tooltips`)를 함께 보내야 "한국어 화면인지"를 바르게 판단할 수 있다.
- 한국어 화면이어도 사용자가 인터페이스 번역을 꺼 두면 메뉴는 영어다. "언어 = ko"만 보고 한국어 메뉴 이름을 쓰면 틀린다.
- (b)를 고르면 서버 답 안의 메뉴 이름에 **영어 원문 + 문맥** 표시가 필요하다(예: 메뉴 경로를 글자로 섞지 말고 따로 된 목록으로). (a)를 고르면 서버에 "메뉴 경로 → 문맥" 표가 필요하다. 어느 쪽이든 문맥 정보를 누군가는 들고 있어야 한다는 점이 이 조사의 핵심 발견이다.
- 선택 물체 이름이 한국어로 올 수 있으니 서버는 물체 이름을 영어라고 가정하지 않는다.

**청크·검색 방식**
- 근거(설명서)는 영어이고 메뉴 이름도 영어로 적혀 있다. 그러니 검색은 영어 메뉴 이름 기준으로 하고, 한국어 표기는 답을 만든 뒤 붙이는 편이 자연스럽다.
- 다만 한국어 화면 사용자는 질문에 "에디트 모드", "솔리디파이", "센터에서"처럼 **화면에 보이는 한국어**를 쓸 가능성이 크다. 사용자의 한국어 메뉴 이름을 영어로 거꾸로 바꿔 검색하려면 ko.po를 서버도 가져야 한다(역방향 찾기). 이 점은 (a) 쪽에 무게를 싣는 근거가 될 수 있다.
- 사전의 같은 한국어가 여러 영어에 대응하기도 한다(예: "옮기기" ← Translate·Translation, "노멀" ← Normal·Normals). 역방향 찾기는 하나로 정해지지 않을 수 있다.
- 설명서 5.0 이후 새 Array는 "Array", 예전 것은 "Array (Legacy)"인데 한국어로는 "배열"·"배열 (레거시)"로 갈린다. 평가 질문에 한국어 화면용 문항(예: "배열 모디파이어로 원형 배치")을 넣을 만하다.
