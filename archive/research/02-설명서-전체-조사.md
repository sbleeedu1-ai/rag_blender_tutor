# 조사 결과: Blender 5.2 설명서 전체의 언어·구조·수집 방법

티켓: `.scratch/mvp-roundtrip/issues/02-설명서-전체-조사.md` · 조사일 2026-10-19 · 1차 출처(blender.org, docs.blender.org, projects.blender.org)만 사용

## 요약

1. 5.2 설명서는 **2,358쪽**(소스 파일 2,358개 = HTML 쪽 2,358개)이고, 그중 **목차만 있는 쪽은 297개**(아래 기준), 나머지 **본문 쪽은 2,061개**다. 4.5는 2,072쪽이었다.
2. **공식 한국어판은 주소만 있고 내용은 거의 영어다.** 번역 파일 기준으로 제대로 번역된 문장은 **1.1%**, 한국어 사이트 본문 단락 중 한글이 있는 것은 6.6%(대부분 "참고", "팁" 같은 꼬리표)다. 번역에 기댈 수 없고 직접 번역해야 한다.
3. 내려받기는 **공식 HTML 묶음(zip, 약 360MB)**이 가장 쉽다. 쪽마다 제목·소제목 앵커(쪽 안 위치 표시)가 살아 있어 근거 링크를 만들기 좋다. 소스 저장소(RST)는 보조로 쓴다.
4. 라이선스는 CC BY-SA 4.0. 설명서가 직접 권하는 표시 문구는 "Blender 5.2 Manual by the Blender Documentation Team is licensed under CC-BY-SA v4.0" + 링크다. 로고·아이콘·코드는 이 라이선스에서 빠진다.
5. 본문 쪽의 **71%에 그림이 있다**(그림 3,782개). 그림 아래 설명(캡션)은 72%에 있지만, 대체 텍스트(alt, 그림을 글로 설명한 것)는 19%뿐이고 나머지는 파일 이름이다. 5.2 LTS는 2026-07-14 출시, 2028년 7월까지 지원.

## 질문별 답

### 1. 전체 쪽수와 목차만 있는 쪽

**방법:** 두 가지로 셌고 숫자가 맞았다.

- 소스 저장소의 `blender-v5.2-release` 브랜치(마지막 커밋 2026-08-17, `4a3be8f`)를 내려받아 `.rst` 파일(설명서 원본 글 파일)을 셈 → **2,358개**. 출처: <https://projects.blender.org/blender/blender-manual/src/branch/blender-v5.2-release>
- 공식 HTML 묶음 <https://docs.blender.org/manual/en/5.2/blender_manual_html.zip> (2026-10-18 갱신, 360,076,475바이트)을 풀어 `.html` 파일을 셈 → 2,361개. 여기서 404·찾아보기(genindex)·검색(search) 3개를 빼면 **2,358개**이고, RST 목록과 하나도 어긋나지 않았다.
- 비교용으로 같은 방법으로 센 4.5(`blender-v4.5-release`)는 **2,072개**. 사용자가 4.5 때 센 2,072개와 같다.
- 제안서의 "5.2 목차 항목 약 2,350개"는 이 2,358쪽과 거의 같은 숫자다. 참고로 첫 화면 <https://docs.blender.org/manual/en/5.2/> 왼쪽 목차의 항목 수는 2,544개였다(같은 쪽이 여러 번 나오거나 쪽 안 항목이 섞인 것으로 보이지만, 정확한 이유는 확인하지 않았다).

**목차만 있는 쪽:** "목차 상자(toctree)가 있고, 제목·목차를 빼면 본문이 20단어 이하"인 쪽을 목차 쪽으로 봤다. 기준에 따라 숫자가 조금 바뀐다.

| 기준(목차 상자 있음 + 본문 단어 수) | 쪽 수 |
|---|---|
| 0단어 | 247 |
| 10단어 이하 | 282 |
| **20단어 이하(권하는 기준)** | **297** → 본문 쪽 2,061 |
| 50단어 이하 | 317 |

- 목차 상자가 있는 쪽은 모두 373개인데, 그중 76개는 목차와 함께 설명 본문도 있어 지우면 안 된다.
- 목차 상자는 없지만 본문이 20단어 이하인 아주 짧은 쪽도 32개 있다(예: 텍스처 노드 쪽 일부, 3단어). 지울지 말지는 청크 티켓에서 정하면 된다.
- 4.5 때 2,072 → 1,734(338개 제외)와 기준이 같은지는 알 수 없다(4.5 수집 코드를 찾지 못함). 같은 방법으로 비교하려면 4.5 HTML 묶음에도 위 스크립트를 돌려야 한다.

**분야별 쪽 수(전체 2,358):** 모델링 774, 렌더 303, 컴포지팅 212, 에디터 201, 스컬프트·페인트 129, 애니메이션 124, 물리 120, 그리스 펜슬 118, 장면 배치 64, 비디오 편집 62, 인터페이스 58, 무비 클립 35, 파일 33, 고급 31, 문제 해결 29, 기여 안내(contribute) 26, 애드온 19, 시작하기(getting_started) 16, 기타 4.

- `contribute`(26쪽)는 설명서를 고치는 사람을 위한 안내라 초보자 질문과 관계가 적다. 검색 대상에서 뺄지 결정이 필요하다.
- 본문 단어 수: 전체 약 72만 단어, 본문 쪽 한 개의 중간값 204단어, 상위 10%는 777단어 이상, 가장 긴 쪽 6,568단어.
- 제안서의 "초보자 범위 약 300쪽"은 공식 분류가 없어 확인할 수 없다. 공식 "시작하기" 분야는 16쪽뿐이다.

### 2. 공식 한국어 번역

- **주소는 있다.** <https://docs.blender.org/manual/ko/5.2/> 와 <https://docs.blender.org/manual/ko/latest/> 모두 열리고 제목도 "Blender 5.2 LTS Manual"이다. 한국어 HTML 묶음도 있다: <https://docs.blender.org/manual/ko/5.2/blender_manual_html.zip> (2026-10-18 갱신).
- **번역 파일(PO 파일, 문장별 원문-번역 짝을 담은 파일)로 본 번역률:** 번역 저장소 <https://projects.blender.org/blender/blender-manual-translations> 의 `blender-v5.2-release` 브랜치(2026-10-18 커밋) `ko/LC_MESSAGES/blender_manual.po`를 직접 세었다.
  - 전체 46,699문장 중 **번역 완료 506개(1.1%)**, 퍼지(fuzzy, "다시 확인 필요"로 표시된 옛 번역) 9,446개(20.2%), 미번역 36,747개(78.7%).
  - 단어 기준으로는 번역 완료 0.8%.
  - 분야별 번역 완료 비율이 가장 높은 곳도 "시작하기" 12.0%, "인터페이스" 6.2% 정도다.
  - 퍼지 번역은 옛 버전에서 남은 것이라 틀린 것이 많다. 예: "Selection can be lazy." → "위치". 설명서 빌드 설정 `conf.py`에 `gettext_allow_fuzzy_translations = False`가 있어서 퍼지 번역은 사이트에 나오지 않는다(소스 저장소 `manual/conf.py` 136번째 줄).
  - 파일 머리말에 번역 작업 위치가 `https://translate.blender.org/projects/blender-manual/blender-5-2/manual-5-2/ko/`(Weblate, 여러 사람이 웹에서 번역하는 도구)로 적혀 있고, 마지막 한국어 수정은 2026-09-07이다.
- **실제 한국어 사이트로 본 결과:** 한국어 HTML 묶음 전체 2,358쪽에서 단락·목록·그림 설명 71,858개를 셌더니 한글이 들어간 것은 4,751개(6.6%)였다. 많이 나온 한글은 "이미지", "참고", "단축키(hotkey) :", "팁", "더 보기" 같은 꼬리표였다. 한글이 절반 넘는 쪽은 19쪽, 쪽 제목이 한글인 쪽은 114쪽뿐이다.
- **결론:** 한국어판은 사실상 영어판이다. 한국어 답을 하려면 영어 원문을 검색하고 번역은 우리가 만들어야 한다(지도의 "번역은 연습 과정 + 초보자 범위만" 원칙과 맞는다). 공식 번역 몇 개를 용어 대조표로 쓸 수는 있지만, 양이 적고 퍼지 번역은 믿으면 안 된다.

### 3. 내려받는 방법과 어느 쪽이 청크에 좋은가

청크: 검색하려고 글을 잘게 자른 조각.

| | 공식 HTML 묶음(zip) | 소스 저장소(RST) |
|---|---|---|
| 받는 곳 | <https://docs.blender.org/manual/en/5.2/blender_manual_html.zip> (EPUB 묶음 `blender_manual_epub.zip`도 첫 화면에 링크가 있음) | `git clone https://projects.blender.org/blender/blender-manual.git` 후 `blender-v5.2-release` 브랜치. 그림은 Git LFS(큰 파일을 따로 보관하는 git 기능)로 받는다(설명서 `contribute/manual/getting_started/local_editing/install/windows.rst`) |
| 크기 | 360MB(풀면 약 1.37GB, 파일 5,929개, 그림 3,139개) | 저장소 약 870MB(대부분 그림) |
| 빌드 | 필요 없음(이미 만들어진 쪽) | Sphinx(RST를 HTML로 바꾸는 도구)로 `make` 실행. 필요한 프로그램은 `requirements.txt`(sphinx 9.1.0, furo 테마 등). 출처: <https://docs.blender.org/manual/en/5.2/contribute/manual/getting_started/local_editing/build.html> |
| 끼워 넣기(include) | 이미 합쳐져 있음 | `.. include::` 244곳을 직접 풀어야 함 |
| 제목·소제목 | 쪽마다 `<section id="...">`로 앵커가 있어 `…/bevel.html#options` 같은 링크를 바로 만들 수 있음 | 제목 표시는 명확하지만 앵커 이름은 Sphinx 규칙을 따라 다시 만들어야 함 |
| 군더더기 | 쪽마다 왼쪽 전체 목차가 들어 있어 쪽 하나가 수백 KB. 본문은 `<article id="furo-main-content">` 안만 쓰면 됨 | `:kbd:`, `:menuselection:` 같은 표시 문법을 지워야 함 |
| 추가 정보 | Python 명령 이름 표시(예: `id="bpy-ops-mesh-bevel"`)가 앵커로 남아 있음 | 같은 표시가 `.. _bpy.ops.mesh.bevel:` 형태로 1,365곳. 쪽 맨 위 "모드·메뉴·단축키" 상자(`.. reference::`) 1,518곳 |

**권하는 것:** 본문은 **HTML 묶음**에서 뽑는다. 끼워 넣기가 이미 풀려 있고 쪽 주소와 소제목 앵커가 그대로라 근거 링크를 만들기 쉽다. 같은 날 받은 영어 HTML과 RST 목록이 정확히 일치하므로, 필요하면 RST에서 "모드·메뉴·단축키" 같은 정보를 메타데이터로 덧붙일 수 있다.

**링크 주의:** HTML 안의 대표 주소(canonical)는 `https://docs.blender.org/manual/en/latest/...`로 되어 있다. `latest`는 다음 버전이 나오면 바뀌므로, 근거 링크는 `https://docs.blender.org/manual/en/5.2/<쪽 경로>.html#<앵커>`로 고정해 만드는 것이 안전하다. 5.3 브랜치(`blender-v5.3-release`)는 이미 있다.

**갱신 주의:** 5.2 HTML 묶음은 2026-10-18에 다시 만들어졌지만, 소스 브랜치 마지막 커밋은 2026-08-17이다. 묶음은 주기적으로 다시 만들어지는 것으로 보인다. 받은 날짜와 커밋 번호를 `data/`에 함께 적어 두면 나중에 같은 자료인지 확인할 수 있다.

### 4. 라이선스 표시 방법

출처: 설명서의 라이선스 쪽 <https://docs.blender.org/manual/en/5.2/copyright.html> (소스 `manual/copyright.rst`), 저장소 `LICENSE`(CC BY-SA 4.0 전문)

- 따로 적힌 것이 없으면 설명서 내용은 **CC BY-SA 4.0 또는 그 이후 버전**(출처를 밝히고, 고친 것도 같은 조건으로 공개해야 하는 라이선스).
- **빠지는 것:** 로고, 상표, 아이콘, 소스 코드와 Python 스크립트.
- **표시 방법:** "Blender Documentation Team"을 밝히고 설명서로 가는 링크를 넣는다. 설명서가 든 예시:
  > The Blender 5.2 Manual by the Blender Documentation Team is licensed under a CC-BY-SA v4.0.
  (링크: 설명서 주소, <https://projects.blender.org/blender/documentation>, <https://creativecommons.org/licenses/by-sa/4.0/>)
- 쪽마다 아래쪽에 "This page is licensed under a CC-BY-SA 4.0 Int. License"가 붙어 있다.
- 더 자세한 방법은 설명서가 Creative Commons의 안내 <https://wiki.creativecommons.org/wiki/Marking/Users> 를 보라고 한다(blender.org 밖이라 내용은 확인하지 않았다).
- 우리에게 뜻하는 것: 직접 만든 번역·쉬운 말 풀이는 원문을 고친 것이므로 공개할 때 CC BY-SA 4.0으로 내야 한다고 보는 것이 안전하다(법률 판단은 아님).

### 5. 그림이 들어간 문서 비율과 그림 설명

**방법:** 표본이 아니라 영어 HTML 묶음 전체(2,358쪽)의 본문(`<article>`)을 모두 셌다. 대체 텍스트가 파일 경로(`…/_images/xxx.png`)이거나 이미지 확장자로 끝나면 "의미 없음"으로 봤다. RST 소스에서도 `:alt:` 옵션 수를 따로 셌다.

| 항목 | 값 |
|---|---|
| 그림이 1개 이상 있는 쪽 | 1,473 / 2,358 (62.5%) |
| 본문 쪽(목차 쪽 제외)만 보면 | 1,472 / 2,061 (**71.4%**) |
| 본문 속 그림 수 | 3,782개(모두 figure 형식, RST의 `.. figure::` 3,414개 + 끼워 넣기로 반복된 것) |
| 그림 아래 설명(캡션)이 있는 그림 | 2,740개 (**72.4%**), 예: "Cubes without and with bevel." |
| 의미 있는 대체 텍스트(alt)가 있는 그림 | 730개 (**19.3%**). RST의 `:alt:` 옵션은 591곳이고 대부분 모델링·컴포지팅·렌더 분야 노드 그림. 내용은 "Mix Node." 같은 짧은 이름이 많음 |
| alt가 없는 그림 | 나머지는 Sphinx 기본값인 **파일 경로**가 alt로 들어감(예: `../../../../_images/modeling_meshes_editing_edge_bevel_cubes.png`) |
| 동영상이 있는 쪽 | 62쪽(video.blender.org를 iframe으로 끼워 넣음, RST의 `.. peertube::` 64곳) |
| 그림 파일 형식(소스) | png 2,165 · webp 641 · jpg 308 · svg 36 · gif 3 |

- 파일 이름도 쪽 경로를 따라 지어져 있어(예: `modeling_meshes_editing_edge_bevel_cubes.png`) 그림이 어느 쪽 것인지는 알 수 있다.

### 6. Blender 5.2 LTS 출시일과 지원 기간

- 출시일 **2026년 7월 14일**, LTS(장기 지원판)라서 "**최대 2년, 2028년 7월까지**" 버그 수정을 받는다. 출처: <https://www.blender.org/download/releases/5-2/>, <https://www.blender.org/download/lts/5-2/>
- 지금 최신 판은 **5.2.2(2026-09-15)**. 출처: <https://www.blender.org/download/lts/>
- 설명서는 판(5.2.0, 5.2.2 …)마다 따로 나오지 않고 `5.2` 하나로 관리된다(묶음 안 폴더 이름 `blender_manual_v520_en.html`).

## 확인 못 한 것

- **Weblate 번역 통계 화면:** translate.blender.org는 사람 확인(Cloudflare) 화면이 떠서 열지 못했다. 대신 같은 내용을 담은 번역 저장소의 PO 파일을 직접 셌다. Weblate가 보여 주는 퍼센트와 조금 다를 수 있다.
- **번역 파일(1.1%)과 한국어 사이트(6.6%) 숫자 차이:** 사이트 쪽은 "참고", "팁" 같은 꼬리표와 짧은 용어도 세었기 때문으로 보이지만, 두 숫자를 한 줄씩 맞춰 보지는 않았다.
- **4.5 때 목차 쪽 338개를 뺀 기준:** 4.5 수집 코드가 이 PC에 없어 같은 기준인지 알 수 없다. 코드 위치는 사용자에게 물어야 한다.
- **"초보자 범위 약 300쪽":** 공식 분류가 없어 확인할 수 없다.
- **왼쪽 목차 2,544개와 쪽 2,358개의 차이** 이유는 따져 보지 않았다.
- **그림 자체에 있는 글자**(화면 캡처 속 메뉴 이름 등)가 얼마나 되는지는 그림을 열어 봐야 해서 세지 않았다.
- 그림·동영상에 설명서와 다른 라이선스가 붙은 경우가 있는지는 쪽마다 확인하지 않았다("따로 적힌 것이 없으면"이라는 조건만 확인).

## 다음 결정에 주는 시사점

**청크·검색 방식 티켓에:**

- 검색 대상은 **본문 쪽 약 2,061개**(목차 쪽 297개 제외, `contribute` 26쪽은 넣을지 결정 필요). 쪽 길이가 중간값 204단어에서 6,568단어까지 다양하므로, 쪽 하나를 통째로 청크로 쓰기보다 **소제목(section) 단위로 자르고**, 청크마다 `쪽 제목 > 소제목` 경로와 `…/en/5.2/<경로>.html#<앵커>` 링크를 붙이는 방식이 맞다.
- 한국어 공식 번역이 거의 없으므로 "원문 + 번역을 함께 담은 청크"의 번역은 우리가 만들어야 한다. 그러면 사용자의 한국어 질문을 영어 원문과 맞추는 방법(질문을 영어로 바꿔 검색하기, 여러 언어를 아는 임베딩 쓰기 등)을 먼저 정해야 한다. 전체(약 72만 단어)를 번역하는 것은 비용이 크므로 지도의 원칙대로 연습 과정 + 초보자 범위만 번역하는 것이 현실적이다.
- 쪽마다 있는 "모드·메뉴·단축키" 상자와 `bpy.ops…` 명령 이름은 애드온이 읽는 작업 상태(지금 모드, 마지막에 쓴 명령)와 설명서 쪽을 이어 주는 열쇠가 될 수 있다. 메타데이터로 남길지 검토할 만하다.

**그림 처리 티켓에:**

- 본문 쪽의 71%에 그림이 있지만, 글로 된 설명은 캡션(72%)이 대부분이고 대체 텍스트는 19%뿐이다. 우선 **캡션을 그림 정보로 청크에 넣는 것**이 가장 싸다.
- 캡션이 없는 그림 약 1,040개(28%)는 글로 된 정보가 파일 이름뿐이다. 그림을 AI로 설명하게 하려면 비용이 드는 API 호출이 되므로, 연습 과정 + 초보자 범위 그림부터 할지 따로 정해야 한다.
- 답에 그림을 보여 줄 경우, 그림도 CC BY-SA 4.0 출처 표시 대상이고 로고·아이콘은 라이선스에서 빠진다는 점을 지켜야 한다.

## 재현 방법(이번 조사에서 한 일)

- 소스: `git clone --depth 1 --filter=blob:none --no-checkout --branch blender-v5.2-release https://projects.blender.org/blender/blender-manual.git` → `git ls-tree`로 파일 목록, 글 파일만 sparse checkout(일부 파일만 꺼내기). 4.5도 같은 방법으로 파일 목록만 셈.
- HTML: 영어·한국어 5.2 HTML 묶음을 내려받아 그림을 빼고 풀어 Python(BeautifulSoup)으로 `<article>` 안을 셈.
