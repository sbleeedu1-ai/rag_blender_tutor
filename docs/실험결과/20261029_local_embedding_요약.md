# 로컬 임베딩 후보 비교

2026-10-29 · Codex · 강의실 PC. 원본: `results/20261029_local_embedding_report/`(Git 제외). 티켓 41, HISTORY [111].

현재 상위 6개 기준으로 EmbeddingGemma를 다음 확인 후보로 권한다. 근거 적중률은 70%(OpenAI 67.5%), 검색 중앙값은 0.151초(OpenAI 0.213초)다. 20문항에서의 2.5%p 차이이며, 일반적인 우열이나 설명서 전체 성능으로 확정하지 않는다. granite는 빠르지만 적중률 50%, e5-small은 35%였다. 세 모델의 현재 PyTorch 실행은 라이브러리 포함 불러오기 10.9-13.1초로 조사 문서의 잠정 목표 5-8초보다 길다.

질문 20개 × 회차 3 × 조건 5개. 채점은 1회차 순위, 시간은 모든 회차.
묶음 200청크(번역 있음 90개). 새 유료 호출: 없음(기존 OpenAI 기준선 결과를 재사용)

## 해석할 때 주의

- 200청크·20문항의 작은 실험이다. 질문마다 필요한 근거 수·난이도가 달라 몇 문항이 결과를 크게 움직인다.
- BM25는 한국어를 두 글자씩, 영어를 낱말로 자른다. 번역 포함 BM25의 효과에는 이 한국어 처리의 영향이 함께 들어 있다.
- 묶음의 번역 비율은 설명서 전체(약 15%)보다 높다. 전체 설명서의 최종 성능으로 읽지 않는다.
- 처음 정답 순위는 남긴 상위 50개 안에서만 센다(BM25를 켜면 RRF에 든 청크만).
- '회차마다 순위 다름'은 같은 질문의 2·3회차 순위가 1회차와 달랐던 질문이다(임베딩이 매번 조금 달라질 때).

## 준비·불러오기 시간

모두 초 단위. 불러오기 합계는 라이브러리 import + 모델 파일 읽기다.

| 모델 | 다운로드 | 설치 직후 첫 불러오기 | 재실행 불러오기 | 라이브러리 / 파일 읽기(첫 유효 실행) | 200청크 DB 생성 | 받은 파일(MB) |
|---|---|---|---|---|---|---|
| granite-embedding-97m-multilingual-r2 | 8.114 | 제외: Blender 조작 겹침 | 10.876 | 9.501 / 1.375 | 17.259 | 220.2 |
| multilingual-e5-small | 15.254 | 12.465 | 12.728 | 9.421 / 3.044 | 13.616 | 493.3 |
| embeddinggemma-300m | 29.823 | 12.892 | 13.105 | 9.480 / 3.411 | 70.796 | 1269.6 |

- granite 첫 실행은 원본을 보존하고 속도 비교에서 제외했다. 유효 실행은 재실행 불러오기이며, DB 생성은 대기 상태에서 별도 폴더에 새로 만들었다.
- 기존 BGE-M3 3.799초는 라이브러리 import를 뺀 모델 파일 불러오기 시간이다. 위 합계 시간과 직접 비교하지 않는다.
- 모델 파일만이 아니라 토크나이저·설정·README 등 실제로 받은 파일의 합계다. 실행 라이브러리 설치 크기는 별도다.
- PyTorch CPU float32 실행만 비교했다. ONNX·8비트 등 작은 실행 형식의 속도와 품질은 확인하지 않았다.
- e5-small은 최대 512토큰, EmbeddingGemma는 2,048토큰, granite는 32,768토큰이다. 입력 길이는 모델 기본값을 사용했다.

## 판단할 때 남는 조건

- 영어 원문만·BM25 끔·한국어 질문에 사전의 영어 메뉴 이름 덧붙이기를 모든 모델에 똑같이 적용했다. 원래 질문과 실제 검색어가 같은지도 300개 행에서 대조했다.
- 한국어를 영어로 번역하거나 답변을 생성하는 모델은 부르지 않았다. 질문과 설명서가 다른 언어인 검색의 결과다.
- 새 모델 3개는 각 60개 표본을 모두 보존했고, 채점은 기존 규칙대로 첫 회차에서만 했다. 마지막 확인용 홀드아웃은 실행하지 않았다.
- 시간은 같은 PC의 별도 실행이다. 기존 BGE-M3·OpenAI의 18조건 교차 실행과 새 모델을 하나씩 실행한 환경 차이가 있다.
- 다운로드 직후에도 운영체제 파일 캐시가 남을 수 있다. 첫 설치 직후라는 측정 조건을 PC 재부팅 직후로 바꿔 부르지 않는다.
- 도우미의 현재 검색 모델은 OpenAI 그대로다. 실제 도우미 연결이나 설명서 전체 8,997청크 검증은 이번 실험에 포함하지 않았다.

## 실제 검색 예와 입력 길이 확인

- 실제 평가 W1은 의자의 회전 기준을 맞추려고 오리진을 바닥으로 옮기는 방법을 묻는다(질문 뜻을 요약, 원문은 Git 제외 자료에 보존).
- [공식 설명서 Object Origin → Set Origin](https://docs.blender.org/manual/en/5.2/scene_layout/object/origin.html#set-origin)의 원문 표기: `Mode: Object Mode`, `Menu: Object ‣ Set Origin`, `Origin to 3D Cursor`. 웹 쪽 제목은 Object Origin, 쪽 안 소제목은 Set Origin, 그 안의 옵션 이름이 Origin to 3D Cursor다.
- 우리 코드의 해당 청크 첫 줄은 `Object Origin > Set Origin`, 열쇠는 `scene_layout/object/origin.html#set-origin/1`이다. W1은 이 기능과 커서를 원하는 곳으로 옮기는 근거 두 묶음을 찾아야 한다.
- 상위 6개에서 OpenAI·granite·e5는 필요한 근거 0/2, BGE-M3·EmbeddingGemma는 1/2였다. EmbeddingGemma는 Set Origin 청크를 2위로 찾았지만 커서 위치 근거까지는 찾지 못했다. 평균이 가장 높아도 이 질문을 완전히 해결한 것은 아니다.
