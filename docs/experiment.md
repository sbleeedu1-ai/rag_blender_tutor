명세 "평가" 절의 기록 파일. 숫자는 여기에만 두고 HISTORY에는 링크만 남긴다.
번호: GPT 빈손 `[E0]`, 우리 도우미는 `[E1]`부터, 홀드아웃은 마지막.
채점: 맞음(초보자가 그대로 따라 해서 된다) / 부분 / 틀림. 틀린 원인 6가지: 검색 실패 / 검색은 맞는데 답이 틀림 / 문서에 원래 없음 / 질문이 모호함 / 상태 읽기 틀림 / 블렌더 표기 틀림.

## 체크리스트 (2026-11-03, [E1]에서 장면을 잘못 만들어 채점이 틀린 일 뒤에 만듦)

채점은 이 체크리스트를 받은 새 하위 에이전트가 한다(메인 세션의 짐작이 섞이지 않게). 메인 세션은 결과를 사용자에게 보이고, 판단이 갈린 것은 사용자에게 묻는다.

### 장면(작업 상태)을 만들 때

1. 연습 과정 단계 문항이면 그 단계 **앞 단계까지 실제 Blender에서 따라 한 결과**와 같은가. 연습 과정 파일(`courses/*.yaml`)의 '쉬운 설명'·'안내'가 말하는 화면(예: 합친 뒤 재질 목록의 빈 칸)이 장면에 있는지 본다. 스크립트가 손으로는 생기지 않는 정리(빈 칸 지우기 등)를 하지 않는다.
2. 질문 글이 장면 그림과 맞는가(질문은 "안 보여요"인데 그림에는 잘 보이는 식이면 고친다).
3. 그림을 눈으로 본다. 재질 색·셰이딩·모드가 의도대로 찍혔나(머티리얼 미리보기는 준비에 시간이 걸린다).

### 답을 채점할 때 (차례마다)

1. **답의 문장마다 출처를 찾는다**: 연습 과정의 그 단계 글(모델에 넘어간 것), 검색된 조각, 작업 상태. 연습 과정 글을 따른 말이 상태와 안 맞으면 답보다 **장면을 먼저 의심**하고 체크리스트 위 1번으로 확인한다.
2. **따라 해서 되나**: 맞음은 초보자가 그대로 따라 해서 된다는 뜻이다. 누를 곳이 '어디에' 있는지 빠지면(예: "설정에서 늘리면 돼요") 맞음이 아니다.
3. **"설명서에 없어요"·"방법이 없어요"는 확인한다**: 청크 파일(`data/chunks/manual_chunks.jsonl`)을 검색해 실제로 없는지 본다. 있으면 그 주장은 틀린 말이다.
4. **Blender 동작 주장은 확인한다**: 계산(회전 각도 등)은 상태 값으로 따져 보고, 필요하면 화면 없는 Blender로 실제로 해 본다. 짐작으로 틀렸다고 하지 않는다.
5. **상태 읽기**: 답이 말한 숫자·이름(선택 수, 배율, 활성 물체)을 작업 상태 JSON과 대조한다.
6. **연습 과정 권하기**(티켓 22 규칙): 연습 과정 밖 단순 질문에 연습 과정을 권하면 틀림. 없는 물건을 만들고 싶다는 질문에 "가장 가까운 건 …"으로 권하면 맞음, 권하지 않으면 부분.
7. **원인은 근거와 함께**: 검색 결과 8개 목록과 정답 조각의 실제 글을 보고 6가지 중 하나로 나눈다. 정답 위치가 여러 개면 '적중'으로 세졌어도 답에 필요한 조각이 실제로 들어 있었는지 따로 본다(예: [E1] D03).
8. **애매하면 판단 대상으로 표시**하고 이유를 적는다. 혼자 정하지 않는다.
