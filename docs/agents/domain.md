# 도메인 문서

엔지니어링 스킬이 코드를 살펴볼 때 이 저장소의 도메인 문서를 어떻게 읽을지 정한다.

## 살펴보기 전에 읽을 것

- 루트의 **`CONTEXT.md`** (용어집. 일반적인 `GLOSSARY.md` 대신 이 이름을 쓴다)
- **`docs/adr/`**: 작업할 영역과 관련된 ADR(중요한 설계 결정 기록)을 읽는다.

이 파일들이 없으면 **조용히 넘어간다**. 없다고 알리거나 미리 만들자고 제안하지 않는다. `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture`에서도 호출됨)이 용어나 결정이 실제로 정해질 때 만든다. 이 스킬이 `GLOSSARY.md`를 말하면 이 저장소에서는 `CONTEXT.md`로 읽고 쓴다.

## 파일 구조 (single-context)

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-첫-결정.md
│   └── 0002-두번째-결정.md
└── src/
```

## 용어집의 말을 쓴다

결과물(이슈 제목, 리팩터링 제안, 가설, 테스트 이름)에서 도메인 개념을 부를 때는 `CONTEXT.md`에 정의된 용어를 쓴다. 용어집이 피하라고 한 동의어로 바꾸지 않는다.

필요한 개념이 `CONTEXT.md`에 없다면 신호다. 프로젝트가 쓰지 않는 말을 지어내고 있거나(다시 생각한다), 실제로 빠진 용어다(`/domain-modeling`용으로 메모한다).

## ADR과 충돌하면 드러낸다

결과물이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 분명히 밝힌다.

> _ADR-0007(이벤트 소싱 주문)과 어긋나지만, 다음 이유로 다시 논의할 가치가 있다…_
