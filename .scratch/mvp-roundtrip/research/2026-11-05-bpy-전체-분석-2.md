- 날짜: 2026-11-05
- 앞 문서: [`2026-11-05-bpy-전체-분석.md`](2026-11-05-bpy-전체-분석.md)(이름 전체), [`2026-11-05-bpy-작업상태-지도.md`](2026-11-05-bpy-작업상태-지도.md)(화면 없이 본 값)

- 실행 환경: Blender 5.2.2 LTS(hash d13f752e3b9c), 창 있음, `--factory-startup --console-crash-handler`, 꺼 둔 번들 애드온 5개를 메모리에서만 켬. 장면과 사용자 설정은 저장하지 않았다.

## 요약

| 일 | 결과 | 빠짐 |
|---|---|---|
| 1. 화면 지도 | 화면 클래스 2,550개, 도구 줄 455행, 코드에서 뽑은 항목 21,943줄, 실제로 그려 읽은 버튼 48,969개, 거꾸로 찾는 칸 표 5,932줄 | 스크립트의 layout 호출 11,217개 중 10,728개가 화면 클래스에 닿음. 나머지 489개와 까닭은 표에 있음 |

| 4. 함수·조작 | 함수 6,093개를 넷으로 나눔(합 맞음). 읽기 1,828개를 실제로 불러 1,772개가 값을 돌려줌. 조작 2,605개 표 | 조작은 실행하지 않음. poll이 거짓일 때 이유 글을 읽는 길을 찾음 |

핵심 발견은 다섯이다.

1. **`layout.introspect()`로 실제 화면 버튼을 읽을 수 있다.** 패널을 그리는 순간 호출하면 버튼마다 RNA 칸, 조작, 보이는 글, 도움말이 나온다. C가 그리는 틀 안까지 나오므로 코드 읽기보다 넓다. 예: `OBJECT_PT_transform`에서 `Object.location[0]`, 보이는 글 `0 m`, 도움말 `Location of the object`.
2. **`Context`는 마우스 위치를 따른다.** 키 F10에서 불린 조작의 `context.area`는 마우스가 있는 영역이다. `view3d.view_selected`는 3D 화면 본문 위에서만 poll이 참이고, `outliner.item_activate`는 물체 목록 본문 위에서만 참이다. `transform.rotate`, `object.delete`처럼 어디서나 참인 조작도 있다. 3D 영역을 `temp_override`로 주면 답이 3D 기준으로 고정된다(4-4절).
3. **poll 거짓의 이유 글은 있다. 다만 읽는 길은 호출 실패 글뿐이다.** poll이 거짓일 때 조작을 부르면 실행 전에 `RuntimeError`로 끝나고 글에 이유가 나온다(조작 189개, 서로 다른 글 49종, 실제 실행 0번). 이유 글을 직접 돌려주는 함수는 못 찾았다.
4. **읽기로 분류한 함수는 장면을 바꾸지 않았다.** 값이 나온 1,772개 호출마다 전후 요약이 같았고, 마지막 실행의 전체 값 128,088구조 비교에서 바뀐 것이 0개였다. 호출하면 Blender가 죽는 함수 2개가 있다.
5. **적힌 타입과 실제 타입이 다른 칸이 많다.** 값을 읽은 칸 2,659개 중 1,363개에서 실제 값은 자식 타입이다. `Object.modifiers`는 `Modifier`라고 적혀 있고 값은 `BevelModifier` 등이다. 자식의 칸은 자식 타입 칸 목록을 봐야 나온다.

앞 조사에서 내가 저지른 부작용이 하나 있어 적는다. 앞 조사의 `addons` 단계가 사용자 애드온 `blender_tutor_addon`까지 메모리에서 켜, **도우미 프로그램이 2번 떴다**(11:59, 12:06, `%TEMP%\blender_tutor_receiver.log`). 기록에 질문 처리는 없고 Blender가 닫히자 스스로 끝났다. 벡터 캐시 파일(`data/vectors`)은 그 시각 뒤로 바뀌지 않아 임베딩 호출은 없었던 것으로 본다. 작업 상태 기록 `%APPDATA%\blender_tutor\streams\20261105-115906.jsonl`(858바이트)이 남아 있고 지우지 않았다. 이번에는 이 애드온을 켜지 않고 코드로만 봤다.

## 사람 없이 돌리기

크래시 창 때문에 멈추지 않게 바꿨다. `--console-crash-handler`와 `--disable-crash-handler`를 일부러 충돌을 내어 시험했다(`option_check/`).

| 옵션 | 스스로 끝남 | 걸린 시간 | 크래시 위치 기록 |
|---|---|---|---|
| 없음 | 아니오(창이 떠서 25초 뒤 내가 끔) | | `.crash.txt` 파일 |
| `--console-crash-handler` | 예(종료 코드 -1073741819) | 8초 | 표준 오류에 같은 내용, 파이썬 줄까지 |
| `--disable-crash-handler` | 예 | 7초 | 없음 |

그래서 `--console-crash-handler`를 썼다. 옵션을 켠 실행과 끈 실행에서 조작 수, 타입 수, 문맥 이름 수, 단축키 수, poll 참 수, 장면 통계 등이 파일 단위로 같았다(`facts_plain_none.json`, `facts_plain_console.json`). 실행기(`launch2.ps1`)는 75초 동안 진행 표시가 멈추거나 시간 제한을 넘으면 **자기가 띄운 프로세스 번호만** 끈다. 반복기(`loop2.ps1`)는 죽은 자리를 건너뛸 목록에 더해 이어 가고, 같은 자리에서 연달아 죽으면 멈춘다.

## 1. 화면 지도

### 1-1. 방법

세 가지를 합쳤다. 줄마다 어느 쪽에서 왔는지 적었다.

- **코드 읽기**: 등록된 클래스의 그리는 함수에서 시작해, 파이썬 구문 나무(AST)로 불리는 함수를 끝까지 따라가며 layout 호출을 모았다. 분기와 상관없이 다 잡는다.
- **가짜 layout 실행**: draw에 기록용 가짜 layout을 넘겨 652개 상태(물체 종류·모드·편집기·탭)에서 돌렸다. 대상 값이 실제 값이라 대상 타입이 확실하다. 화면에는 그리지 않는다. 10,556줄 기록.
- **실제 그리기**: draw를 감싸 실제로 그리는 순간 `layout.introspect()`로 버튼을 읽었다(2절). 1,223개 클래스에서 버튼 48,969개.

`Mesh.use_auto_smooth`는 5.2 RNA에 없는 칸이라(실행 확인: 있나 = False) 비교용으로 넣었다. `BevelModifier.width`가 없는 것은 모디파이어 패널 내용을 C가 그리기 때문이다. 코드에는 `template_modifiers` 한 줄뿐이고, 대상별 패널이라 실제 그리기도 하지 못했다. 칸이 없는 것이 아니라 **이 지도가 모디파이어·제약·효과 패널 안의 칸 위치를 못 담았다는 뜻**이다.

RNA 칸(화면 타입과 조작 입력 제외) 10,600개 중 화면에서 찾은 것 4,870개이고, 못 찾은 5,730개는 `props_not_on_screen.csv`에 있다. "화면에 없다"는 뜻이 아니다. 시도한 상태에서 안 그려졌거나, 패널이 아니라 C 틀이나 화면 위 동작으로만 쓰는 칸일 수 있다.

실제 그리기에서만 나온 칸 203개(코드 표에 없고 그림에 있음): 예 `AOV.name`, `AOV.type`, `Area.ui_type`, `Armature.name`, `Armature.rigify_active_action_slot`, `Armature.rigify_colors_index`, `Armature.use_fake_user`, `AttributeGroupCurves.active_index`, `AttributeGroupGreasePencil.active_index`, `AttributeGroupMesh.active_color_index`, `AttributeGroupMesh.active_index`, `AttributeGroupPointCloud.active_index`, `BoneCollections.active_index`, `Camera.composition_guide_color`. 대부분 `template_ID`, `template_color_ramp` 같은 C 틀이 그린 칸이다.

### 4-4. poll 이유 글과 문맥

**이유 글을 읽는 길.** RNA와 `bpy.ops`에서 찾았다.

- `Operator.poll_message_set`: 파이썬 조작의 `poll` 안에서 이유를 **적는** 함수다. 읽는 함수가 아니다.
- `bpy.ops.x.y`의 공개 이름은 `bl_options`, `get_rna_type`, `idname`, `idname_py`, `poll`뿐이고, `_bpy.ops`에도 `poll` 글을 돌려주는 것이 없다. RNA에서 `poll`·`msg`·`message`를 찾으면 `Operator.poll_message_set`만 나온다.
- **남은 길**: poll이 거짓인 것을 확인한 뒤 조작을 부르면 실행 전에 `RuntimeError`가 나고 글에 이유가 있다. 시험 조작에서 `Operator bpy.ops.bt_poll.msg.poll() 시험 이유 글입니다`이 나왔다.

2,605개 조작을 4개 문맥(3D 화면, 큐브 활성, 문맥 없음(타이머), 물체 목록, 속성 편집기)에서 시험했다. **실제로 실행된 조작 0개**(poll이 거짓인 때만 불렀다).

읽는 법:

- F10의 `context.area`와 `region`은 **마우스 아래** 영역이다. 머리줄 위에서 누르면 `region`이 `HEADER`다.
- 3D 영역 전용 조작(`view3d.*`)은 마우스가 3D 화면에 없으면 거짓이다. `view3d.view_selected`는 머리줄에서도 거짓이라 본문이어야 참이고, `view3d.view_axis`와 `view3d.snap_cursor_to_center`는 머리줄에서도 참이다. 편집기 전용 조작도 비슷하다(`outliner.item_activate`는 물체 목록 본문만, `action.select_all`은 머리줄도 참).
- `object.delete`, `transform.rotate`, `object.mode_set` 등은 시험한 모든 위치에서 참이었다. 참은 "실행을 시도할 수 있다"는 뜻이고 그 자리에서 쓸모 있게 돈다는 뜻은 아니다.
- `invoke`와 `execute`의 차이는 이번 시험에서 나타나지 않았다. 타이머에서 영역 없이 부르면 `area`는 None이고 참이 가장 적다.
- `context.temp_override(window=, area=3D, region=WINDOW)`를 주면 어디서 불러도 답이 3D 기준으로 같아진다. 다만 편집기 전용 조작은 3D 기준으로 거짓이 된다.

이번 시험 조작은 이 저장소의 F10 조작이 아니라 같은 모양의 시험 조작이다. 흉내 낸 입력으로 실제 키보드는 아니다.

## 5. 확인하지 못한 것

- **읽으면 죽어 비운 값**: `is_overridable`(지시대로 전체 안 읽음), 패널·메뉴 실물의 `bl_description`, 패널 실물의 `custom_data`, `Panel.custom_data`의 메타 `tags`, 평가된 `NodeLink.is_hidden`. 원인은 조사하지 않았다.
- **불렀더니 죽은 함수 2개**: `DynamicPaintSurface.output_exists`, `XrSessionState.action_state_get`. 띄우면 죽는 패널: `COLLECTION_PT_exporters`, 대상별 패널 전부.
- **화면 지도**: 대상 타입을 확정 못 한 칸 호출 814개. C 패널·C 영역의 칸(그림으로 보거나 C 코드가 있어야 한다. C 소스는 받지 않았다). 메뉴의 실제 호출 위치 140개. 분기를 다 돌았다는 보장이 없는 가짜 layout 실행의 대상 타입.
- **값**: 못 본 타입 732개(까닭은 표). 파이썬 조작의 실행 중 `self`.
- **함수 분류**: 규칙과 눈으로 나눈 것이다. 전부 읽어 맞춘 것은 아니다. "바꾼다"와 "그리기·등록"은 부르지 않았으니 분류가 맞는지 실행으로 확인되지 않았다.
- **실제 사람 입력**: 키는 흉내 낸 이벤트다. 실제 F10의 `context`와 비교하지 않았다. 저장소 애드온의 F10은 켜지 않아 시험하지 않았다.
- **애드온**: 번들 5개는 메모리에서 켰고(Rigify 포함, 이번에는 `default_set=True`로 성공), 사용자 애드온 `blender_tutor_addon`은 켜지 않았다(켜면 도우미가 뜸). 사용자 확장은 없다.
- **VR, 3D 마우스**: 장치가 없어 관련 타입의 값을 못 봤다(세션이 안 열림으로 확인, 장치 부재는 추측).
