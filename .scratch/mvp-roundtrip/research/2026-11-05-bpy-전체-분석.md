# Blender 5.2 `bpy` 전체 분석

- 날짜: 2026-11-05
- 목적: 창을 띄운 Blender 5.2에서 `bpy`(Blender가 파이썬에 내주는 창구)가 제공하는 것을 고르지 않고 전부 나열하고, 빠진 것이 없음을 개수로 보인다. 어떤 값을 도우미에 넣을지는 여기서 정하지 않는다. 앞선 문서 [`2026-11-05-bpy-작업상태-지도.md`](2026-11-05-bpy-작업상태-지도.md)가 화면 없이 고른 칸을 봤다면, 이 문서는 창을 띄워 전체를 본다.
- 실행 환경: Blender 5.2.2 LTS(hash d13f752e3b9c), 창 있음(`--factory-startup`, 공장 설정), 파이썬 3.13.13, Windows 11, 창 크기 1920×1057. 장면은 빈 장면 `data/eval/dev50/scenes/base/untitled.blend`(큐브·카메라·조명 3개)이고 저장하지 않았다.
- 전체 자료: `results/20261105/120433_bpy_dump/` (Git 밖, 파일 목록은 13절)

## 요약

**`bpy`의 공개 이름은 9개다**(`app`, `context`, `data`, `msgbus`, `ops`, `path`, `props`, `types`, `utils`). 그 안에 조작 2,499개, 타입 4,112개, 타입이 직접 가진 칸 11,226개와 함수 6,093개가 있다. 이름은 모두 나열했고, 공식 API 문서·설명서 생성 도구·Blender 자체 코드와 대조해 빠진 이름을 찾지 못했다(2절). 다만 대조 중에 내 첫 나열이 등록 타입 28개를 놓친 것이 드러나 더했고, 값을 읽지 못한 칸이 세 가지 있다(12절).

핵심 발견은 넷이다.

1. **창이 있어야 생기는 이름은 없다.** 창 없이 돌린 결과와 조작·타입·칸 수·모듈·문맥 이름이 하나도 다르지 않다. 창이 바꾸는 것은 **값**이다. 단축키 항목 3228개(창 없이 12개), 값을 읽은 구조 15,746개(창 없이 3,101개), N 패널 탭 `Item`(창 없이 `UNSUPPORTED`), 조작 기록 글(창 없이 빈 목록).
2. **키를 친 것처럼 시험하는 길이 있다.** `Window.event_simulate`와 `--enable-event-simulate`로 R, Z, 9, 0, Enter를 보내자 `wm.operators`에 `value` 1.5708, `constraint_axis` [False, False, True]가 남았다. 앞선 문서가 미확인으로 둔 "사람이 키로 실행한 값"을 흉내 낸 입력으로 확인했다(실제 키보드는 아니다).
3. **진행 중 조작의 값은 끝날 때까지 안 바뀐다.** R Z 9 0까지 친 때 물체는 이미 90° 돌아 있는데 `window.modal_operators[0].properties.value`는 0.0, `constraint_axis`는 전부 거짓이다. 진행 중 값을 이 칸으로는 알 수 없다.
4. **조작 2,499개 중 690개는 이번에 만든 어떤 상태에서도 실행 가능(poll 참)으로 나오지 않았다.** 없는 것이 아니라 필요한 조건(자산, 트랙 등)을 만들지 않은 것으로 본다(추측).

## 읽는 법

- **RNA**: Blender가 "내가 가진 타입·칸·함수는 이것"이라고 스스로 알려 주는 목록. 대부분의 숫자는 여기서 나왔다.
- **타입**: `Object`, `Mesh` 같은 자료의 틀. **칸**은 타입이 가진 값 하나(`Object.location`), **함수**는 타입이 가진 동작 하나(`Object.select_get`)다.
- **조작**: `bpy.ops.transform.rotate`처럼 메뉴·키로도 부르는 동작. **poll**은 "지금 상태에서 이 조작을 실행할 수 있나"를 묻는 검사로, 조작을 실행하지 않는다.
- **문맥**: `bpy.context.active_object`처럼 "지금 어디서 무엇을 보고 있나"를 담은 값들. **편집기**는 3D 화면·속성 편집기 같은 창 한 칸의 종류, **영역**(region)은 그 안의 머리줄·도구 줄·본문 같은 조각이다.
- **enum**: 정해진 글자 중 하나만 받는 칸(예: `rotation_mode`의 `XYZ`, `QUATERNION`).
- **확인 수준**: "실행"은 이번에 Blender를 띄워 나온 값이다. "코드"는 Blender에 들어 있는 파이썬 파일을 글자로 찾은 결과다. "추측"은 그렇게 적었다.

- `bpy.app.autoexec_override`: 문서에 있고 5.2.2에 없다(`hasattr` 거짓, 실행). 버전 차이로 본다(추측).

- `Operator.bl_property`: 문서에 있고 클래스에는 없다. 애드온이 클래스에 적는 약속으로 보인다(추측).
- `anim.update_animated_transform_constraints`, `wm.console_toggle`: 덤프에 있고 문서에 없다.

검사기 자체도 시험했다. 일부러 이름을 하나 뺐을 때 조작 1개, 타입 1개, 문맥 1개가 빠졌다고 나왔다.

**대조로 잡은 실제 누락.** 첫 나열은 `dir(bpy.types)`와 칸이 가리키는 타입만 따라가 등록 타입 28개를 놓쳤다. 키잉 세트 22개(`BUILTIN_KSI_*`, `Location`, `WholeCharacter` 등), Cycles·glTF 쪽 4개(`CyclesPreferences`, `CyclesDeviceSettings`, `GLTF_AddonPreferences`, `GLTF2_filter_action`), 렌더 엔진 `CYCLES`, 단축키 묶음 설정 `Prefs`(`presets/keyconfig/Blender.py`)다. 이들은 `bpy.types`의 `dir`에 없고 파이썬 클래스와 `_rna_info`로만 보인다. `types_extra.json`에 더했고, 그 뒤 위 표의 빠짐이 0이 됐다. 같은 까닭으로 앞선 지도 문서의 "타입 4,030개"는 RNA 아닌 이름 18개를 포함하고 이 28개와 숨은 72개를 뺀 수다.

**한계**: 이 대조는 "지금 등록된 것"을 맞춘다. 꺼 둔 애드온(9절 끝)과 사용자가 까는 확장이 더할 이름은 합계에 없다. 대조한 출처가 모두 놓친 이름이 있는지는 증명할 수 없다.

## 4. `bpy.ops`

조작 2,499개, 분야 77개. `ops.json`에 이름·설명·옵션·입력 칸(기본값, 범위, enum 항목)·도움말 글이 모두 있다. 조작은 **실행하지 않았고** poll만 불렀다.

- 입력 칸 종류: BOOLEAN 2,976, ENUM 1,084, INT 790, FLOAT 680, STRING 500, POINTER 118, COLLECTION 80.

버튼을 그릴 때 `layout.context_pointer_set("modifier", ...)`로 넣어 둔 값을, 버튼을 누른 조작 안에서 읽는 이름이다(코드). 예: `bl_ui`의 `context.button_operator`. 값은 보지 못했다. 사람이 그 버튼을 누르는 순간에만 있기 때문이다. `texture_slot`은 C 쪽 목록에 있는데 `dir`에 안 나왔고, 속성 편집기의 텍스처 탭에 어떤 조건을 갖춰야 나오는지는 확인하지 못했다.

## 9. 값까지 읽기

`bpy.data`, `bpy.context`(3D 화면 영역을 준 상태), 환경 설정, 평가된 장면에서 시작해 칸이 가리키는 것을 끝까지 따라가며 값을 읽었다(`values.jsonl`). 함수는 부르지 않고, 파이썬 `@property`는 읽었다. 같은 것은 (타입, 메모리 주소)로 한 번만 읽었다. 시작 전에 큰 영역의 편집기를 23종 모두 한 번씩 거쳐 Space 실물이 남게 했다.

| 장면 | 구조 | 값 | 실물 타입 | 읽기 오류 |
|---|---|---|---|---|
| 빈 장면 | 15,746 | 222,767 | 1,293 | 1 |
| 실물 장면 | 111,451 | 613,222 | 2,041 | 1 |

실물 장면은 메모리 안에서 물체 20종, 모디파이어(83종을 메시에 붙여 봐서 55종이 붙음. 그리스 펜슬 26종과 볼륨 2종은 오류 없이 붙지 않았고, 내 스크립트가 해당 물체에 다시 붙이지 않아 값을 못 봄), 제약 29종, 노드 556개(나무 4종), 텍스처 12종, 시퀀서 조각 2개와 빈 데이터 4종을 만들어 읽었다. 만들기 실패 22건은 모두 추상 부모(`ShaderNode`)나 등록되지 않은 노드 이름이다(`values_rich_summary.json`의 `made.fail`).

"실물 타입"에는 단축키 항목이 담은 조작 입력 타입 937개가 들어 있다. 이것들은 `ops.json`의 조작 입력과 같은 것이다. 타입 전체 4,112개 중 값까지 읽은 것은 1,104개이고, 나머지 3,008개는 **이름과 모양만 알고 값은 못 봤다**.

| 값을 못 본 타입 | 수 | 까닭 |
|---|---|---|
| 패널·메뉴·머리줄·목록·선반·파일 처리기·파이썬 조작·렌더 엔진 | 2,265 | 클래스로 등록돼 있고, 실물은 그리거나 실행하는 순간에만 생긴다. 함수 안에서만 보임 |
| 묶음의 함수 타입(`BlendDataObjects` 등) | 194 | 칸을 읽으면 항목 목록으로 돌아와 이 타입의 실물이 값으로 나오지 않는다. `new`·`remove`는 `types.json`에 있음 |
| 그 밖(`MovieTracking*`, `Mask*`, `Bone`, `NlaStrip`, `Driver` 등) | 549 | 이 장면에 그런 자료를 만들지 않았다. 목록은 `analysis.json`의 `unseen_other` |

## 12. 확인하지 못한 것

**읽으면 Blender가 죽어 건너뛴 값 3가지.** 모두 `EXCEPTION_ACCESS_VIOLATION`(프로그램이 잘못된 메모리를 읽음)으로 죽었고 보고서는 `crash_reports/`에 있다. 왜 죽는지는 조사하지 않았다.

| 값 | 어디서 죽었나 | 처리 |
|---|---|---|
| `Property.is_overridable` | `FunctionNodeInputIntVector.vector`, `FunctionNodeInputVector.vector`, `ImagePreview.image_pixels`, `ImagePreview.image_pixels_float`의 메타를 읽을 때 차례로 죽음. 이 넷 말고 더 있는지는 모름. 첫 시험에서 조작 입력 칸을 읽을 때는 죽지 않았음 | **모든 칸에서 읽지 않음.** 메인 세션이 "사용자 승인, 작업 상태와 관계없는 값"이라며 건너뛰라고 전달한 지시를 따랐다. 그래서 칸 11,226개와 조작 입력에 이 값이 없다. 같은 뜻으로 보이는 `bpy_struct.is_property_overridable_library`는 이름만 확인하고 부르지 않음 |
| `Panel.custom_data`의 메타 `tags` | 이 칸 하나 | 건너뜀(`types_meta.json`의 `meta_crash_list`). 같은 `tags`는 다른 칸에서 읽힘 |

**실행하지 않아 모르는 것.**
