## Answer

2026-10-19 사용자와 질문 라운드(Q1-Q28)로 정함. 근거: 강사님 기준(`data/강사님의 기준.txt`, 커밋 안 함. 4단계 평가셋 20/5/5, 5단계 오답노트, 최종 측정 숫자 표), 이전 프로젝트 `rag_korea_history`의 최종 측정·채점 방식(별도 채점기는 일치 66%라 참고용), 제안서 5쪽(30 + 10문항, 정답·근거 위치, 작업 연동 품질, 속도).

| 항목 | 결정 |
|---|---|
| 문항 단위 | 질문 글(시나리오형은 앞선 대화 포함) + **작업 상태 JSON**(우리용) + **스크린샷 PNG**(GPT용) + 맞는 답의 핵심 1-3개 + **정답 위치**(설명서 쪽 주소·소제목 1-2개). JSON·PNG는 문항을 만드는 순간 함께 저장한다. 애드온에 평가용 "지금 상태 저장" 단축키를 더한다. `.blend` 파일은 저장하지 않는다 |
| 문항 출처 | 섞는다: 사용자가 검 연습 과정을 따라 하다 막힌 곳 / 티켓에 쌓인 후보(아래) / AI 초안을 사용자가 자기 말로 고쳐 씀. 설명서 문장을 그대로 옮기지 않는다. 정답 위치는 미리 AI가 초안, 사용자가 링크를 열어 확인 |
| 개발 30 | **정답형 20**(연습 과정 단계 10 / 한국어 화면 메뉴 위치 3 / 초보자 범위 밖 어려운 것 3 / 앞선 대화에 이어 묻는 시나리오형 4) + **문서에 없는 질문 5**(게임 엔진에 넣기, 4.5에만 있던 기능, 다른 프로그램 등) + **함정 5**(배열 vs 배열(레거시), 번역이 여러 개인 Apply, "4.5 강좌대로 했는데 메뉴가 없어요"). 작은 분류도 기록해 오답 분석에 쓴다 |
| 홀드아웃 10 | 정답형 6 / 없는 질문 2 / 함정 2. 내용은 나중에 정하되 **"고치기 전" 결과를 보기 전에** 써서 봉인한다(`data/`, 커밋 안 함). 코드 동결(커밋 번호 기록) 뒤 **한 번만** 돌리고, 그때 `eval/`로 옮긴다. 틀린 것을 보고 고치지 않는다 |
| 측정 단계 | 강사님 표 그대로: **GPT 빈손 / 고치기 전 / 고친 후(개발) / 고친 후(홀드아웃)**. GPT는 개발 30·홀드아웃 10 모두 |
| 재는 것 | 답 정확도, 검색 적중(정답 위치가 검색 결과에 들어왔나, 프로그램이 셈), 근거 표시 정확도(붙은 근거가 답을 뒷받침하나), 상태 읽기 맞음/틀림(문항마다 JSON을 PNG와 대조), 시간. GPT 빈손의 검색 적중·근거 표시는 해당 없음. 모든 숫자에 분모와 채점자(사람/AI/프로그램) |
| GPT 조건 | 사용자가 **무료 웹**에서 직접(유료 이용자가 적다는 이유). 문항마다 새 대화(시나리오형만 같은 대화에 앞선 질문 먼저), 기억·개인 설정 끔, 스크린샷 + 같은 질문 글, **연습 과정 정보 안 줌**. 기본 상태(Think 안 누름, 스스로 추론하면 기록만), Think 켬은 참고용 5문항. 날짜·표시된 모델 이름을 문항마다 적는다. 하루 이미지 제한 때문에 며칠에 나눌 수 있다 |
| 시간 | 개발 10(고치기 전 단계, GPT 빈손도 같은 10) + 홀드아웃 10(최종)만. **질문 준비**(GPT: 스크린샷 키 → 엔터 / 우리: F10 → 입력 가능 약 0.1초 + 붙여 넣기)와 **보낸 뒤**(엔터 → 답 끝, 우리는 첫 글자까지도). 질문 글은 양쪽 모두 미리 복사해 붙여 넣는다. 초 단위, 스톱워치로 충분. PC 이름(강의실 PC: i7-4770, GTX 950 2GB, 16GB)을 함께 적는다. 우리 쪽 정확도는 평가 프로그램이 JSON으로 자동 실행 |
| 채점 | 맞음 / 부분 / 틀림. 맞음 = 초보자가 그대로 따라 해서 된다. 없는 질문은 지어내지 않으면 맞음(우리: "설명서에 없다" + 가까운 쪽 권함, GPT: 사실에 맞는 일반 답도 맞음). **Claude가 AI 채점자**(별도 채점 프로그램·API 비용 없음, 이전 프로젝트에서 gpt-4o-mini 채점기를 그만둔 이유와 같음). 홀드아웃 10은 사용자가 어느 쪽 답인지 가린 채 따로 채점하고 **Claude와 사람의 일치율**로 "AI vs 사람 채점 비교"를 채운다 |
| 이겼다 기준(결과 전에 적음) | 홀드아웃에서 ① 우리 답 끝까지(질문 준비 포함)가 GPT의 절반 이하 ② 맞음 수가 GPT 빈손보다 적지 않다. "GPT가 반드시 틀려야 한다"는 조건은 없다. GPT가 이기는 부분은 한계로 숨기지 않고 적는다 |
| 파일 위치 | 개발 문항·채점 기준·정답 위치·JSON·PNG는 `eval/`(커밋). 측정마다 GPT 답 원문·우리 답·채점표는 `results/<날짜>_<이름>/`에 새로(덮어쓰지 않음) |
| 실험 기록 | `docs/experiment.md` 한 파일 = 강사님 5단계 오답노트 + 6단계 실험 로그. 실험마다 `[E번호] 날짜 · 제목`: 무엇을 바꿨나 / 결과(전 → 후, 분모·채점자) / 틀린 원인 개수 / 대표 실패 1-2개(질문 → 가져온 조각 → 원인 가설) / 채택·기각 / 다음 테스트 한 줄 / results 경로. GPT 빈손은 `[E0]`(원인 분류 없이 틀린 사례와 화면 캡처 경로), 홀드아웃은 마지막(다음 테스트 = "고치지 않음, 한계로"). 숫자는 여기에만, HISTORY에는 링크만. 실패 유형 집계표는 results 채점표에서 나중에 엑셀로 뽑는다 |
| 틀린 원인 6가지 | 검색 실패 / 검색은 맞는데 답이 틀림 / 문서에 원래 없음 / 질문이 모호함(강사님 4가지) + **상태 읽기 틀림** / **화면 이름 틀림**(한국어 ↔ 영어 메뉴 짝). 채점표 칸에는 이 이름만 쓴다 |

**강사님 중간 확인 때 물어볼 것:** GPT에게 연습 과정 정보(지금 몇 단계인지)를 주지 않는 조건이 괜찮은지.

이 평가로 판단하기로 앞 티켓에서 넘긴 것(그대로 개발 평가에서 본다): 초보자 범위 밖 한국어 질문(전체 번역 여부), 리랭커·bge-m3·초보자 범위 순위 올리기, 시나리오형에서 붙여 검색 vs 검색어 다시 쓰기, 최근 대화 3쌍 vs 5쌍.

ADR은 만들지 않음: 측정 방식은 강사님 틀을 따른 것이고, 문항 수·비율은 나중에 바꿀 수 있다.
