# 그림이 중요한 설명의 처리

Type: grilling
Status: resolved
Blocked by: 02

## Question

그림이 있어야 이해되는 설명서 내용을 검색과 답에서 어떻게 다루는가?

## 조사에서 넘어온 것

- 본문 쪽 71.4%에 그림, 캡션 72.4%, 쓸 만한 alt 19.3%
- 캡션을 청크에 넣는 것이 가장 쌈. 캡션 없는 그림 약 1,040개를 AI로 설명하면 유료
- (청크·검색 방식) 글 없이 영상만 있는 소제목 40개(주로 "Example", video.blender.org 영상), 그림만 있는 소제목 9개는 청크로 만들지 않았다. 이 둘을 어떻게 보여 줄지(예: "영상 있음" 표시와 링크) 여기서 정한다

## Answer

2026-10-19 사용자와 질문 라운드로 정함. 근거: 공식 HTML 묶음(`data/manual_en_5.2/`)의 `<figure>` 구조 확인(캡션은 `figcaption`에 글자로 있음, alt는 대부분 파일 경로), 도우미 창 시제품은 tkinter(기본으로 PNG·GIF만 표시, 설명서 그림 중 JPG 307·WEBP 638개), 그림 폴더 251MB. 사용자가 캡션 없는 그림 예시(Bevel의 Width Type, Profile Shape, 영역 나누기, 사이드바, 상단 바)를 웹사이트에서 직접 봄.

| 항목 | 결정 |
|---|---|
| 청크 글 속 그림 | 그림 자리에 캡션이 있으면 `[그림: 캡션]`, 없으면 `[그림]`만 남긴다. 파일 경로뿐인 alt는 버린다. 그림 주소는 메타데이터로만 |
| 캡션 없는 그림 AI 설명 | MVP에서 하지 않는다. 개발용 평가에서 그림을 봐야 답할 질문이 틀리면 초보자 범위의 캡션 없는 그림만 설명을 붙이는 선택지(실행 전 비용 확인) |
| 답에서 그림·영상 보여 주기 | 도우미 창에 직접 띄우지 않는다. 근거 링크로 설명서 웹사이트의 그 소제목을 열고, 링크 옆에 "그림 있음"·"영상 있음"만 표시. 미리보기는 나중에 출력 쪽 확장 |
| 영상만 40·그림만 9개 소제목 | 청크로 만들지 않고 같은 쪽 바로 앞 청크 메타데이터에 "영상/그림 예시 + 링크"를 붙인다. 표시는 위와 같음. 글 속에 영상이 있는 소제목도 그 청크 메타데이터에 영상 링크 |
| 답변 모델 지시 | 그림 내용은 캡션 글만 쓰고 지어내지 않는다. `[그림]`이 답에 중요해 보이면 "설명서 그림을 함께 보세요"라고 안내 |

사용자 말: "Q2 일단 네", "웹사이트라는 기반이 있으니 이미지와 영상 모두 이렇게 처리하죠", "그럼 그냥 메타데이터 말한대로 붙여두면 될거같네요 ... 해당하는 청크에 붙여서", "3-5 는 설명으로 커버칠만해보이는데 1,2 는 흠.. 예시를 보는게 좋아보이긴 한느데 없어도 이해는 할거같고", "최소한 캡션이 없어도 그림이 있었다는 정보정도는"
