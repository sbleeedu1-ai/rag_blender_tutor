# 48: 쓸 사람이 무슨 권한을 왜 주는지 알고 정하도록, README에 운영체제 권한과 밖으로 보내는 자료를 빠짐없이 적는다

Status: needs-triage

근거: HISTORY [314], 사용자 "쓸 사람들은 무슨 권한을 가져가는지 다 알고 결정해야해 뭐 어디 이상한 곳으로 안보내고 우리 내부적으로 쓰이는 점도 상세하게 다 설명해줘야하고". README는 아직 없다. 만들 때 이 내용을 넣는다.

## 적을 것

권한마다 "무엇을 할 수 있게 되는 권한인가 → 우리가 실제로 쓰는 부분 → 쓰지 않는 부분 → 안 주면 어떻게 되나"를 적는다. 쓸 때 코드로 다시 확인하고 근거 위치를 단다.

- Mac '손쉬운 사용'(도우미가 처음 켜질 때 한 번만 묻는다. 다시 묻게 하려면 `~/Library/Application Support/blender_tutor/accessibility_asked`를 지운다, HISTORY [316]): Mac 설명으로는 다른 앱 제어·키보드 감시 등까지 되는 넓은 권한이다. 우리는 마우스 왼쪽 단추를 누르는 순간만 받아, 누른 자리의 창이 Blender인지 다른 앱인지 보고 도우미 창 자리만 옮긴 뒤 그대로 흘려보낸다(`macapi.watch_clicks`). 키보드는 받지 않고, 누른 자리·창 정보를 저장하거나 밖으로 보내지 않는다. 안 주면 Blender로 돌아올 때 도우미가 잠깐 깜빡인다.
- Mac '입력 모니터링': 도우미가 묻지 않고 없어도 된다(손쉬운 사용만으로 됨, HISTORY [315]). 이미 켜 두었으면 손쉬운 사용이 없을 때 엿듣기로 쓴다(가끔 깜빡임).
- Mac이 처음 켤 때 물을 수 있는 것: 이동식 볼륨(프로그램이 바깥 저장 장치에 있을 때만. 내장 디스크면 안 물을 것, 추측), 문서·데스크탑·다운로드 폴더(프로젝트를 그 안에 두면 물을 수 있음, 추측 — README에는 권하는 설치 위치를 함께 적는다), 로컬 네트워크(도우미는 이 컴퓨터 안 127.0.0.1로만 Blender와 주고받는다. 서버가 켤 때 자기 주소 이름을 묻던 것을 빼서 이제 안 묻는다, HISTORY [315]. 물으면 거부해도 된다).
- Windows: 따로 묻는 권한 없음(F10으로 도우미를 앞에 부를 때 Blender가 허락하는 함수만 씀). 강의실 PC에서 다시 확인.
- 밖으로 보내는 자료: 질문 글과 Blender 상태(모드·고른 물체·장면 정보 등)는 답을 만들려고 AI 회사 API로 간다(지금 기록상 OpenAI 임베딩·Anthropic 답 모델). 무엇이 어디로 가는지 코드에서 항목별로 확인해 적는다. 마우스 누름·창 정보는 보내지 않는다.
- 이 컴퓨터에 남기는 것: 작업 상태 흐름 기록·시간 기록(`~/Library/Application Support/blender_tutor/`, Windows APPDATA) — 무엇이 남고 어떻게 지우는지.
- 2026-11-13 사용자 확인(Mac, 권한을 모두 지우고 새로 켬): 뜬 창은 로컬 네트워크·손쉬운 사용('기기 제어 및 데이터 접근')·제거 가능한 볼륨, 입력 모니터링은 안 뜸. 거부해도 시스템 설정 목록에 꺼진 줄로 남음. 거부 뒤 다시 켜면 손쉬운 사용만 또 묻고 로컬 네트워크는 안 물음. 제거 가능한 볼륨을 막으면 도우미가 `No module named 'blender_tutor'`로 켜지지 않는데 사용자에게 까닭을 알리는 안내가 없다(README에 적고, 안내를 더할지는 따로 정함).
- 권한을 거두는 법: 시스템 설정의 각 목록에서 BlenderTutorHelper 끄기·빼기.
