# 속도 목표 숫자

Type: grilling
Status: resolved
Blocked by: 01, 04

## Question

단축키부터 답이 다 나올 때까지 몇 초 안을 목표로 하는가?

## 조사에서 넘어온 것

- 이전 프로젝트에서 시간을 잡아먹은 것은 답변이 아니라 리랭커·근거 대조 같은 추가 호출. 구성(호출 수)과 목표를 함께 정한다
- 목표를 '첫 글자까지'와 '답 끝까지'로 나눌지
- low/medium/none 시간을 재는 작은 유료 실험(몇 센트)은 사용자 승인 뒤에만
- 잰 시간은 PC마다 다르다. 어느 PC에서 쟀는지 기록한다(강의실 PC: i7-4770, GTX 950 2GB, 16GB, Blender 5.x 최소 사양선)
- (애드온 왕복 시제품, 강의실 PC) F10 → 도우미 창 입력 가능 108-124ms, 애드온 쪽 부담 15-64ms, 작업 상태 읽기 약 0.004ms. 우리 쪽 "질문 준비 시간"은 F10 → 입력 가능 + 입력 시간
- (애드온 ↔ 서버 형식) 답은 스트리밍, 근거는 답 끝에. 시간은 "첫 글자까지"와 "답 끝까지" 둘 다 기록하기로 함
- (대화 기억 범위) 앞말 질문도 추가 호출 없이 붙여 검색한다. 최근 대화 3쌍(설정값)이 답 모델 입력에 더해진다
- (GPT 비교 평가 설계) 시간은 개발 10(고치기 전) + 홀드아웃 10(최종)만, "질문 준비"(F10 → 입력 가능 + 붙여 넣기)와 "보낸 뒤"(첫 글자까지, 답 끝까지)로 나눠 초 단위로 잰다. GPT 대비 기준은 미리 정함: 홀드아웃에서 답 끝까지(질문 준비 포함)가 GPT 무료 웹 기본 상태의 절반 이하. 여기서는 GPT와 상관없는 우리 자체 목표 숫자를 정한다

## Answer

2026-10-19 사용자와 질문 라운드(Q1-Q8)로 정함. 유료 호출 없음.

| 항목 | 결정 |
|---|---|
| 목표의 성격 | **개발 목표**. 넘으면 원인을 찾아 고치고, 추가 호출을 켤지 이 숫자로 정한다. 탈락선은 아니다(합격 기준은 GPT 비교의 "이겼다 기준"이 맡음) |
| 기준 PC | **강의실 PC**(i7-4770, GTX 950 2GB, 16GB, Blender 5.x 최소 사양선). 집 PC 값은 참고로만 |
| 목표 숫자(잠정) | 강의실 PC, 10문항 **중앙값**으로 판정(최대값도 적음). 질문 준비(F10 → 입력 가능) **0.5초 이하** / 보낸 뒤 → 첫 글자 **2초 이하** / 보낸 뒤 → 답 끝 **6초 이하** |
| 숫자 고치기 | 구현 첫 단계의 실측 뒤 **한 번만** 고칠 수 있다. 고치면 HISTORY에 적는다 |
| 생각 수준 실측 | 지금은 하지 않음. 구현 첫 단계에 **none과 low만** 잰다. medium은 low로도 안 될 때만 그때 잰다 |
| 생각 수준 고르기 | **none으로 시작**, 모자라면 low. medium은 최후의 수단이고 답 끝 6초를 넘기면 고르지 않는다 |
| none → low 판단 | 전체 맞음 수가 아니라 **추론이 들어갈 만한 문항만** 따로 본다: 앞선 대화에 이어 묻는 시나리오형(멀티턴) 4 + 함정 5(개발 평가 기준) |
| 호출 수 | 질문당 **2번 고정**(임베딩 1 + 답 1). 리랭커·검색어 다시 쓰기·로컬 bge-m3 등은 정확도가 올라도 목표 숫자를 넘기면 채택하지 않고 `docs/experiment.md`에 "속도 때문에 기각"으로 남긴다 |
| 시간 기록 | 도우미 창이 F10 받음 / 입력 가능 / 보냄 / 첫 글자 / 답 끝 시각과 생각 수준·PC 이름을 기록 파일에 자동으로 남기고, 평가 프로그램이 중앙값·최대값을 낸다. 스톱워치는 GPT 비교 20문항에만 |

ADR은 만들지 않음: 숫자는 잠정이고 실측 뒤 바꿀 수 있다.

사용자 말: "네 구현이후 일단 none/low 까지만 보죠", "역으로 none 으로 시작해 low 까지로 봅시다 강조하는대로 속도가 생명이니 / medium 은 최후의 수단", "네 추론이 들어갈만한 멀티턴 대화 / 함정 문항만"
