# 40: 검색 방식을 고를 근거를 마련하기 위해, 소규모 자료로 검색을 비교한다

Blocked by: 없음. 필요한 원문·번역·메뉴 이름 검수 결과는 준비되어 있으며, 31번 전체 완료를 기다리지 않는다.
Status: resolved

근거: `grill-with-docs`에서 확정한 소규모 검색 실험, [HISTORY [93]](../../../HISTORY.md), [31번 번역과 임베딩](31-유료-번역과-임베딩.md).

**비용이 드는 실행 전마다 자료 생성·질문 처리·반복 횟수를 반영한 추정 비용을 보여 주고 사용자 확인을 받는다.**

## 할 일

같은 질문과 설명서 청크 묶음으로 검색 방식들을 실행해, 실제 정답 근거를 얼마나 찾는지와 시간이 얼마나 걸리는지 비교한다. 답변 모델은 호출하지 않는다. 검색용 DB와 다시 실행할 수 있는 비교 프로그램, 개별 결과와 비교표를 남기고 사용자가 다음 실험 후보를 판단할 수 있게 한다.

31번에서 이미 번역·검수한 자료를 입력으로 사용한다. 이 티켓의 결과를 보고 31번에서 전체 자료에 적용할 검색 방식을 정한다. 전체 자료의 임베딩·저장, 연습 과정 벡터, 실제 도우미 연결 등 31번의 남은 일은 이 티켓으로 옮기지 않는다.

## 완료 조건

### 질문과 청크

- [x] 질문부터 정한 뒤 정답 근거와 검색할 청크를 모은다. 설명서 청크를 먼저 읽고 거기에 맞춘 질문을 만드는 순서로 바꾸지 않는다.
- [x] 독립적으로 이해할 수 있는 한국어 질문 20개를 만든다. 웹에서 실제 초보자 질문을 찾아 참고하는 10개와 AI가 작성하는 10개로 구성한다. 앞선 대화에 이어 묻는 문항은 넣지 않는다.
- [x] 웹 질문은 가능한 한 반복해서 등장하는 초보자 주제에서 찾고 출처 링크·선정 근거를 남긴다. 확인하지 않은 질문 빈도를 가장 많다고 단정하지 않는다. 실제 질문의 뜻을 살려 쓰고 설명서 문장을 그대로 옮기지 않는다.
- [x] 모든 질문은 Blender 5.2 공식 설명서에서 정답 근거를 확인한다. 웹 게시글의 답변을 그대로 정답으로 삼지 않는다. 질문마다 정답 청크와 공식 설명서 링크를 등록한다.
- [x] 정답 근거에 번역이 있는 질문 10개·없는 질문 10개로 나눈다. 웹 질문과 AI 작성 질문에 각각 5개씩 배분하며, 번역이 없는 쪽도 초보자가 할 만한 질문에서 찾는다.
- [x] 정답 청크를 모두 포함하고, 비슷해서 헷갈릴 청크와 다른 분야의 청크를 더해 200개를 목표로 검색 묶음을 만든다. 필요한 정답·경쟁 후보를 빼서 개수를 맞추지 않는다. 필요하면 늘릴 수 있으며 이유와 바뀐 묶음을 기록한다.
- [x] 같은 질문·청크 묶음을 모든 조건에 사용한다. 묶음을 바꾼 뒤에는 모든 조건에 같은 변경을 적용하고 새 결과로 비교한다. 홀드아웃과 기존 본평가의 문항 구성은 건드리지 않는다.

### 검색 조건과 저장

- [x] 아래 세 축을 독립적으로 바꾼 기본 18개 조합을 모두 실행한다. 리랭커는 사용하지 않는다.

| 비교 축 | 조건 |
|---|---|
| 임베딩 모델 | text-embedding-3-large / 로컬 BGE-M3 |
| 뜻 검색에 넣는 글 | 영어 원문만 / 원문+번역을 이어 붙여 하나로 임베딩 / 원문·번역을 각각 임베딩한 뒤 검색 결과를 합침 |
| BM25 | 끔 / 영어 원문 / 원문+번역 |

- [x] 번역을 포함하는 조건에서도 번역이 없는 청크는 영어 원문으로 유지한다. 임베딩 모델에 넣는 글은 BM25용으로 자르지 않는다.
- [x] 원문·번역을 분리한 검색에서는 같은 청크의 높은 점수 하나로 최종 순위를 만든 뒤 결과 개수를 자른다. 원문·번역 각각의 점수·순위도 보관한다. 서로 다른 비교 조건의 결과를 중복이라는 이유로 지우거나 합치지 않는다.
- [x] BM25 점수 계산은 현재의 BM25Okapi로 고정한다. 한국어는 두 글자씩 겹쳐 자르고 영어는 단어 단위로 처리한다. 모든 BM25 조건의 문서와 질문에 같은 분할 규칙을 적용한다. BM25를 켠 조건에서는 뜻 검색과 해당 BM25의 순위를 RRF로 합친다.
- [x] 한국어와 영어의 분할 단위가 달라, 번역 포함 BM25의 효과에는 이 한국어 처리의 영향도 포함된다는 점을 결과에 명시한다. 이전 프로젝트의 BM25 계산식을 그대로 옮기는 작업으로 바꾸지 않는다.
- [x] 사전으로 한국어 메뉴 이름에 영어 이름을 덧붙이는 기존 기능을 모든 조건에서 켜 둔다. 원래 질문과 실제 검색어를 모두 기록한다.
- [x] 설명서의 검색용 DB를 모델·입력 글에 맞춰 한 번씩 만들고 재사용한다. 어떤 글과 모델·설정으로 만들었는지 남긴다. 정확도 비교에서 같은 입력의 임베딩을 반복 생성하지 않는다.
- [x] 검색 결과를 고르는 개수 외의 기존 순위 합치기 설정은 고정하고 기록한다. 원문·번역·BM25의 개별 점수·순위와 합친 최종 결과를 보관한다.

### 검색 적중과 후보 비교

- [x] 각 조합에서 같은 검색 순위의 상위 4개·6개·8개를 모두 평가한다. 서로 다른 결과 개수를 섞어 검색 방식의 우열을 정하지 않는다.
- [x] 같은 쪽 주소가 아니라 실제 정답 청크가 잡혔는지로 판정한다. 처음 등장한 정답의 순위도 남긴다. 조건 사이의 유사도 숫자 크기만으로 검색 성능을 판단하지 않는다.
- [x] 같은 답을 충분히 설명하는 대체 청크와, 함께 찾아야 답을 설명할 수 있는 여러 근거를 구분해 등록한다. 대체 청크를 여러 개 찾았다고 같은 필수 근거를 중복해서 세지 않는다.
- [x] 일부 적중과 필요한 근거의 전체 적중을 모두 기록한다. 질문마다 필요한 근거 중 찾은 비율을 구하고, 20개 평균으로 질문별 비중을 같게 둔다. 필요한 근거를 전부 찾은 질문 수도 별도로 남긴다.
- [x] 전체 결과뿐 아니라 정답 근거의 번역 유무별 결과와 질문별 결과를 함께 제시한다. 작은 묶음과 20문항의 한계, 근거 수·난이도가 다른 영향을 명시한다.
- [x] 상위 4개·6개·8개 각각에서 정답 근거를 많이 찾은 순으로 비교표를 만들고 시간·비용을 함께 보여 준다. 후보 3개는 잠정안이며 고정 수·최대 수가 아니다. 실제 결과에 따라 후보 수와 구성을 크게 바꿀 수 있게 근거를 제시하고 사용자 검토를 받는다.

### 시간과 비용

- [x] 검색용 DB 생성과 새 질문 처리를 구분한다. 속도 측정은 질문 처리 시작부터 질문 임베딩·검색·BM25·RRF를 거쳐 검색 결과가 확정될 때까지 잰다. 단계별 시간과 전체 시간을 모두 기록한다.
- [x] 각 조건에서 질문 20개를 3회씩, 조건당 60회 측정한다. 이때는 저장한 질문 임베딩을 사용하지 않고 매번 새로 계산한다. 18개 조건의 질문 처리는 총 1,080회이며, 상위 4개·6개·8개를 확인하기 위해 같은 처리를 다시 세 번 실행하지 않는다.
- [x] 조건별 중앙값과 최대값, 질문별 측정 원본을 남긴다. 설명서 임베딩·DB 생성 시간과 최초 모델 로딩 시간은 따로 기록한다. 실제 토큰·요청 수·유료 비용과 로컬 계산을 구분해 남긴다.
- [x] 강의실 PC에서 같은 연습용 파일을 Blender에 열고, 조작·렌더링 없이 대기시킨 상태로 측정한다. 모든 조건에서 환경을 같게 하고 PC·파일·동시 실행 프로그램을 기록한다.

### 결과물과 검증

- [x] 같은 고정 자료와 기록한 설정으로 다시 실행할 수 있는 비교 프로그램과 사용 방법을 제공한다. 결과는 매번 새 폴더에 남기며 이전 결과를 덮어쓰지 않는다.
- [x] 자료 원문·번역·웹 질문 원문·검색 DB는 커밋하지 않는 자료 영역에 둔다. 실험 결과는 저장소 규칙의 `results/<날짜>_<이름>/`에 새로 남긴다. 키·토큰 등 비밀값은 출력하거나 결과에 넣지 않는다.
- [x] 자동 시험은 API 키·유료 호출 없이 작은 고정 자료와 가짜 임베딩으로 수행한다. 조건 누락, 중복 청크 처리, 대체·필수 근거의 일부·전체 적중, 상위 개수별 집계, 결과 재사용·재실행을 확인한다. 실제 유료 실험을 자동 시험에 넣지 않는다.
- [x] 구현으로 프로그램·파일·주고받는 모양이 바뀌면 구조 문서에 반영한다. 검토 결과와 후보 제안을 사용자가 판단할 수 있게 제시하고, 추가로 한 일은 티켓 Comments에 남긴다.

## 이번 티켓 밖

- 리랭커는 기본 후보를 정한 뒤 마지막에 별도로 시험한다. 모델·적용 범위는 그때 정한다.
- 전체 설명서에서 후보를 재확인하는 실험과 실제 답변 생성 비교는 이번 결과를 본 뒤 후속 범위를 정한다.
- 실제 도우미에 검색 모델을 연결하거나, 기존 본평가·홀드아웃을 실행하는 작업은 포함하지 않는다.
- 200청크의 결과를 전체 설명서의 최종 성능이나 최종 검색 방식의 확정으로 해석하지 않는다.
