# 25: 애드온 — 작업 상태 읽기와 보내기

Blocked by: 15
Status: ready-for-agent

근거: 명세 "애드온", "전체 구성", ADR-0001. 시제품 브랜치 `prototype/01-addon-roundtrip`은 참고만 하고 그대로 옮기지 않는다.

## 만들 것

Blender 5.2 애드온이 작업 상태 12칸을 읽어 도우미 창 프로그램(이 티켓에서는 창 없이 받는 쪽만)으로 보낸다.

## 완료 조건

- [ ] 작업 상태 12칸을 읽는다. 편집 모드 개수 읽기 시간을 잰다.
- [ ] F10에 보내고, 0.5초마다 읽어 바뀌었을 때만 보낸다. 자기 Blender 창 번호를 함께 보낸다.
- [ ] 받는 쪽은 창 번호마다 최신 상태 하나를 들고, 닫힌 Blender의 상태는 버린다.
- [ ] Blender를 켤 때 도우미 프로그램을 켜고(이미 켜져 있으면 그것을 씀), 마지막 Blender가 닫히면 끈다.
- [ ] glTF 내보내기를 "방금 실행한 조작"에 넣는다: 애드온 모듈에 `glTF2_post_export_callback`을 두고, 불리면 `export_scene.gltf`를 더한다. 사용자가 메뉴(File > Export > glTF 2.0)로 내보냈을 때 잡히는지 확인해 적는다. 안 잡히면 검 파일의 내보내기 끝난 조건을 뺀다.
- [ ] 상태 읽기는 Blender를 화면 없이 띄우는 자체 시험으로 확인한다(기본 테스트에는 넣지 않음).

## Comments

- 2026-10-20 Claude(티켓 17에서 넘김):
  - **모드**: Blender `context.mode` 값을 그대로 보낸다(편집 모드면 `EDIT_MESH`). 연습 과정 파일과 판정이 이 꼴을 쓴다. 사용자가 시제품(티켓 01)에서 직접 조작했을 때 이 값이 나왔다.
  - **방금 실행한 조작**: Blender 기록(`window_manager.operators`)에는 `OBJECT_OT_join` 꼴로 남는다. 연습 과정 파일·명세는 `object.join` 꼴이므로 보낼 때 바꾼다(`OBJECT_OT_join` → `object.join`). 이 기록에는 사람이 키보드·메뉴로 실행한 조작만 남고, 파이썬으로 부른 조작은 남지 않는다. 그래서 화면 없는 자체 시험으로는 확인할 수 없다.
  - **glTF 내보내기**: 기록에 잡히지 않는다(2026-10-20 사용자가 Blender 5.2.2에서 직접 확인했고, 조작에 `REGISTER` 표시도 없다). 검 과정의 내보내기 단계는 끝난 조건을 빼고 버튼으로만 마친다. 완료 조건의 "glTF 내보내기가 잡히는지 확인"은 이것으로 답이 났다.
  - **나중 선택지**: 기록에 이름만 3개 남아서, 뒤로 간 단계에 같은 조작이 남아 있으면 진행 관리가 곧바로 다시 묻는다. 조작마다 순번을 함께 보내면 "단계 시작 뒤 새로 한 조작"만 가려낼 수 있다(사용자는 지금은 그대로 두기로 함).
- 2026-10-20 Claude(티켓 17에서 넘김, 위 glTF 메모를 고침): 조작 기록에는 안 남지만 방법을 찾았다. glTF 내보내기 코드(`io_scene_gltf2/__init__.py`)는 켜진 애드온 모듈에 `glTF2_post_export_callback(export_settings)` 함수가 있으면 내보내기가 끝날 때 부른다(`export_settings["gltf_filepath"]`에 저장 경로). Blender 5.2.2를 화면 없이 띄워 확인함. 그래서 검 파일 내보내기 단계에 `방금 조작: export_scene.gltf`를 다시 넣었다. 공식 설명서에는 없는 glTF 내보내기 내부 장치라 다른 버전에서는 바뀔 수 있다. HISTORY [27]
- 2026-10-20 Claude(티켓 18에서 넘김): 진행 관리는 파일 열기·저장을 경로 변화가 아니라 **사건**으로 받는다(`ProgressManager.on_file_opened(path)`, `on_file_saved(path)`). 경로만 보면 "B를 열었다"와 "B로 다른 이름 저장했다"를 가를 수 없어서다. 애드온은 `bpy.app.handlers.load_post`·`save_post`로 알아채 어느 쪽인지 함께 보낸다(다른 이름으로 저장도 `save_post`). 사건 없이 경로만 바뀌면 진행 관리는 아무것도 하지 않는다. HISTORY [30]
