# 연습 과정 데이터 파일의 형식

Type: grilling
Status: resolved

## Question

연습 과정을 담는 데이터 파일은 어떤 형식인가? 구간·단계·조작을 어떻게 적고, 단계마다 무엇을 두는가(쉬운 설명, 먼저 볼 설명서 소제목, 끝난 조건, 목표 모양 설명과 참고 치수)? 검·방패 공통 1단계(공통 준비)는 어디에 두는가? 파일 하나를 더해 아이템을 늘릴 수 있어야 한다.

## 다른 티켓에서 넘어온 것

- (연습 과정 고르기) 구간 > 단계 > 조작, 진행·완료 판정은 단계 단위. 단계 = 눈으로 확인할 중간 결과 하나. 목표 모양은 말로, 치수는 참고로만. 시작은 기본 장면(정육면체가 칼날 시작), 1단계는 공통 준비
- (청크·검색 방식) 단계마다 연결한 설명서 소제목을 검색 "먼저 보기"에 쓴다
- (대화 기억 범위) 진행 기록은 연습 과정 이름·현재 단계·끝낸 단계 목록을 든다. 앞말 질문 검색에 현재 단계 이름과 연결 소제목을 붙인다
- (단계 완료 자동 판정) **끝난 조건**은 단계마다 있어도 없어도 되는 칸. 지금 단계 것만 보고, "방금 실행한 조작"과 묶고, 치수는 비율로만 적는다. 작업 상태에 재질 슬롯 수가 더해진다
- (확장 원칙, 지도 Notes) 코드가 아니라 데이터 파일로, 아이템을 바꾸거나 늘릴 때 파일만 더한다. 최종 목표(범위 밖)는 같은 형식을 AI가 만들어 내는 것이라 사람이 읽고 AI가 쓰기 쉬워야 한다

## Answer

2026-10-19 사용자와 질문 라운드(Q1-Q9, 세 번)로 정함. 근거: 강좌 대조 조사(`research/03-course`)의 검 9단계 초안, 이 지도의 앞선 티켓 답들. 이 PC에는 YAML 읽기 부품(PyYAML)이 없어 설치가 하나 늘어난다.

| 항목 | 결정 |
|---|---|
| 형식 | **YAML 한 벌**. 도우미 창을 켤 때 한 번 읽어 메모리에 둔다(읽는 시간 수 밀리초, 답 시간에 안 들어감). JSON으로 바꾼 두 번째 벌은 두지 않는다(어느 쪽이 진짜인지 갈림). 답변 모델에는 파일이 아니라 지금 단계 내용만 뽑아 넘긴다 |
| 파일 | 연습 과정 하나에 파일 하나: `courses/sword.yaml`, `courses/shield.yaml`. 공통 준비(화면 돌리기·확대·이동, 화면 언어 확인)는 `courses/_common.yaml` 하나에 두고 각 파일이 "먼저 할 것"으로 가리킨다 |
| 맨 위 칸 | 이름표(`sword`), 이름, 한 줄 설명, 난이도, 마지막 결과(glTF 파일), 비슷한 아이템 말 목록 |
| 구간 | 이름 + 단계 목록만 |
| 단계 칸 | 이름표(꼭), 이름(꼭), 목표 모양(꼭, 말로), 참고 치수(선택, 비율 위주 문장), 쉬운 설명(꼭, 2-3문장), 조작 목록(꼭: 한 줄 설명 + 메뉴 경로 **영어** + 단축키), 먼저 볼 설명서 소제목(꼭, 1-3개, `경로.html#앵커`), 끝난 조건(선택), 자주 막히는 곳(선택, 검수 때 더함). 구간·조작에는 이름표 없음 |
| 단계 이름표 | 바뀌지 않는 영어 소문자(`blade-tip`). 진행 기록은 순서 번호가 아니라 이름표로 적는다. 화면의 "n단계"는 파일 순서로 센다. 기록의 이름표가 파일에서 사라지면 끝내지 않은 첫 단계로 가고 한 줄 알린다 |
| 끝난 조건 | 정해 둔 검사 종류만, 여러 개면 **모두 맞아야** 맞음. 종류: 모드, 방금 조작(최근 3개 안, Blender 조작 이름 그대로 예 `object.join`), 장면 물체 수(**단계 시작 때보다** 늘어남. 도우미 창이 단계 시작 때 수를 기억), 모디파이어 있음, 재질 슬롯 수, 배율, 크기 비율(가장 긴 축 ≥ 두 번째 축 × n). 새 종류가 필요하면 코드에 하나 더하고 그때까지 그 단계는 버튼만 |
| 칸 이름 | 한국어(`목표 모양`, `끝난 조건`…). 이름표·Blender 조작 이름·메뉴 경로는 영어 |
| 비슷한 연습 과정 권하기 | 연습 과정마다 "이름 + 한 줄 설명 + 비슷한 말"을 미리 임베딩해 둔다. **연습 과정을 진행하지 않을 때만**, 설명서 검색에 쓰는 질문 임베딩을 그대로 다시 써서 가까운 상위 3개를 답변 모델에 붙인다. 추가 호출 없음(호출 2번 유지), 연습 과정이 늘어도 넘기는 양이 같음. MVP(2개)도 같은 길로 만든다. 딱 맞는 게 없으면 답변 모델이 "가장 가까운 건 …"이라고 말하게 한다 |
| 검사 테스트 | API 키·Blender 없이: 꼭 있어야 하는 칸, 모르는 칸 이름, 이름표 겹침, 끝난 조건 종류, 공통 파일 가리키기, YAML 함정(따옴표 없는 `no` 등). `data/`가 있을 때만: 설명서 소제목 주소가 실제로 있음, 메뉴 경로가 번역 사전에 있음, 설명서와 긴 문장이 똑같이 겹치지 않음. 통과하면 쓸 수 있는 파일로 본다(나중에 AI가 만든 파일도 같은 기준) |
| 공개 | `courses/`는 커밋한다. 글은 우리 말로 새로 쓰고 설명서 문장은 옮기지 않고 소제목 주소로만 가리킨다(CC BY-SA 조건이 파일에 붙지 않게) |

ADR은 만들지 않음: 형식·칸은 파일 몇 개라 나중에 바꾸기 쉽다. 용어집에 「공통 준비」를 더하고 「연습 과정」 정의를 아이템마다 하나로 고침.
