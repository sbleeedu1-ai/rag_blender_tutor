# 청크·검색 방식

Type: grilling
Status: resolved
Blocked by: 02, 04, 05, 12

## Question

설명서 전체 원문과 연습 과정 + 초보자 범위(번역·쉬운 말 풀이)를 청크에 어떻게 담고, 무엇으로 검색하며, 일부를 어떻게 먼저 보는가? 초보자 범위는 어떤 기준으로 고르고(AI 분류의 근거), 초반 검수는 어떻게 하는가?

## 조사에서 넘어온 것

- 공식 한국어 번역이 사실상 없음 → 한국어 질문을 영어 원문과 맞추는 방법을 먼저 정한다(다국어 임베딩, 질문을 영어로 바꿔 검색, 일부만 한국어 번역 청크)
- 임베딩 후보: text-embedding-3-large / bge-m3(내 PC에서 실행, 쓸지 결정 필요)
- 청크는 소제목 단위 + `/en/5.2/...#앵커` 링크가 유력(쪽 길이 중간값 204단어, 최대 6,568단어)
- 설명서 기여자용 contribute 분야 26쪽을 검색에서 뺄지
- 공식 초보자 범위가 없으므로 초보자 분류 기준을 새로 정해야 함
- 강의실 PC(i7-4770, GTX 950 2GB, 16GB)는 Blender 5.x 최소 사양선. bge-m3를 이 PC에서 돌리면 GPU 메모리가 부족해 CPU로 돌아가므로, 전체 임베딩과 질문당 시간 부담을 함께 따진다(2026-10-19 사용자 사양 확인)
- (화면 한국어 번역 조사) 한국어 화면 사용자는 질문에 한국어 메뉴 이름("배열", "베벨")을 쓴다. 화면 번역 사전(ko.po)으로 영어 메뉴 이름으로 거꾸로 바꿔 검색에 쓸 수 있다. 같은 한국어가 여러 영어에 대응하는 경우가 있다

## Answer

2026-10-19 사용자와 질문 라운드로 정함. 근거: 공식 HTML 묶음(`data/manual_en_5.2/`, 커밋 안 함)을 직접 잘라 본 결과. 쓴 스크립트는 일회용이라 저장소에 넣지 않았다(소제목 단위 자르기, 크기 세기, 제목만 있는 소제목 분류).

**설명서 전체를 소제목 단위로 센 결과**(contribute 제외): 소제목 9,537개, 약 73만 단어. 0단어 432개(5%), 1-49단어 4,536개(48%), 50-400단어 4,425개(46%), 401단어 이상 144개(2%). 청크는 약 9,100개가 된다.

| 항목 | 결정 |
|---|---|
| 한국어 질문 ↔ 영어 원문 | (가) 다국어 임베딩 + (다) 초보자 범위 청크에 한국어 번역 + (라) 화면 번역 사전(ko.po)으로 질문 속 한국어 메뉴 이름을 영어로 바꿔 덧붙임(여러 개면 모두). 질문을 AI로 영어로 바꾸는 방법은 시간이 늘어 뺌 |
| 임베딩 | text-embedding-3-large 기본, bge-m3는 선택지(평가에서 한국어 질문 검색이 눈에 띄게 낮을 때만) |
| 검색 | 임베딩 + BM25를 RRF로 합친 상위 6-8개를 바로 답변 모델에. **리랭커 없음**(이전 프로젝트에서 6-13.5초. 이번엔 속도가 핵심 근거). 정확도가 모자라면 켜는 선택지로 두고 켰을 때 시간을 함께 잰다 |
| 청크 단위 | 소제목 하나 = 청크 하나, 근거 링크 `/en/5.2/<경로>.html#<앵커>` |
| 위계 메타데이터 | 분야 > 묶음(폴더 경로) > 쪽 > 소제목(여러 겹) > 옵션(정의 목록). 청크 글 앞에 "쪽 제목 > 소제목" 경로를 붙인다 |
| 짧은 소제목 | 합치지 않는다. **작게 찾고 크게 읽기**: 찾은 청크가 50단어 미만이면 같은 부모 아래 형제 소제목을 약 400단어까지 함께 답변 모델에 넘긴다. 링크는 찾은 소제목 그대로 |
| 긴 소제목(400단어 넘음) | 옵션 묶음 경계에서 나눈다(예: Bevel Options 937단어). 나눈 청크도 같은 경로·앵커. 옵션이 없으면 문단 끝 |
| 제목만 있는 소제목 432개 | 아래 소제목만 묶는 377개는 경로에만 남김, 목차만 있는 6개는 버림. 영상만 40개·그림만 9개는 청크로 만들지 않고 "그림이 중요한 설명의 처리" 티켓으로 |
| "모드·메뉴·단축키" 상자 | 쪽 첫 청크 본문에 두고 메타데이터로도 따로 저장 |
| 검색 제외 | 기여자용 contribute 26쪽 |
| 초보자 범위 청크에 담을 것 | 영어 원문(모든 청크) + 한국어 번역 + 쉬운 말 풀이. 범위 표시는 메타데이터(`연습 과정`/`초보자`/`일반`). 임베딩에는 원문 + 번역, 풀이는 답변 모델에게만 |
| 번역 속 화면 이름 | "한국어(영어)"로 함께 쓴다. 한국어는 AI가 짓지 않고 **ko.po에서 가져온다**. 번역 뒤 짝이 사전과 맞는지 코드로 확인. 사전에 번역이 없으면 영어만. 화면 이름은 HTML의 메뉴 경로 표시(1,831곳)·버튼 이름 표시(709곳)·옵션 이름(정의 목록, 뒤에 붙은 단축키 글자는 뗌)에서 코드로 뽑는다 |
| 번역 범위 | 초보자 범위만. 한국어 답에는 미리 번역이 필요 없다(답변 모델이 영어 원문을 읽고 한국어로 답함). 개발용 평가에 **초보자 범위 밖 한국어 질문**을 넣어 검색 적중이 낮으면 나머지를 "검색용 기계 번역"(근거로 보여 주지 않음)으로 더한다 |
| 먼저 보기 | 현재 단계에 연결된 설명서 소제목(연습 과정 데이터 파일에 적음)을 검색 상위 위에 **덧붙인다**(최대 2-3개, 대신하지 않음). 초보자 범위 순위 올리기는 **하지 않는다**((가)). 평가 뒤 "진행 중이고 현재 단계와 관련 있을 때만 올리기"((나))를 검토 |
| 초보자 범위 기준 | 단위는 쪽. 연습 과정 단계가 가리키는 쪽 + 시작하기 16쪽은 바로 넣고, 나머지는 AI가 "처음 쓰는 사람이 간단한 아이템 하나를 만들고 내보내며 마주칠 가능성"으로 판단, 쪽마다 이유 한 줄. 약 300쪽 안 |
| 분류 방법·검수 | 경계 쪽을 섞은 **50쪽 시험**: Claude(대화 세션, 비용 없음)가 기준 판단 → luna(API)가 같은 50쪽 분류 → 다른 쪽은 이유와 함께 사용자가 봄. 거의 같으면 전체 약 2,000쪽 라벨링을 luna로(추정 $1 미만), 많이 다르면 그때 모델을 다시 정함. 연습 과정을 따라 하다 빠진 쪽이 나오면 더함. 실행은 구현 단계, 비용은 실행 전에 확인 |
| 번역 검수 | "한국어(영어)" 짝이 ko.po와 맞는지 코드로 자동 확인 + 무작위 약 20개를 사용자가 읽음 |
| ko.po | 명세 단계에서 Blender 저장소 `locale/po/ko.po`를 `data/`에 받는다(GPL, 커밋 안 함). 애드온은 파일 대신 `pgettext_iface`를 쓴다 |

비용 추정(가격표 계산, 실측 아님): 50쪽 시험 몇 센트, 전체 분류(luna) $1 미만, 초보자 범위 번역 $1 안팎, 전체 임베딩 $1 미만. OpenAI 잔액 약 $2.8 안. 시험 결과가 좋으면 Anthropic 쪽 $5 충전도 생각하기로 함(사용자).
