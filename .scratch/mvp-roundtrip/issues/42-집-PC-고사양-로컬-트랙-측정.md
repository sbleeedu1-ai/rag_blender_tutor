# 42: 고사양 PC용 로컬 트랙이 쓸 만한지 판단하기 위해, 집 PC에서 8-14B 생성 모델의 질문 바꾸기 속도와 기능 이름 품질을 잰다

Status: ready-for-agent

근거: HISTORY [122]·[123]. 사용자 "투트랙으로 할까 했었지 저사양/고사양 그래서 그 모델도 쪼금 더 키운버전을 쓸수도 있을거고", "집 PC 는 계획만 남겨두고", "지금 우리는 API 로 가자고".

## 배경

- 강의실 PC(i7-4770, GPU 없음)에서 0.8B·2B·Gemma 4 E2B는 luna보다 느리고(2-15초), W1·W2·W10에서 질문에 없는 기능 이름(Set Origin·Join·Active Image Texture)을 하나도 떠올리지 못했다([122]).
- 집 PC: Ryzen 7 7800X3D, DDR5-4800 32GB, RTX 5080 16GB. GPU 메모리 속도가 강의실 PC의 약 40배라, 8-14B Q4 모델이 질문 바꾸기 한 번에 0.3-1초일 것으로 어림했다(측정 안 함). 남는 문제는 품질이다.
- 지금 운영 방향은 API 트랙(luna 질문 바꾸기 3번 동시 → 먼저 온 1개 + large + BM25 끔 + 상위 8개, [127])이다. 이 티켓은 그 결정을 바꾸지 않고, 고사양 트랙을 붙일 근거만 모은다.

## 할 일

1. `prototype/local_llm/llm_bench.sh`로 llama.cpp CUDA판과 후보 모델을 받아 속도를 잰다. `ASSET`을 CUDA 배포 파일 이름으로, 모델 목록을 8-14B 후보로 바꾼다. 후보는 그때의 최신 공식 모델 카드를 확인해 고른다(라이선스: 공개 배포 가능한 것).
2. `prototype/local_llm/local_rewrite.py`로 W1·W2·W10 초벌 품질을 본다(luna와 같은 지시). 질문에 없는 기능 이름을 떠올리는지가 기준이다.
3. 초벌에서 기능 이름을 떠올리는 모델이 있으면, 20문항 × 3회로 `search_compare`의 검색어 파일을 만들어 large 검색 적중률을 luna([117]·[121]·[122])와 견준다.
4. 결과는 `results/<날짜>/<시각>_<이름>/`, 판단은 HISTORY에 남긴다.
