# 26: 도우미 창 왕복

Blocked by: 21, 25
Status: ready-for-human

근거: 명세 "도우미 창", ADR-0001, User Stories 3-12·18-21·31, 조사 `archive/research/도우미-창-UI-도구-조사.md`, HISTORY [17]·[18], 화면 시제품 브랜치 `prototype/02-helper-window-ui`(위젯 판이 출발점, 그대로 옮기지 않고 새로 짠다)

## 만들 것

F10으로 도우미 창이 앞으로 나와 한글로 질문하고, 답 엔진의 답이 흘러나오듯 보인다.

## 완료 조건

- [x] ADR-0001 창 동작: 작게·정해진 자리, Esc로 그 Blender 복귀, Blender가 앞일 때만 맨 위, 최소화 연동, 직접 내리면 F10까지 내린 채, 줄여도 입력칸과 최근 답 일부 보임.
- [x] Enter 한 번에 보내고, 답은 스트리밍, 근거는 끝에 한꺼번에, 근거 링크를 누르면 설명서가 열린다.
- [x] 질문은 마지막으로 앞에 있던 Blender의 상태로 보낸다. 최근 대화 3쌍을 들고 창이 꺼지면 사라진다.
- [x] 답을 기다리는 동안 Blender가 멈추지 않는다. 오류·시간 초과는 짧은 문구.
- [ ] 사용자가 강의실 PC에서 한글 입력·F10 → 입력 가능 시간·창 동작을 눈으로 확인한다.
- [x] 화면 도구는 PySide6 위젯(파이썬만, QML 쓰지 않음). 그래픽 카드를 Blender와 나눠 쓰지 않게 한다.
- [x] 모양: 테두리·제목 표시줄 없음, 어두운 반투명 판(진하기 약 235/255, 진짜 흐림은 끌 수 있는 선택 기능), 둥근 모서리, 답은 크고 굵은 흰 글씨·질문은 작은 회색, 근거는 반투명 둥근 카드, 아래 알약 모양 입력칸. 답은 문장 끝(`.` `!` `?` 뒤 빈칸)마다 줄을 바꾼다(5.2 같은 숫자는 그대로). Apple·Siri 이름·로고는 쓰지 않는다.
- [x] 버튼은 오른쪽 위 `X`(숨기기) 하나, 마우스를 올렸을 때 보인다. 가장자리를 끌어 크기를 바꿀 수 있다.
- [x] 작업 표시줄과 Alt+Tab에 나오지 않고 트레이 아이콘만 둔다. 왼쪽 클릭 = 보이기(숨기지 않음), 오른쪽 메뉴 = 보이기 / 끝내기. 끝낸 뒤 F10을 누르면 애드온이 다시 켠다.
- [x] 보이지 않는 Blender만 있으면(모두 최소화) 트레이 보이기를 막고, 아이콘 안내에 "Blender를 먼저 열어 주세요". Blender가 하나라도 보이면 F10과 똑같이 부른다(그 뒤 다른 프로그램을 누르면 ADR-0001대로 그 뒤로).
- [x] 앞 프로그램이 작업 표시줄·트레이일 때는 창을 그대로 둔다(트레이 클릭 때 깜빡임 방지).
- [x] 설치 안내에 "트레이 아이콘을 ^ 밖으로 꺼내 두세요" 한 줄(프로그램이 바꿀 수 없음).

## Comments

- 2026-10-21 Claude(티켓 21에서): **답 엔진이 잡지 않는 오류는 창이 받는다.** 답 엔진은 바깥 서비스(임베딩·답변 모델) 오류만 "잠시 뒤 다시 물어봐 주세요"로 바꾸고, 우리 코드의 버그는 그대로 올려 보낸다(평가 중 버그가 "오류" 문항으로 숨지 않게). 창은 맨 바깥에서 한 번 받아 꺼지지 않고 "도우미 프로그램에 문제가 생겼어요"를 보여 주며, 오류 내용은 기록 파일에 남긴다
- 2026-10-22 Claude(티켓 25에서 넘김): 창은 `blender_tutor/receiver.py`의 `Receiver(token, listener)`를 띄우고 `run_until_no_blender()`가 돌아오면 끝난다(마지막 Blender가 닫힘). 비밀 글자는 애드온이 켤 때 환경 변수 `BLENDER_TUTOR_TOKEN`으로 넘긴다. `listener`는 받는 쪽 스레드에서 봉투마다 불리고 봉투를 하나씩 여므로, 화면 일·답 만들기는 창 쪽으로 넘기고 바로 돌아와야 한다(아니면 다른 Blender 봉투가 막힘). `Message.summon`이 F10, `Message.window`가 Esc로 돌아갈 창 번호. 창 번호별 최신 상태는 `Receiver.latest(창 번호)`. 지금 `receiver.main()`은 창 없이 기록만 남기므로 창 프로그램 입구로 바꾼다(애드온 `config.json`의 명령이 `-m blender_tutor.receiver`이니 함께 바꾸고 설치 명령을 다시 돌림). "끝낸 뒤 F10을 누르면 애드온이 다시 켠다"는 애드온에 이미 있다
- 2026-10-22 Claude(티켓 25 뒤, 사용자와 구조를 보다 찾음): **청크 파일을 읽어 `Chunk`로 되돌리는 코드가 아직 없다.** `manual_chunks.main`은 `data/chunks/manual_chunks.jsonl`에 `asdict(chunk)`에 `url`·`text`(사람이 보기 편하라고 계산해 적은 값)를 더해 한 줄씩 쓰기만 하고, 지금까지는 테스트가 `Chunk`를 직접 만들어 답 엔진에 넣었다. 창이 답 엔진을 만들 때 이 파일을 읽어야 하므로 읽기 함수를 `manual_chunks.py`에 둔다(`url`·`text`는 버리고, 리스트 칸은 튜플로, `reference`는 짝의 튜플로, `examples`는 `Example`로). 쓰고 읽어 같은 `Chunk`가 나오는지 테스트한다

- 2026-10-22 Claude(구현, HISTORY [45]):
  - **진짜 모델 대신 무료 임시 엔진**(사용자 결정): `blender_tutor/stand_in.py`. 실제 `data/` 청크 + 실제 검색 코드에, 낱말 세기 임베딩과 정해 둔 글을 흘리는 가짜 답변 모델(첫 글자 전 1.5초 쉼)을 끼운다. 창 동작을 보는 용도이고 답·검색의 질은 의미 없다(한국어 질문은 영어 설명서와 낱말이 거의 안 겹쳐 근거가 자주 빗나감). 티켓 31·33에서 `build_engine`의 임베딩·모델만 진짜로 갈아 끼운다
  - 실제 실행: 도우미가 켜져 대답까지 1.2초, 엔진 준비 1.5초(청크 8,997개 읽기 0.45초 포함). 엔진은 창을 띄운 뒤 뒤에서 만들고, 그 전에 물으면 "설명서를 읽는 중" 문구
  - 기본 테스트 266개 통과, 애드온 자체 시험 전체 통과(새 도우미가 Blender와 함께 켜지고 꺼짐). 설치 명령을 다시 돌려 `config.json` 명령이 `-m blender_tutor.helper`가 됨
  - 남은 완료 조건: **사용자 눈 확인**(강의실 PC에서 한글 입력·F10 → 입력 가능 시간·창 동작). 확인할 것은 HANDOFF "다음 할 일"
  - 정한 것(사용자에게 알리고 진행): Esc는 창을 숨기지 않고 마지막 앞 Blender로 초점만 돌린다(Blender가 앞이 되니 창은 그 위에 남음). 창은 처음부터 보이되 초점은 빼앗지 않는다. 진짜 흐림은 켜는 명령 끝에 `--blur`
  - 코드 검토(표준·명세 두 갈래)에서 고친 것: 작업 표시줄 단추로 Blender를 최소화하면 앞 창이 작업 표시줄로 남아 창이 숨지 않던 것(최소화를 먼저 봄), 앞 창 없음(0)일 때 '그 뒤로'가 맨 앞으로 올리던 것, 번호 목록 "1. "에서 줄이 바뀌던 것, 이름(`show_answer_event`), 트레이 묶음
  - 완료 조건 밖에 더한 것:
    - 맨 위 띠를 끌어 창 옮기기: 시제품 위젯 판에 있었고 사용자가 써 봄. F10을 눌러도 처음 자리로 되돌리지 않는다("정해진 자리"는 처음 뜨는 자리로 읽음)
    - 답을 기다리는 동안 Enter를 막음(쓴 글은 지우지 않음): 답 두 개가 섞여 그려지지 않게
    - X가 서서히 나타나는 효과, 질문·답 글자 선택: 시제품 위젯 판 그대로
    - 질문·답은 서식 없는 글로 보임: 질문에 `<b>` 같은 글을 써도 그대로 보이게
    - `--blur`일 때 판 진하기 170(기본 235): 235면 흐림이 거의 안 보여서
    - 문구 "Blender 작업 상태를 아직 받지 못했어요", "설명서 자료(data/)가 없어…": 그 경우 창이 아무 말 없이 멈추지 않게
    - 기록 파일에 "F10 받음 → 입력 가능 ms", 파일 열기·저장 사건 한 줄: 눈 확인 때 숫자를 보려고(전체 시간 기록은 티켓 28)
    - 설치 명령이 끝날 때 트레이 안내 줄(완료 조건의 "설치 안내"를 README가 없어 여기에)
    - `manual_chunks.save_chunks`·`load_chunks`(Comments 요청), `Receiver.blenders()`(앞 프로그램이 Blender인지 가르려고)
    - 받는 쪽 혼자 실행 입구(`receiver.main`)를 지우고 `helper.main`으로 옮김(Comments 요청), `--port`는 그대로
  - 그대로 둔 알려진 한계:
    - 트레이 보이기를 막는 기준은 작업 상태를 보낸 Blender뿐이다(애드온이 켜진 Blender는 0.5초 안에 보냄)
    - 자체 시험이 진짜 도우미를 켜므로 시험 중 트레이 아이콘이 잠깐 보인다(화면 없는 Blender라 창은 숨은 채)
    - 진짜 흐림은 문서 없는 Windows 함수라 업데이트로 깨질 수 있다. 실패하면 기록에 한 줄 남기고 판만 보인다
    - 창이 주 화면 오른쪽 아래에만 뜬다(Blender가 다른 화면에 있어도)
