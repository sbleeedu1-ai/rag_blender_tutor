# 명세: 왕복 MVP와 GPT 비교 평가

Status: ready-for-agent

근거: 지도 `.scratch/mvp-roundtrip/map.md`와 닫힌 티켓 01-14(각 티켓의 `## Answer`), `docs/adr/0001-채팅은-Blender-위-도우미-창으로.md`, 용어집 `CONTEXT.md`. 여기 적힌 결정은 모두 그 티켓에서 사용자가 고른 것이다. 이 명세에서 새로 정한 것은 "시험 경계" 하나뿐이다(아래 Testing Decisions).

## Problem Statement

Blender를 처음 쓰는 사람이 검이나 방패 같은 3D 아이템을 직접 만들다가 막히면, 지금은 화면 스크린샷을 찍어 GPT에 붙이고 답을 기다려야 한다. 이 방법은 느리다(스크린샷 찍기, 창 옮기기, 붙여 넣기, 긴 답 기다리기). 게다가 일반 GPT는 지금 사용자가 어느 모드에서 무엇을 골랐는지, 연습 과정의 몇 단계에 있는지 모르고, Blender 5.2 설명서와 다른 옛 버전(4.5 강좌 등) 내용을 섞어 답하기 쉽다. 설명서는 사실상 영어뿐이고(공식 한국어 번역 1.1%), 화면을 한국어로 쓰는 초보자는 메뉴 이름부터 설명서와 맞지 않는다. Blender 안 글자 칸에는 Windows 기본 한국어 입력기로 한글이 제대로 들어가지 않는다.

강사님은 "초보자 대상이면 GPT가 더 잘하는 것 아닌가?"라고 물었다. 이 질문에 숫자로 답해야 한다: 같은 질문을 했을 때 우리 서비스가 GPT(스크린샷 방식)보다 **얼마나 빠르고, 덜 틀리는지**.

## Solution

세 부분이 "질문 + 작업 상태 → 답 + 근거"로 주고받는 왕복 MVP를 만들고, 같은 평가 문항으로 GPT 빈손과 비교해 정확도와 걸린 시간을 잰다.

- **애드온(Blender 5.2 안)**: F10을 누르면 작업 상태를 읽어 보내고 도우미 창을 앞으로 부른다. 상태가 바뀔 때마다 자동으로 다시 보낸다. 검색·답 생성은 하지 않는다.
- **도우미 창(Blender 위에 떠 있는 작은 창, 답 엔진과 한 프로그램)**: 사용자가 한글로 질문을 쓰고 Enter 한 번에 보내면, 답이 글자가 나오는 대로 보이고 끝에 근거(설명서 소제목 경로와 링크, "그림 있음"/"영상 있음")가 붙는다. 연습 과정(검, 방패)을 단계별로 안내하고, 단계의 끝난 조건이 맞으면 "다음 단계로 갈까요?"라고 묻는다. 파일마다 진행 기록을 남겨 다시 열면 이어 할 수 있다.
- **답 엔진**: Blender 5.2 설명서 전체(개발자용 Python API·기여자용 쪽 제외)에서 검색하고, 질문당 호출 2번(임베딩 1 + 답 1)으로 쉬운 한국어 답을 만든다. 한국어 화면이면 메뉴 이름을 화면에 보이는 한국어로 먼저 쓰고 영어를 괄호로 붙인다.
- **평가**: 개발 30문항·홀드아웃 10문항을 GPT 빈손 / 고치기 전 / 고친 후(개발) / 고친 후(홀드아웃) 네 칸으로 재고, 일부 문항은 질문 준비 시간과 보낸 뒤 시간을 나눠 잰다. 결과는 `docs/experiment.md`와 `results/<날짜>_<이름>/`에 남긴다.

## User Stories

### 시작과 도우미 창

1. 초보자로서, 애드온을 한 번 설치한 뒤 평소처럼 Blender만 열고 싶다, 그래야 도우미 창이나 서버를 따로 켜는 법을 몰라도 된다.
2. 초보자로서, Blender를 닫으면 도우미 창과 서버도 함께 꺼지길 원한다, 그래야 보이지 않는 프로그램이 남지 않는다.
3. 초보자로서, F10 한 번으로 도우미 창이 앞으로 나와 바로 한글을 쓸 수 있길 원한다, 그래야 스크린샷 없이 곧장 물어볼 수 있다.
4. 초보자로서, Windows 입력기 설정을 바꾸지 않고도 한글이 제대로 들어가길 원한다, 그래야 설치 안내가 짧다.
5. 초보자로서, 질문을 쓰고 Enter 한 번에 보내고 싶다, 그래야 다른 채팅 프로그램처럼 자연스럽다.
6. 초보자로서, Esc를 누르면 바로 Blender로 돌아가 조작을 이어 가고 싶다, 그래야 마우스로 창을 옮겨 누를 필요가 없다.
7. 초보자로서, 도우미 창이 작고 늘 같은 자리에 뜨길 원한다, 그래야 작업 화면을 가리지 않고 어디 있는지 안다.
8. 초보자로서, 창 크기를 줄여도 입력칸과 최근 답 일부는 늘 보이길 원한다, 그래야 작게 두고도 쓸 수 있다.
9. 초보자로서, Blender가 앞에 있을 때만 도우미 창이 맨 위에 있고 다른 프로그램을 열면 그 뒤로 가길 원한다, 그래야 다른 일을 방해하지 않는다.
10. 초보자로서, Blender를 최소화하면 도우미 창도 숨고 다시 열면 함께 나오길 원한다.
11. 초보자로서, 도우미 창만 따로 내리면 F10으로 다시 부를 때까지 내린 채로 있길 원한다, 그래야 잠깐 치워 둘 수 있다.
12. 초보자로서, 답을 기다리는 동안에도 Blender 화면을 돌리고 물체를 고를 수 있길 원한다, 그래야 멈춘 것처럼 느끼지 않는다.

### 작업 상태

13. 초보자로서, 지금 모드·고른 물체·방금 한 조작을 내가 설명하지 않아도 도우미가 알길 원한다, 그래야 질문을 짧게 쓸 수 있다.
14. 초보자로서, F10을 누르지 않고 도우미 창을 마우스로 눌러 질문해도 최신 작업 상태로 답받길 원한다.
15. 초보자로서, Blender를 두 개 열어도 도우미 창 하나가 마지막으로 앞에 있던 Blender의 상태로 답하고 Esc도 그 Blender로 돌아가길 원한다.
16. 초보자로서, 화면을 한국어로 쓰고 있다는 것과 인터페이스 번역이 켜져 있는지를 도우미가 알길 원한다, 그래야 내 화면에 보이는 메뉴 이름으로 안내받는다.
17. 초보자로서, 물체 이름이 한국어("실린더")로 바뀌어 있어도 도우미가 헷갈리지 않길 원한다.

### 질문과 답

18. 초보자로서, 답이 다 만들어질 때까지 기다리지 않고 글자가 나오는 대로 읽고 싶다, 그래야 덜 느리게 느껴진다.
19. 초보자로서, 답 끝에 근거가 된 설명서 소제목 경로와 그 위치로 가는 링크를 보고 싶다, 그래야 답을 믿을 수 있고 더 읽을 수 있다.
20. 초보자로서, 근거 옆에 "그림 있음"·"영상 있음"이 표시되길 원한다, 그래야 그림을 봐야 할 때 링크를 열면 된다는 걸 안다.
21. 초보자로서, 근거 링크를 누르면 설명서 웹사이트의 그 소제목이 열리길 원한다.
22. 한국어 화면 초보자로서, 메뉴 이름을 "추가(Add) > 메시(Mesh)"처럼 내 화면 이름 먼저, 영어는 괄호로 보고 싶다, 그래야 화면에서 바로 찾고 영어 자료와도 맞출 수 있다.
23. 영어 화면 초보자로서, 메뉴 이름을 영어 그대로 보고 싶다.
24. 한국어 화면 초보자로서, 번역이 없는 메뉴(예: At Center)는 영어 그대로 보이길 원한다, 그래야 화면과 다르지 않다.
25. 한국어 화면 초보자로서, 질문에 "배열", "베벨"처럼 한국어 메뉴 이름을 써도 영어 설명서에서 맞는 곳을 찾아 주길 원한다.
26. 초보자로서, 설명서에 없는 것(게임 엔진에 넣기, 다른 프로그램 사용법 등)을 물으면 지어내지 않고 "설명서에 없다"고 말한 뒤 가까운 쪽을 권해 주길 원한다.
27. 초보자로서, 4.5 강좌와 5.2가 달라 메뉴가 안 보일 때(배열 vs 배열(레거시) 등) 5.2 기준으로 바로잡아 주길 원한다.
28. 초보자로서, "그거 어떻게 해요?"처럼 앞말을 가리키는 질문도 알아듣길 원한다, 그래야 같은 말을 되풀이하지 않는다.
29. 초보자로서, 도우미 창을 끄면 최근 대화가 사라지길 원한다(진행 기록은 남음).
30. 초보자로서, 그림 내용을 지어내지 않고 그림이 중요하면 "설명서 그림을 함께 보세요"라고 알려 주길 원한다.
31. 초보자로서, 서버 오류나 시간 초과가 나면 짧은 오류 문구를 보고 싶다, 그래야 창이 멈췄는지 기다려야 하는지 안다.
32. 초보자로서, 연습 과정 밖의 자유 질문도 설명서 전체로 답받고 다시 현재 단계로 돌아오고 싶다.
33. 초보자로서, 답이 쉬운 한국어이고 처음 나오는 용어는 풀어 주길 원한다.

### 연습 과정

34. 초보자로서, 만들고 싶은 아이템(검, 방패)을 골라 단계별로 따라 하고 싶다.
35. 초보자로서, 원하는 아이템이 없으면 가장 비슷한 연습 과정을 권해 주길 원하고, 원하면 연습 과정 없이 자유 질문으로 계속하고 싶다.
36. 초보자로서, 모든 연습 과정의 맨 앞에서 화면 돌리기·확대·이동과 화면 언어 확인(공통 준비)을 먼저 하고 싶다.
37. 초보자로서, 각 단계에서 목표 모양(말로), 쉬운 설명 2-3문장, 해야 할 조작 목록(메뉴 경로·단축키)을 보고 싶다.
38. 초보자로서, 치수는 참고로만 보고 비율이 대충 맞으면 넘어가고 싶다, 그래야 숫자에 얽매이지 않는다.
39. 초보자로서, 단계를 끝내면 도우미 창이 "…한 것 같아요. 다음 단계(…)로 갈까요? [네] [아니요]"라고 묻고 "네"를 눌러야 넘어가길 원한다, 그래야 잘못 알아채도 내가 막을 수 있다.
40. 초보자로서, 그 물음이 도우미 창 안에만 뜨고 창을 앞으로 끌어오지 않길 원한다, 그래야 조작이 끊기지 않는다.
41. 초보자로서, 대답하기 전에 Ctrl+Z 등으로 조건이 깨지면 물음이 사라지길 원한다.
42. 초보자로서, 한 단계에서 한 번 거절하면 그 단계에서는 다시 묻지 않길 원한다.
43. 초보자로서, "다음 단계" 버튼을 언제나 누를 수 있길 원한다, 그래야 알아채지 못하는 단계도 넘어갈 수 있다.
44. 초보자로서, 원하는 단계로 건너뛰거나 뒤로 갈 수 있길 원한다.
45. 초보자로서, 마지막에 glTF 파일로 내보내면 연습 과정이 끝나길 원한다.
46. 초보자로서, 저장한 파일을 다시 열면 "지난번 n단계(이름)까지 했어요. 이어 할까요?"를 한 번 묻길 원한다.
47. 초보자로서, 거절해도 진행 기록은 지워지지 않길 원한다.
48. 초보자로서, 저장하기 전에 한 진행도 처음 저장할 때 그 파일에 붙고, 다른 이름으로 저장하면 새 파일로 따라가길 원한다.
49. 초보자로서, 같은 파일에서 다른 연습 과정으로 바꿀 때 "이 파일의 진행 기록(검, 4단계)이 방패로 바뀌어요. 새 파일에서 시작하면 둘 다 남아요" 확인을 보고 싶다.
50. 초보자로서, 연습 과정이 고쳐져 단계 순서가 바뀌어도 내 진행 기록이 엉뚱한 단계를 가리키지 않길 원한다.

### 연습 과정 파일 (만드는 사람)

51. 연습 과정을 만드는 사람으로서, 아이템을 늘릴 때 코드는 건드리지 않고 파일 하나만 더하고 싶다.
52. 연습 과정을 만드는 사람으로서, 파일을 사람이 읽고 고칠 수 있길 원한다, 그래야 diff 검수와 조건 확인을 할 수 있다(나중에 AI가 만든 파일도).
53. 연습 과정을 만드는 사람으로서, 단계마다 끝난 조건을 적어도 되고 안 적어도 되길 원한다.
54. 연습 과정을 만드는 사람으로서, 끝난 조건을 정해 둔 검사 종류(모드, 방금 조작, 물체 수 늘어남, 모디파이어 있음, 재질 슬롯 수, 배율, 크기 비율)로만 적고 싶다, 그래야 코드 없이 조건을 바꿀 수 있다.
55. 연습 과정을 만드는 사람으로서, 파일을 쓰면 검사 테스트가 빠진 칸·모르는 칸·이름표 겹침·잘못된 조건 종류·YAML 함정을 잡아 주길 원한다.
56. 연습 과정을 만드는 사람으로서, 자료가 있을 때는 설명서 소제목 주소가 실제로 있는지, 메뉴 경로가 번역 사전에 있는지, 설명서 문장을 그대로 옮기지 않았는지도 검사받고 싶다.
57. 연습 과정을 만드는 사람으로서, 단계마다 "자주 막히는 곳"을 검수 뒤에 더하고 싶다.

### 자료 준비

58. 개발자로서, 설명서 HTML 묶음을 소제목 단위 청크로 자르고 쪽 제목 > 소제목 경로와 위계 메타데이터를 붙이고 싶다.
59. 개발자로서, 짧은 소제목은 합치지 않고 찾은 뒤 형제 소제목을 함께 넘기고(작게 찾고 크게 읽기), 긴 소제목은 옵션 묶음 경계에서 나누고 싶다.
60. 개발자로서, 청크 속 그림 자리를 `[그림: 캡션]`/`[그림]`으로 남기고 영상·그림 표시는 메타데이터에 두고 싶다.
61. 개발자로서, 기여자용 쪽을 검색에서 빼고 싶다.
62. 개발자로서, 초보자 범위를 50쪽 시험으로 기준을 맞춘 뒤 전체를 분류하고 쪽마다 이유 한 줄을 남기고 싶다, 그래야 나중에 검수할 수 있다.
63. 개발자로서, 초보자 범위 청크에만 한국어 번역과 쉬운 말 풀이를 붙이고, 번역 속 블렌더 표기가 번역 사전과 맞는지 코드로 확인하고 싶다.
64. 개발자로서, 여러 번역이 있는 메뉴 이름(예: Apply)은 초보자 범위 안만 목록으로 뽑아 초반에 화면과 맞춰 고정하고 싶다.
65. 사용자(비용 결정자)로서, 비용이 드는 분류·번역·임베딩을 돌리기 전에 추정 비용을 보고 승인하고 싶다.

### 시간 기록과 평가

66. 개발자로서, 도우미 창이 F10 받음 / 입력 가능 / 보냄 / 첫 글자 / 답 끝 시각과 생각 수준·PC 이름을 자동으로 기록하길 원한다, 그래야 스톱워치 없이 목표 숫자를 잴 수 있다.
67. 개발자로서, 평가 프로그램이 강의실 PC 10문항의 중앙값·최대값을 내 주길 원한다(목표: 질문 준비 0.5초, 첫 글자 2초, 답 끝 6초 이하).
68. 평가 문항을 만드는 사람으로서, 애드온 단축키 하나로 그 순간의 작업 상태 JSON과 화면 PNG를 함께 저장하고 싶다, 그래야 우리와 GPT에 같은 상황을 줄 수 있다.
69. 평가자로서, 평가 프로그램이 개발 문항 JSON을 Blender 없이 답 엔진에 바로 넣어 답·검색 결과를 모으길 원한다.
70. 평가자로서, 정답 위치가 검색 결과에 들어왔는지(검색 적중)를 프로그램이 세 주길 원한다.
71. 평가자로서, 측정마다 결과가 새 폴더에 남고 덮어써지지 않길 원한다.
72. 평가자로서, 답 엔진의 설정(생각 수준, 최근 대화 쌍 수, 리랭커 켬, 임베딩 종류)을 바꿔 같은 문항을 다시 재고 싶다.
73. 평가자로서, 홀드아웃은 고치기 전 결과를 보기 전에 써서 봉인하고, 코드 동결(커밋 번호 기록) 뒤 한 번만 돌리고 싶다.
74. 강사님으로서, GPT 빈손 / 고치기 전 / 고친 후(개발) / 고친 후(홀드아웃) 네 칸 표를 분모·채점자와 함께 보고 싶다.
75. 강사님으로서, 실험마다 무엇을 바꿨고 무엇이 틀렸는지(틀린 원인 6가지)와 대표 실패 사례를 오답노트로 보고 싶다.
76. 강사님으로서, AI 채점과 사람 채점이 얼마나 일치하는지(홀드아웃 블라인드) 보고 싶다.
77. 사용자로서, "이겼다" 기준(홀드아웃에서 답 끝까지가 GPT의 절반 이하, 맞음 수가 GPT 빈손보다 적지 않음)을 결과 전에 적어 두고 싶다.

### 검수

78. 사용자로서, 검 연습 과정을 Blender 5.2에서 처음부터 끝까지 따라 하며 막힌 곳을 기록하고 싶다(평가 문항 후보가 됨).
79. 사용자로서, 따라 하는 동안 물음이 뜰 때마다 "방금 그 단계를 끝냈나" O/X를 남기고 싶다, 그래야 Blender를 몰라도 판정을 검수할 수 있다.
80. 개발자로서, 그때 도우미 창이 받은 작업 상태 흐름이 파일로 남아, 끝난 조건을 고친 뒤 Blender 없이 다시 돌리는 자동 테스트가 되길 원한다.

## Implementation Decisions

### 전체 구성

- 프로그램은 둘이다: **애드온**(Blender 안)과 **도우미 창 프로그램**(도우미 창 + 진행 관리 + 답 엔진을 한 프로그램에). 애드온 → 도우미 창은 내 PC 안 HTTP. 도우미 창 ↔ 답 엔진은 같은 프로그램 안의 함수 호출이고, 이것이 "형식의 경계"다. 나중에 배포할 때 이 사이에 HTTP 한 겹만 넣는다(ADR-0001, 티켓 08).
- 애드온 안에 검색·답 생성 로직을 넣지 않는다. 음성·오버레이 같은 확장은 형식의 앞(입력)이나 뒤(출력)에 붙인다. 형식에는 MVP가 쓰는 칸만 둔다.
- 시제품(`prototype/01-addon-roundtrip` 브랜치)은 Python, tkinter 도우미 창, HTTP 왕복이었다. 본 구현도 Python으로 하되 시제품 코드를 그대로 옮기지 않고 아래 경계에 맞춰 새로 짠다. 새로 필요한 부품: PyYAML.

### 애드온

- F10: 작업 상태를 읽어 보내고, `AllowSetForegroundWindow`로 허락한 뒤 도우미 창을 앞으로 부른다. 자기 Blender 창 번호를 함께 보낸다(Esc로 돌아올 곳).
- 0.5초마다 작업 상태를 읽어 **바뀌었을 때만** 다시 보낸다.
- 작업 상태 칸(12칸): 모드 · 활성 물체(이름·종류·모디파이어 종류 목록) · 선택 물체 수와 이름 · 화면 언어 + 인터페이스 번역 켜짐 여부 · 열린 파일 경로(저장 전이면 비움) · 장면 물체 수 · Blender 버전 · 편집 모드 선택 방식(점·선·면)과 고른 개수 · 방금 실행한 조작 3개(Blender 조작 이름 그대로) · 활성 물체 배율과 크기 · 활성 물체 재질 슬롯 수. 편집 모드 개수 읽기 시간은 구현 때 잰다.
- Blender를 켤 때 도우미 창 프로그램을 켜고(이미 켜져 있으면 그것을 쓴다), 마지막 Blender가 닫히면 도우미 창도 꺼진다.
- 평가용 "지금 상태 저장" 단축키: 그 순간의 작업 상태 JSON과 화면 PNG를 함께 저장한다. `.blend`는 저장하지 않는다.
- glTF 내보내기가 "방금 실행한 조작"에 실제로 잡히는지 구현 때 확인한다. 안 잡히면 그 단계는 버튼만.

### 도우미 창

- 창 동작은 ADR-0001 그대로(작게·정해진 자리·Esc 복귀·Blender 앞일 때만 맨 위·최소화 연동·직접 내리면 F10까지 내린 채·줄여도 입력칸과 최근 답 일부 보임).
- **창 번호마다 최신 작업 상태 하나**를 들고, 질문을 보내면 마지막으로 앞에 있던 Blender의 상태를 쓴다. 닫힌 Blender의 상태는 버린다.
- **최근 대화**: 최근 3쌍(질문과 답 글만, 근거 목록 뺌), 설정값. Blender가 여럿이어도 하나. 창이 꺼지면 사라진다. 자유 질문도 같은 최근 대화에 넣는다.
- 답은 스트리밍으로 표시, 근거는 답 끝에 한꺼번에. 오류·시간 초과는 짧은 오류 문구.
- **시간 기록**: F10 받음 / 입력 가능 / 보냄 / 첫 글자 / 답 끝 시각, 생각 수준, PC 이름을 기록 파일에 자동으로 남긴다.
- 검수용으로 받은 작업 상태 흐름을 파일로 남길 수 있다(진행 관리 테스트의 입력이 됨).

### 진행 관리 (도우미 창 안, 창과 떼어 둔 모듈)

창 그리기와 상관없이 "사건을 받고 할 일을 돌려주는" 모듈로 둔다. 시험 경계 ②.

- 받는 사건: 작업 상태 도착(창 번호 포함), 파일 열림/저장/다른 이름으로 저장(애드온이 Blender의 load_post·save_post 알림으로 알아채 사건으로 보냄. 경로 변화만으로는 열기와 다른 이름 저장을 가를 수 없음, 티켓 18), 사용자 응답(연습 과정 고르기·바꾸기, 네/아니요, 다음 단계, 건너뛰기·뒤로).
- 돌려주는 것: 띄울 물음(다음 단계로 갈까요 / 이어 할까요 / 연습 과정을 바꿀까요)과 거둘 물음, 지금 연습 과정·단계(답 엔진에 넘길 칸), 진행 기록 저장.
- 끝난 조건 판정: AI 없이, **지금 단계의 조건만**, 적힌 검사를 **모두 맞아야** 맞음. "장면 물체 수"는 단계 시작 때 수보다 늘었는지로 본다(시작 때 수를 기억). 크기는 비율로만.
- 묻는 규칙: 창을 앞으로 끌어오지 않음 / 답하기 전에 조건이 깨지면 거둠 / 한 단계에 한 번, 거절하면 그 단계는 버튼만 / 넘어간 뒤 되돌려도 진행 기록은 그대로. 진행 기록에는 사용자가 확인한 것만 남는다.
- **진행 기록**: 열린 파일 경로마다 하나, 사용자 설정 폴더의 작은 JSON(저장소 밖), 지우지 않는다. 내용: 연습 과정 이름표, 현재 단계 이름표, 끝낸 단계 이름표 목록, 마지막으로 바뀐 시각. 저장 전에는 메모리에 두었다가 처음 저장 때 붙이고, 다른 이름으로 저장하면 새 경로로 복사. 같은 파일을 Blender 둘에서 쓰면 나중에 바뀐 쪽이 덮어쓴다. 끝낸 단계는 [네]와 "다음 단계" 버튼만 센다(건너뛴 단계 제외). 다른 파일을 열면 지금 진행을 비운다(앞 파일의 진행은 그 파일 기록에 남음, 티켓 18).
- 기록의 단계 이름표가 연습 과정 파일에서 사라졌으면 끝내지 않은 첫 단계로 가고 한 줄 알린다. 화면의 "n단계"는 파일 순서로 센다.

### 답 엔진

시험 경계 ①. Blender·창 없이 부를 수 있고, 아무것도 기억하지 않는다.

- 입력: 질문 글, 작업 상태(12칸), 최근 대화(쌍 목록), 현재 연습 과정·단계(없을 수 있음).
- 출력: 답 글 조각의 흐름(스트리밍) + 끝에 근거 목록(소제목 경로, 영어 5.2 설명서 주소 `/en/5.2/<경로>.html#<앵커>`, 그림 있음/영상 있음 표시, 영상 링크) + 검색 결과 목록(평가용) + 오류 표시.
- 답변 모델·임베딩은 바꿔 끼울 수 있게 밖에서 받는다(테스트는 가짜를 끼움). 기본: 답변 gpt-6-luna(생각 수준 none 시작, 설정값), 임베딩 text-embedding-3-large. bge-m3는 선택지.
- **호출 2번 고정**: 임베딩 1 + 답 1. 리랭커·검색어 다시 쓰기는 끄는 것이 기본인 선택지이고, 켜도 목표 숫자를 넘기면 채택하지 않는다.
- 검색어 만들기(추가 호출 없음): 현재 질문 + 직전 질문 + 현재 단계 이름과 연결 소제목 + 방금 실행한 조작 이름. 질문 속 한국어 메뉴 이름은 번역 사전으로 영어를 찾아 덧붙인다(여러 개면 모두).
- 검색: 임베딩 + BM25를 RRF로 합친 상위 6-8개. 찾은 청크가 50단어 미만이면 같은 부모 아래 형제 소제목을 약 400단어까지 함께 넘긴다(링크는 찾은 소제목 그대로).
- 먼저 보기: 현재 단계에 연결된 설명서 소제목(최대 2-3개)을 검색 상위 위에 **덧붙인다**(대신하지 않음). 초보자 범위 순위 올리기는 하지 않는다.
- 비슷한 연습 과정: **연습 과정을 진행하지 않을 때만**, 같은 질문 임베딩으로 미리 임베딩해 둔 연습 과정(이름 + 한 줄 설명 + 비슷한 말) 중 가까운 상위 3개를 답변 모델에 붙인다. 딱 맞는 게 없으면 "가장 가까운 건 …"이라고 말하게 한다.
- 답변 모델에 넘기는 것: 검색 청크(초보자 범위면 원문 + 번역 + 쉬운 말 풀이), 작업 상태, 최근 대화, 지금 단계 내용만(연습 과정 파일 전체가 아님).
- 지시: 쉬운 한국어, 5.2 기준, 설명서에 없으면 지어내지 말고 "설명서에 없다" + 가까운 쪽 권함, 그림은 캡션 글만 쓰고 `[그림]`이 중요하면 설명서 그림을 보라고 안내.
- **메뉴 이름 한국어**: 답 엔진이 바꾼다. 인터페이스 번역이 켜진 한국어 화면이면 "한국어(영어)", 번역이 하나면 그대로, 여러 개면 초반 검수로 고정한 짝, 범위 밖·번역 없음은 영어 그대로. 번역이 꺼져 있으면 영어만.

### 자료 준비 (한 번 돌리는 프로그램들)

시험 경계 ④는 "HTML 조각 → 청크" 부분.

- 원자료: 공식 5.2 설명서 HTML 묶음, Blender 저장소의 `ko.po`와 설치본 번역 사전. 모두 `data/`(커밋 안 함).
- 청크: 소제목 하나 = 청크 하나(실제 8,997개, 목차뿐인 소제목 283개를 버려 예상 약 9,100개보다 적음, 티켓 19). 위계 메타데이터 분야 > 묶음 > 쪽 > 소제목(여러 겹) > 옵션. 청크 글 앞에 "쪽 제목 > 소제목". 400단어 넘으면 옵션 묶음 경계(없으면 문단 끝)에서 **고르게** 나누고 같은 경로·앵커. 옵션 하나가 400단어를 넘으면 그 안의 범주 → 값(이름 + 설명 한 쌍) → 문단 경계에서 나누고, 뒤 조각 글 앞 경로에 옵션·범주를 더함(예: "Math Node > Properties > Operation"). 아래 소제목만 묶는 제목뿐인 소제목은 경로에만, 목차만 있는 것은 버림. "모드·메뉴·단축키" 상자는 **상자가 있는 소제목의 청크** 본문 + 메타데이터(한 쪽에 도구가 여럿이면 상자도 소제목마다 따로 있음, 티켓 19). contribute 26쪽 제외.
- 그림·영상: 그림 자리에 `[그림: 캡션]`/`[그림]`, 경로뿐인 alt는 버림, 그림 주소는 메타데이터. 영상만·그림만 있는 소제목은 청크로 만들지 않고 같은 쪽 바로 앞 청크 메타데이터에 "영상/그림 예시 + 링크".
- 범위 표시 메타데이터: `연습 과정` / `초보자` / `일반`.
- 초보자 범위: 단위는 쪽. 연습 과정 단계가 가리키는 쪽 + 시작하기 16쪽은 바로 넣고, 나머지는 "처음 쓰는 사람이 간단한 아이템 하나를 만들고 내보내며 마주칠 가능성"으로 AI가 판단, 쪽마다 이유 한 줄(약 300쪽 안). 경계 쪽을 섞은 50쪽 시험(Claude 대화 세션 판단 → luna 분류 → 다른 쪽은 사용자가 봄) 뒤 전체를 luna로.
- 번역: 초보자 범위만. 블렌더 표기는 ko.po에서 가져와 "한국어(영어)", 짝을 코드로 확인 + 무작위 약 20개 사용자 읽기.
- 메뉴 이름 짝: 설명서의 메뉴 경로 표시·버튼 이름 표시·옵션 이름, 그리고 쪽 제목·소제목 가운데 번역 사전에 있는 것(뒤의 Modifier·Node·Tool·Constraint를 뗀 이름도)에서 블렌더 표기를 코드로 뽑아 번역 사전과 대조. 모디파이어·노드 이름(Array 등)은 설명서가 메뉴 경로로 적지 않고 쪽 제목으로만 적기 때문(티켓 20). 이름마다 출처(화면 표시·옵션·제목)를 적는다. 여러 번역과 제목에서만 뽑은 이름은 목록으로 뽑아 초반 검수(초보자 범위만 걸러 내기는 초보자 분류 뒤).
- 임베딩 대상: 원문 + 번역(풀이는 답변 모델에게만). 저장 방식(벡터 저장소 종류)은 구현 때 정한다.
- 비용 추정(가격표 계산): 50쪽 시험 몇 센트, 전체 분류 $1 미만, 번역 $1 안팎, 전체 임베딩 $1 미만. **돌리기 전마다 사용자 확인.**

### 연습 과정 파일

- YAML 한 벌(JSON 두 번째 벌 없음). 도우미 창을 켤 때 한 번 읽는다. 연습 과정 하나에 파일 하나(검, 방패) + 공통 준비 파일 하나, 각 연습 과정이 공통 준비를 "먼저 할 것"으로 가리킨다. 저장소의 `courses/`에 커밋한다(우리 말로 새로 쓰고 설명서 문장은 옮기지 않으며 소제목 주소로만 가리킴).
- 칸 이름은 한국어, 이름표·Blender 조작 이름·메뉴 경로는 영어.
- 맨 위: 이름표, 이름, 한 줄 설명, 난이도, 마지막 결과(glTF), 비슷한 아이템 말 목록. 구간: 이름 + 단계 목록.
- 단계: 이름표(꼭, 바뀌지 않는 영어 소문자), 이름(꼭), 목표 모양(꼭), 참고 치수(선택, 비율 위주), 쉬운 설명(꼭, 2-3문장), 조작 목록(꼭: 한 줄 설명 + 영어 메뉴 경로 + 단축키), 먼저 볼 설명서 소제목(꼭, 1-3개), 끝난 조건(선택), 자주 막히는 곳(선택).
- 끝난 조건 검사 종류: 모드, 방금 조작(최근 3개 안), 장면 물체 수 늘어남, 모디파이어 있음, 재질 슬롯 수, 배율, 크기 비율(가장 긴 축 ≥ 두 번째 축 × n). 새 종류는 코드에 하나 더하고, 그때까지 그 단계는 버튼만.
- 검 연습 과정은 기본 장면(빠른 설정 창을 닫은 뒤)에서 시작해 기본 정육면체를 칼날 시작으로 쓰고 glTF 내보내기로 끝난다. 검을 먼저 완성(AI 초안 → 사용자가 따라 하기 → 고치기), 그다음 방패.

### 평가

- 문항: 질문 글(시나리오형은 앞선 대화 포함) + 작업 상태 JSON + 스크린샷 PNG + 맞는 답의 핵심 1-3개 + 정답 위치(설명서 쪽 주소·소제목 1-2개) + 작은 분류.
- 개발 30: 정답형 20(연습 과정 단계 10 / 한국어 화면 메뉴 위치 3 / 초보자 범위 밖 어려운 것 3 / 시나리오형 4) + 문서에 없는 질문 5 + 함정 5. 초보자 범위 밖 한국어 질문을 넣는다. 홀드아웃 10: 정답형 6 / 없는 2 / 함정 2, 고치기 전 결과를 보기 전에 써서 `data/`에 봉인, 동결 뒤 한 번만 돌리고 그때 `eval/`로 옮긴다.
- 출처: 사용자가 검을 따라 하다 막힌 곳 / 티켓에 쌓인 후보 / AI 초안을 사용자가 자기 말로 고침. 설명서 문장을 그대로 옮기지 않는다. 정답 위치는 AI 초안, 사용자가 링크를 열어 확인.
- 측정 네 칸: GPT 빈손 / 고치기 전 / 고친 후(개발) / 고친 후(홀드아웃).
- **평가 프로그램**: 문항 JSON을 답 엔진에 바로 넣어 답·검색 결과를 모으고, 검색 적중을 세고, 시간 기록에서 중앙값·최대값을 내고, `results/<날짜>_<이름>/`에 새로 쓴다(덮어쓰지 않음). 답 엔진 설정을 바꿔 다시 돌릴 수 있다.
- 재는 것: 답 정확도, 검색 적중, 근거 표시 정확도, 상태 읽기 맞음/틀림(JSON을 PNG와 대조), 시간. 모든 숫자에 분모와 채점자.
- GPT 조건: 사용자가 무료 웹에서 직접, 문항마다 새 대화(시나리오형만 앞선 질문 먼저), 기억·개인 설정 끔, 스크린샷 + 같은 질문 글, 연습 과정 정보 안 줌, Think 안 누름(Think 켬은 참고용 5문항), 날짜·표시된 모델 이름 기록.
- 시간: 개발 10(고치기 전, GPT 빈손도 같은 10) + 홀드아웃 10만. 질문 준비(GPT: 스크린샷 키 → 엔터 / 우리: F10 → 입력 가능 + 붙여 넣기)와 보낸 뒤(우리는 첫 글자까지도). 질문 글은 양쪽 모두 미리 복사해 붙여 넣는다. GPT 쪽만 스톱워치. PC 이름 기록.
- 채점: 맞음/부분/틀림(맞음 = 초보자가 그대로 따라 해서 된다). Claude가 대화 세션에서 채점(별도 채점 프로그램·API 비용 없음). 홀드아웃은 사용자가 어느 쪽 답인지 가린 채 따로 채점해 일치율을 낸다.
- 틀린 원인 6가지: 검색 실패 / 검색은 맞는데 답이 틀림 / 문서에 원래 없음 / 질문이 모호함 / 상태 읽기 틀림 / 블렌더 표기 틀림.
- 이 평가로 판단할 것: 전체 번역 여부, 리랭커·bge-m3·초보자 범위 순위 올리기, 시나리오형에서 붙여 검색 vs 검색어 다시 쓰기, 최근 대화 3쌍 vs 5쌍, 생각 수준 none → low(시나리오형 4 + 함정 5만 따로 봄), 캡션 없는 그림 설명 추가.
- 기록: `docs/experiment.md` 한 파일(오답노트 + 실험 로그, `[E번호]`, GPT 빈손은 `[E0]`, 홀드아웃은 마지막). 숫자는 여기에만, HISTORY에는 링크만.

## Testing Decisions

- **좋은 테스트**: 경계 바깥에서 보이는 동작만 본다(넣은 것 → 나온 것). 안쪽 함수 이름·자료 구조가 바뀌어도 깨지지 않아야 한다. 기본 테스트는 **API 키·Blender·화면 없이** 돌고 늘 통과 상태로 둔다. `data/`가 있어야 하는 테스트는 없으면 건너뛴다.
- **시험 경계 4개**(사용자 확인, 2026-10-19):
  1. **답 엔진**(주 경계): 가짜 답변 모델·가짜 임베딩을 끼우고 작은 청크 묶음으로 시험한다. 보는 것: 근거 목록의 경로·주소·그림/영상 표시, 질문 속 한국어 메뉴 이름이 검색어에 영어로 덧붙는지, 앞말 질문에 직전 질문·단계 이름·조작 이름이 붙는지, 먼저 볼 소제목이 상위 위에 덧붙는지, 짧은 청크에 형제가 함께 넘어가는지, 연습 과정을 진행하지 않을 때만 비슷한 연습 과정 3개가 붙는지, 한국어/영어 화면·번역 꺼짐에 따른 메뉴 이름 표기, 호출이 2번인지, 오류·시간 초과 때 오류 표시. 평가 프로그램도 이 경계를 그대로 쓴다.
  2. **진행 관리**: 작업 상태 흐름과 사용자 응답을 차례로 넣고 나온 물음·거둔 물음·진행 기록을 본다. 검수 때 남긴 실제 상태 흐름 파일을 다시 돌리는 테스트가 여기 붙는다(끝난 조건을 고친 뒤 회귀 확인). 진행 기록은 임시 폴더에 쓴다.
  3. **연습 과정 파일 검사**: 꼭 있어야 하는 칸, 모르는 칸 이름, 이름표 겹침, 끝난 조건 종류, 공통 파일 가리키기, YAML 함정(따옴표 없는 `no` 등). `data/`가 있을 때만: 설명서 소제목 주소가 실제로 있음, 메뉴 경로가 번역 사전에 있음, 설명서와 긴 문장이 똑같이 겹치지 않음. 실제 `courses/` 파일들이 이 검사를 통과해야 한다(나중에 AI가 만든 파일도 같은 기준).
  4. **자료 준비(HTML → 청크)**: 설명서 구조를 흉내 낸 작은 HTML 조각(직접 쓴 것, 설명서 원문 아님)을 넣고 청크 경계·경로·앵커·위계 메타데이터·그림 표시·긴 소제목 나누기·제목뿐인 소제목 처리를 본다.
- **애드온**: 작업 상태 읽기는 Blender를 화면 없이 띄우는 자체 시험으로 따로 돌린다(기본 테스트에는 넣지 않음). 창 동작·F10·한글 입력은 사용자가 강의실 PC에서 눈으로 확인한다.
- **이전 사례**: 시제품 브랜치의 Blender 화면 없이 돌리는 자체 시험(작업 상태 읽기), 이전 프로젝트 `rag_korea_history`의 평가·채점 방식.
- 유료 호출이 드는 측정(생각 수준 실측, 개발 평가 실행)은 테스트가 아니라 평가이고, 돌리기 전에 확인받는다.

- 만든 아이템을 실제 게임에 넣는 작업
- 사용자 목표에 맞춰 연습 과정을 그 자리에서 만드는 것(최종 목표, 새 지도로)
- 5.2가 아닌 다른 Blender 버전
- 그림 비교로 단계 완료 판정, 단계마다 목표 모습 그림 보여 주기
- 도우미 창 안에 설명서 그림·영상 직접 띄우기(근거 링크로 웹사이트에서 봄)
- 캡션 없는 그림의 AI 설명(평가에서 필요하다고 나올 때만 선택지)
- 초보자 범위 밖 쪽의 번역(평가에서 검색 적중이 낮을 때만 "검색용 기계 번역" 선택지)
- 배포(답 엔진을 다른 PC에 두고 여러 사용자가 쓰기, API 키 한곳 관리)
