# 지도: 왕복 MVP

Label: wayfinder:map

## Destination

Blender 5.2 애드온(단축키·작업 상태 읽기)과 Blender 위에 떠 있는 도우미 창(질문 입력·답 표시), 내 PC의 RAG 서버가 "질문 + 작업 상태 → 답 + 근거" 형식으로 주고받는 **왕복 MVP 명세**, 그리고 같은 질문을 **GPT(스크린샷 방식)와 비교해 정확도와 걸린 시간을 재는 평가 계획**. 둘이 정해져 `/to-spec`으로 넘길 수 있으면 끝.

## Notes

- **배경:** 강사님 질문 "초보자 대상이면 GPT가 더 잘하는 것 아닌가?" → 직접 해 보니 스크린샷을 찍어 건네고 GPT 답을 기다리는 데 오래 걸림. 애드온이 작업 상태를 바로 읽고 RAG로 빠르게 답한다는 점을 설명해 OK 받음(2026-10-19). 그래서 **애드온 왕복과 걸린 시간 비교가 MVP의 핵심 근거**다.
- **원본 제안서:** `docs/산출물/1단계_주제확정/Blender_RAG_제안서_2026-10-19.pdf`(내부 참고용, 커밋 안 함)
- **확장 원칙:** 코드는 최소로. 연습 과정은 코드가 아니라 데이터 파일로 두어 아이템을 바꾸거나 늘릴 때 파일만 더한다. 음성·오버레이 같은 확장은 애드온 ↔ 서버 형식의 앞(입력)이나 뒤(출력)에 붙이고, 애드온 안에 검색·답 생성 로직을 넣지 않는다. 형식에는 MVP가 쓰는 칸만 둔다.
- **자료 원칙:** 검색 대상은 5.2 설명서 전체(개발자용 Python API 문서 제외). 번역·쉬운 말 풀이·우선순위는 연습 과정 + 초보자 범위에만 하고 메타데이터로 표시한다. 사용자에게 도메인 지식이 없어 초보자 범위 분류는 AI에 기대므로, 분류 근거를 남기고 **검수는 시간이 들어도 초반에** 한다.
- **시간 재기:** 시작은 질문하려고 손을 움직인 순간(GPT: 스크린샷 찍기 시작, 우리: 단축키), 끝은 답이 다 나온 순간. 질문 준비 시간과 보낸 뒤 시간을 나눠 기록한다.
- **공개·라이선스:** 설명서 CC BY-SA 4.0, Blender Studio 강좌 CC BY 4.0(강좌 쪽에서 문구 미확인, 강좌 글을 데이터로 쓰기 전 확인). 내려받은 원문·번역은 `data/`(커밋 안 함). 답에 근거 링크와 출처 표시. 평가 질문에 설명서 문장을 그대로 옮기지 않는다.
- **참고할 이전 프로젝트:** `C:\sample\rag_korea_history`의 `docs/결정.md`(원문·번역·풀이를 담은 청크, gpt-6-luna, text-embedding-3-large, RRF + 리랭커, 대화 이력 분리 D2).
- **조사 브랜치:** `research/*` 브랜치는 main에 합치지 않고 지도가 진행되는 동안 근거로 둔다. **명세(`/to-spec`)가 완성되면 로컬·원격 모두 지운다**(요지는 각 티켓의 Answer에 있다).
- **쓸 스킬:** grilling 티켓은 `grilling` + `domain-modeling`, 용어는 `CONTEXT.md`를 따른다.

## Not yet specified

- 연습 과정 데이터 파일의 형식(애드온 ↔ 서버 형식 뒤). 검·방패가 함께 쓰는 1단계(공통 준비)를 각 파일에 넣을지 따로 둘지, 단계마다 연결할 설명서 소제목(검색 "먼저 보기"에 씀)을 적는 방법 포함

## Out of scope

- 음성 받아쓰기, 뷰포트 위 오버레이(3D 뷰 안에 겹쳐 그리기. 도우미 창과 다르다), 메뉴 강조: 핵심 대화 기능 뒤에 붙일 확장
- 만든 아이템을 실제 게임에 넣는 작업: 게임마다 조건이 달라 대상 게임을 정한 뒤 따로
- 사용자 목표에 맞춰 연습 과정을 그 자리에서 만드는 것: **최종 목표**. MVP(검·방패, 없는 아이템은 비슷한 것 권하기)가 일정보다 빨리 끝나면 새 지도로 시작. 같은 연습 과정 파일 형식을 AI가 만들어 내는 방식으로 이어 붙인다
- 5.2가 아닌 다른 Blender 버전
